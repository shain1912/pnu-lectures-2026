AI 시대에 이론을 배우는 이유

용어 미리보기 (1/3) — 화면 쪽

픽셀Pixel

화면을 이루는 가장 작은 색 칸 하나 — 모자이크의 타일 한 장 (picture element 의 줄임말)

칸 하나 = 숫자 세 개 (R, G, B) · 주황 = (255, 140, 0)

그래픽스의 최종 결과물 = 이 칸마다 들어갈 색 → 모든 이론이 결국 이 색을 정하는 방법

해상도Resolution

화면의 가로 칸 수 × 세로 칸 수 — 칸이 많을수록 그림이 촘촘하고 매끈

FHD 1920 × 1080 ≈ 207만 칸 · Quest 3 한 눈 2064 × 2208 ≈ 456만 칸

칸 수만큼 색 계산이 늘어남 → VR 은 모니터보다 약 4.4배 많은 칸을 칠해야 함

Unity : Game 뷰 상단 해상도 드롭다운 (Free Aspect → 1920x1080 등)

프레임Frame

화면에 한 번 그려지는 정지 그림 한 장 — 플립북의 종이 한 장 · 1초에 몇 장인가 = fps · 모자라면 끊김

90 fps = 1초에 90장 → 한 장에 쓸 수 있는 시간 약 11.1 ms

Unity : Game 뷰 오른쪽 위 Stats 버튼 → FPS · ms 표시

GPUGraphics Processing Unit

쉬운 계산 수억 개를 동시에 나눠 처리하는 그래픽 전용 칩 — 초등학생 수천 명이 곱셈을 나눠 푸는 교실

Quest 3 의 GPU = 헤드셋 안 모바일 칩 (Snapdragon XR2 Gen 2) · PC 그래픽카드보다 여유 적음

Unity : Window → Analysis → Profiler → GPU 사용량 모듈

용어 미리보기 (2/3) — 장면과 계산

메시Mesh

작은 삼각형을 이어 붙여 만든 3D 물체의 겉껍질 데이터 — 속이 빈 종이 공예 모형

정육면체 = 삼각형 12개 · Unity 기본 Sphere = 삼각형 약 770개

Unity : Inspector 의 Mesh Filter 컴포넌트 · Scene 뷰 Shading Mode → Wireframe

정점Vertex

삼각형의 꼭짓점 하나 — 위치 (x, y, z) 와 방향·색 같은 정보를 함께 담은 점

정육면체 꼭짓점 8개 · 의자 앉는 면 중심 (0, 0.5, 0)

Unity : Game 뷰 Stats 창의 Verts(정점 수) · Tris(삼각형 수)

렌더링Rendering

3D 장면의 숫자들을 계산해 픽셀 색 배열(이미지 한 장)로 바꾸는 일 — 촬영장 촬영을 계산으로 하기

입력 : 메시 · 재질 · 광원 · 카메라 → 출력 : 1920 × 1080 칸의 색

Unity : Game 뷰에 보이는 화면 = 매 프레임의 렌더링 결과

파이프라인Pipeline

여러 계산 단계를 정해진 순서로 이어 흘려보내는 작업 흐름 — 자동차 조립 라인

좌표 변환 → 투영 → 래스터화 → 셰이딩 → 깊이 판정

결과가 틀리면 «어느 단계에서?» 로 범위를 좁혀야 원인을 찾음

Unity : Project Settings → Graphics → Default Render Pipeline (URP 에셋)

Part I 용어

용어 미리보기 (3/3) — 파이프라인 안쪽

좌표계Local · World · View

위치를 말할 때의 «기준점» — 물체 자신 기준(로컬) · 씬 전체 기준(월드) · 카메라 기준(뷰)

로컬 (0, 0.5, 0) 인 점 + 의자를 월드 (3, 0, 2) 에 배치 → 월드 (3, 0.5, 2)

Unity : Inspector 의 Transform Position = 부모 기준 값 · Scene 뷰 툴바 Local / Global 전환

프래그먼트Fragment

래스터화(삼각형 → 칸 고르기)로 뽑힌 칸 하나 — 아직 색이 확정되지 않은 «색칠 후보»

이번 장 그림 : 112칸 중 중심점이 삼각형 안인 37칸 = 프래그먼트 37개

뒤의 셰이딩·깊이 판정은 이 후보 하나하나를 대상으로 실행

셰이더Shader

칸(또는 꼭짓점)마다 GPU 에서 실행되는 작은 프로그램 — 칸마다 «무슨 색인가» 를 계산

밝기 = 바탕색 × cos θ → 0.8 × 0.5 = 0.4

Unity : Material 의 Inspector 맨 위 Shader 드롭다운 (Universal Render Pipeline/Lit)

깊이 버퍼Depth buffer

② 투영 — 멀수록 작게

\[ x' = f \cdot \frac{x}{z} \]

x : 물체 높이 · z : 카메라까지 거리 · f : 카메라에서 화면까지 거리 · x′ : 화면 위 높이

손계산 (f = 1, 높이 1 m)
2 m 거리 : \(1 \times \tfrac{1}{2} = 0.5\)
4 m 거리 : \(1 \times \tfrac{1}{4} = 0.25\) → 거리 2배 · 크기 1/2

창문에 풍경 따라 그리기 (르네상스 원근법) : 한쪽 눈을 고정하고 유리창에 바깥 풍경을 그대로 따라 그리면 → 먼 나무는 작게, 가까운 나무는 크게 그려짐 · 투영 = 이 유리창 그림을 계산으로

- 그림 : 눈에서 물체 꼭대기로 그은 선이 화면(노란 선)을 지나는 높이 = 화면 위 크기 - 실제 4주차 투영 행렬은 이 나눗셈(÷z)을 행렬 + 원근 나눗셈으로 처리 - 실습 명세(오늘 마지막)에서 2 m · 4 m 큐브를 놓고 이 비율을 화면에서 검증

④ 셰이딩 — 칸마다 색 계산

같은 빨간 공이라도 빛을 정면으로 받는 쪽은 밝고, 비스듬히 받는 쪽은 어두움 → 칸마다 다른 색

\[ \text{밝기} = \text{바탕색} \times \cos\theta \]

θ : 면이 바라보는 방향과 빛이 오는 방향 사이 각도

손계산 — 바탕색 빨강 값 0.8
빛이 정면 (θ = 0°) : \(0.8 \times 1 = 0.8\)
빛이 60° 기울어짐 : \(0.8 \times 0.5 = 0.4\)
빛이 90° (스치듯) : \(0.8 \times 0 = 0\)

해바라기 판 : 해를 정면으로 마주한 판이 가장 뜨겁고, 기울일수록 덜 뜨거움 · 같은 햇빛이 더 넓은 면적에 퍼지기 때문 → 픽셀 밝기도 같은 원리

이 계산을 담당하는 작은 프로그램 = 셰이더 (Shader) · 5주차 조명 · 6주차 직접 작성

명세 4칸 맛보기 — 지각 실험실의 뼈대

[목표]
지각 실험실 씬의 뼈대를 만든다. 바닥 1개, 기준 큐브 3개, 눈높이 카메라.

[제약]
- 1 unit = 1 m. 바닥은 Plane, Scale (2, 1, 2) → 20 m × 20 m
- 큐브는 한 변 1 m, 바닥 위에 놓일 것 (y = 0.5)
- 큐브 앞면이 카메라 정면 2 m · 4 m · 8 m 거리 (중심 z = 2.5 · 4.5 · 8.5)
- Main Camera 위치 (0, 1.6, 0) — 서 있는 사람의 눈높이
- 스크립트를 쓰지 말고 에디터 조작 순서로 안내할 것

[검증 조건]
- Inspector 의 Position · Scale 이 위 수치와 일치
- Game 뷰에서 앞면 세로 모서리 길이 : 2 m 큐브 = 4 m 큐브의 2배 (±10%)

[비목표]
- 재질 · 조명 변경, VR 설정, 패키지 설치
