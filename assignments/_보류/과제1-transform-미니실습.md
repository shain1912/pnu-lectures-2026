## 이 과제가 확인하려는 것

이 수업에서 **코드는 AI가 씁니다.** 여러분이 하는 일은 두 가지입니다.

1. 무엇을 만들어야 하는지 **정확한 용어로 요구하는 것**
2. AI가 내놓은 결과가 **왜 틀렸는지 판별하는 것**

그래서 이 과제의 제출물은 **완성된 코드가 아니라 프롬프트와 검증 리포트**입니다.
코드가 잘 돌아가도 프롬프트와 리포트가 부실하면 점수를 받지 못합니다. 반대도 마찬가지입니다.

## 과제 내용

### 실습 1 — 명세대로 회전 스크립트 받아내기 (필수)

아래 명세를 **그대로** AI 에이전트(OpenCode / Antigravity CLI 등)에게 주고 스크립트를 받으세요.

```
[목표]
큐브를 월드 Y축 기준으로 초당 45° 등속 회전시킨다.

[제약]
- 회전 누적에 eulerAngles 를 쓰지 말 것 (짐벌락·값 튐)
- Quaternion 을 유지한 채 누적할 것
- 프레임률과 무관하게 같은 속도 (Time.deltaTime)
- 회전 중심은 물체 자신의 원점

[검증 조건]
- 60fps 와 30fps 에서 10초 뒤 각도가 같을 것
- 어떤 각도에서도 축이 잠기지 않을 것

[비목표]
- 입력 처리, UI 는 만들지 말 것
```

**기록할 것**: AI의 **첫 번째 응답을 손대지 말고 그대로** 로그에 붙여넣으세요.
마음에 안 들어도 지우지 마세요. 첫 응답이 곧 명세의 품질 지표입니다.

---

### 실습 2 — 짐벌락 재현하고 진단하기 (필수)

이번에는 **일부러 틀린 것**을 만듭니다.

1. AI에게 `transform.eulerAngles` 를 누적하는 버전을 요청하세요.
   (예: `"eulerAngles 를 직접 더해서 X와 Y를 동시에 회전시켜줘"`)
2. 피치(X)를 **90°** 근처로 만든 상태에서 요(Y)와 롤(Z)을 각각 움직여 보세요.
3. **두 축이 같은 회전을 만드는 순간을 영상으로 캡처**하세요.

**리포트에 답할 것**
- 어느 두 축이 겹쳤는가?
- 자유도가 3에서 몇으로 줄었는가?
- 이것이 "가끔 생기는 버그"가 아니라 오일러각의 구조적 결함인 이유는?

---

### 실습 3 — 계층 변환과 전단(shear) 관찰 (필수)

1. 부모 → 자식 → 손자, **3단 체인**을 만드세요.
2. 부모에 `Scale (1, 3, 1)` 을 주세요.
3. 자식을 Y축이 아닌 축으로 회전시켜 보세요.

**리포트에 답할 것**
- 자식이 어떻게 찌그러졌는가? (스크린샷 첨부)
- 왜 그런가? (힌트: `S · R ≠ R · S`)
- 이 문제를 피하려면 계층 구조를 어떻게 바꿔야 하는가?

---

### 실습 4 — 카메라 vs 리그 (확장 · 선택)

> 11주차 VR 실습의 예비 훈련입니다. 필수는 아니지만 해두면 11주차가 훨씬 수월합니다.

1. Main Camera 를 **직접** 움직이는 스크립트
2. Main Camera 를 자식으로 둔 **빈 부모(리그)** 를 움직이는 스크립트

둘 다 만들어서 동작을 비교하세요.

**리포트에 답할 것**
- 일반 게임에서는 둘 중 무엇을 써도 되는가?
- VR에서는 왜 반드시 후자여야 하는가? (수업에서 다룬 좌표계 체인으로 설명)

## C. 검증 리포트 양식

```
1. 무엇을 확인했는가
   (예: 60fps 와 30fps 에서 10초 뒤 각도 비교)

2. 어떻게 확인했는가
   (측정 방법. Application.targetFrameRate 를 바꿔서, 로그를 찍어서 등)

3. 결과
   (숫자 또는 스크린샷)

4. 통과 / 불통과
   불통과라면 → 원인은 무엇이고, 어떻게 고쳤는가
```

각 실습마다 하나씩, 총 3~4개.
