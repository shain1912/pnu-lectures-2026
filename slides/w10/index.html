왜 «버튼» 이 아니라 «의도» 로 받는가

같은 «점프» 의 실제 입력

  • PC : 키보드 Space
  • 게임패드 : 아래쪽 버튼 (South)
  • Quest : 오른손 컨트롤러 A 버튼

버튼마다 코드를 따로 작성 → 기기 추가 때마다 게임 코드 수정 → 수정 누락 = 그 기기에서만 먹통

입력 추상화 (Input abstraction) : 게임 코드는 «점프가 일어났다» 만 알고, «어떤 버튼이었나» 는 설정 파일이 담당 → 기기 추가 = 설정 한 줄 추가

TV 리모컨의 «채널 올림» : 거실 리모컨 · 휴대폰 앱 · TV 본체 버튼 — 무엇을 누르든 TV 는 «채널 올림» 명령 하나만 받음 → TV 회로는 리모컨 종류를 모름

- 11주 Quest 전환이 이 슬라이드의 이유 : 지금 키보드로 만든 코드를 다음 주 컨트롤러로 그대로 쓰려면 액션 기반이어야 함

- Value 타입의 "가장 크게 움직인 입력 하나" = 컨트롤 분쟁 해결(disambiguation) - 단순 버튼은 started 와 performed 가 같은 프레임에 일어남 → 다음 장 Hold 에서 차이가 드러남
입력 · 5

코드 — 액션 구독하기

using UnityEngine;
using UnityEngine.InputSystem;

public class JumpInput : MonoBehaviour
{
    [SerializeField] InputActionReference jump;   // 인스펙터에서 Player/Jump 지정

    void OnEnable()  { jump.action.performed += OnJump; jump.action.Enable(); }
    void OnDisable() { jump.action.performed -= OnJump; }   // ← 구독 해제 짝

    void OnJump(InputAction.CallbackContext ctx)
    {
        Debug.Log($"점프 · 입력 기기 = {ctx.control.device.displayName}");
    }
}

Unity 6 프로젝트 전역 액션 : InputSystem.actions.FindAction("Jump") 로도 조회 가능 · 이 코드에 키 이름·버튼 이름 0개 → 다음 주 Quest 에서 수정 없이 재사용

- OnEnable/OnDisable 짝 강조 → 이벤트 · 5 에서 함정으로 다시 나옴 - ctx.control.device 로 어떤 기기였는지는 필요할 때만 알아냄

Interaction 과 Processor — 손계산

Interaction상호작용 조건
«언제 performed 로 칠지» 규칙 — Hold (기본 0.4초 이상 누름) · Tap · Multi Tap
Processor값 가공
값을 코드에 넘기기 전 손질 — Stick Deadzone · Invert · Scale
데드존Deadzone
스틱이 살짝 기울어진 잡음 구간을 0 으로 무시하는 범위

Stick Deadzone 기본값 min 0.125 · max 0.925

\[ v' = \frac{|v| - 0.125}{0.925 - 0.125} \]

|v| = 0.10 → 0.125 미만 → 0 (손 떨림 무시)
|v| = 0.50 → \(0.375 \div 0.8 \approx\) 0.47
|v| = 0.95 → 0.925 초과 → 1 (끝까지 기울임)

수도꼭지의 헐거운 구간 : 손잡이를 조금 돌릴 때는 물이 안 나오고, 끝까지 돌리기 전에 최대 수량 도달 → 사람 손의 오차를 기계 쪽에서 흡수

- 컨트롤러 스틱이 낡으면 손을 떼도 0.05~0.1 정도 기울어 있음 → 데드존이 없으면 캐릭터가 저절로 미끄러짐 - 수치는 Input System 기본값 · 프로젝트 설정에서 변경 가능

폴링 vs 이벤트

폴링 (Polling)

Update() 안에서 매 프레임 «눌렸나?» 확인
손계산 : 90 Hz × 60 초 = 1분에 5,400번 질문 · 실제 눌림 1번이어도 동일

이벤트 (Event)

눌린 순간 등록된 함수만 호출
1분에 1번 눌림 → 호출 1번 · 확인 코드가 흩어지지 않음

택배 기다리기 : 1분마다 현관문을 열어 확인 (폴링) vs 초인종이 울리면 나가기 (이벤트) · 단, 초인종 방식은 초인종을 미리 달아 둬야 함 = 구독 등록

폴링이 맞는 경우도 존재 : 스틱 이동처럼 매 프레임 값이 필요한 연속 입력 → move.ReadValue<Vector2>() 를 Update 에서 읽기

- "이벤트가 무조건 좋다" 가 아님 · 버튼 = 이벤트, 연속값 = 폴링이 실무 기본 - 5,400번은 성능 문제라기보다 "로직이 Update 한 곳에 엉키는" 문제

이벤트의 흔한 실수 — 구독 해제 누락

  • += 로 구독 · 짝이 되는 -= 없음
  • 씬 재시작 · 패널 껐다 켜기 → 같은 함수가 두 번, 세 번 등록
  • 결과 : 버튼 한 번에 효과음 3번 · 이미 파괴된 오브젝트 접근 → MissingReferenceException

게임 흐름 상태 + 액션 맵 전환

public enum GameState { Menu, Playing, Paused }
GameState state;

public void SetState(GameState next)
{
    if (next == state) return;
    state = next;
    bool ui = next != GameState.Playing;
    player.Disable(); uiMap.Disable();           // 전부 끄고
    (ui ? uiMap : player).Enable();              // 필요한 맵 하나만 켬
    menuPanel.SetActive(ui);
    Time.timeScale = next == GameState.Paused ? 0f : 1f;
    StateChanged?.Invoke(next);                  // 이벤트로 알림
}

상태 전환 = 한 함수 · 맵 전환·패널 표시·시간 정지가 여기에서만 일어남 → «메뉴 열렸는데 캐릭터가 걷는» 버그의 출처가 하나로 줄어듦

- 입력 → 이벤트 → 상태 → UI 의 전체 사슬이 이 함수 하나에 보임 - VR 주의 : Time.timeScale = 0 이어도 머리 트래킹은 계속됨 (11주 연결)

World Space 크기 — 픽셀을 미터로 바꾸기

캔버스 Width 1000 · Height 600 (UI 단위) · Scale 0.001

\[ 1000 \times 0.001 = 1.0\,\text{m} \qquad 600 \times 0.001 = 0.6\,\text{m} \]

글자 Font Size 40 → \(40 \times 0.001 = 0.04\,\text{m}\) = 4 cm 높이

Scale 1 그대로 두면 → 1000 m × 600 m 패널 → 하늘을 덮는 거대한 판 · 또는 카메라가 안쪽에 갇혀 아무것도 안 보임
AI 가 Render Mode 만 World Space 로 바꾸고 Scale 을 빼먹는 경우가 흔함

설계 도면의 축척 : 도면 위 1000 칸 · 축척 1/1000 → 실물 1 m · 축척을 안 적은 도면 = 크기를 알 수 없는 그림

«4 cm 글자가 적당한가» 는 거리에 따라 달라짐 → Part II 각크기에서 판정

- Unity 에서 1 unit = 1 m · Quest 에서는 이 약속이 실제 몸 크기와 직결 - 0.001 이 외우기 쉬운 값 : 캔버스 단위 1 = 1 mm

HMD 에는 «화면» 이 없다 — 렌즈가 만든 가상 이미지

  • 디스플레이 패널 : 눈앞 수 cm · 맨눈으로는 초점 불가
  • 렌즈 : 패널 영상을 멀리 있는 것처럼 보이게 확대 → 눈이 초점을 맞추는 «가상 이미지» 거리 = 고정
  • 그 고정 거리 : 기기마다 다름 · 공식 수치 미공개인 경우 많음 → 오늘 손계산은 1.5 m 로 가정
  • 두 눈 = 두 패널 영역 · 각각 다른 시점·다른 투영 (4주차 비대칭 절두체)

돋보기로 작은 글씨 읽기 : 돋보기를 글씨에 가까이 대면 글씨가 크고 먼 곳에 있는 것처럼 편하게 보임 → 눈은 «종이» 가 아니라 «돋보기가 만든 상» 에 초점

비유의 한계 : 돋보기 상의 거리는 손을 움직이면 변함 · HMD 렌즈 상의 거리는 항상 같음

그래서 : «화면 좌표» 의 기준이 될 화면이 하나로 정해지지 않음 → 모든 것은 3D 공간에 놓고 두 눈 각각에서 렌더 → UI 도 예외 없음

양안 시차가 말하는 것

\[ \text{수렴각} \approx 2\arctan\!\frac{\text{IPD}/2}{d} \]

손계산 (IPD = 두 눈 사이 약 63 mm)
d = 2 m : \(2\arctan(0.0315/2) \approx\) 1.8°
d = 1 m : \(2\arctan(0.0315) \approx\) 3.6°
d = 0.3 m : \(2\arctan(0.105) \approx\) 12°
→ 가까울수록 눈이 급격히 안쪽으로

쌍안 카메라 두 대 : 피사체 쪽으로 고개를 돌리는 동작(수렴) + 렌즈 초점 링 돌리기(조절) · 사람 눈은 이 두 동작이 한 손잡이에 연결된 카메라

지각 · 5 ★

조절-수렴 충돌 (VAC)

- 현실 : 파란 시선 두 줄과 노란 초점선이 같은 점 - HMD : 파란 시선은 0.5 m 에서 만나는데 노란 초점선은 1.5 m 에 고정 - Hoffman et al. 2008 : 이 충돌이 시각 피로를 유발
지각 · 6

VAC 손계산 — 디옵터로 거리 비교

\[ \Delta = \left|\frac{1}{d_{\text{UI}}} - \frac{1}{d_{\text{초점}}}\right| \ \ [\text{D}] \]

초점 고정면 1.5 m 가정 → \(1/1.5 \approx 0.67\,\text{D}\)

거리 대신 디옵터를 쓰는 이유 : 눈의 초점 조절 «노력» 이 거리의 역수에 비례 → 3 m ↔ 6 m 차이 (0.17 D) 는 작고 · 0.3 m ↔ 0.6 m 차이 (1.67 D) 는 큼

1.0 m1.00 D0.33 D

후속 문헌의 실무 권고 : 어긋남 약 ±0.5 D 이내 (Shibata et al. 2011 편안 영역 연구 기반 · 원문 수치 여부 확인 중) → 1.5 m 가정이면 약 0.86 m ~ 6 m 구간 → 오래 읽는 UI = 1~2 m · 0.5 m 근처는 짧은 터치용

각크기 — 크기는 미터가 아니라 «도» 로

\[ \theta = 2\arctan\!\frac{s}{2d} \]

s : 실제 크기 · d : 거리

손계산 ① 폭 0.6 m 패널 · 1.5 m
\(2\arctan(0.3/1.5) = 2\arctan(0.2) \approx\) 22.6°

손계산 ② 같은 패널 · 3 m
\(2\arctan(0.1) \approx\) 11.4° → 거리 2배 = 각크기 약 절반

DMM 환산 : 크기(mm) ÷ 거리(m)
4 cm 글자 · 1.5 m → 40 ÷ 1.5 ≈ 27 DMM
4 cm 글자 · 3 m → 13 DMM → 본문 권고 24 DMM 미달

팔 뻗은 엄지손가락 : 엄지 폭 ≈ 약 2° · 보름달 ≈ 약 0.5° → 엄지 하나로 달을 가릴 수 있는 이유 = 각크기가 4배 큼

그래서 : UI 명세에는 «0.6 m» 가 아니라 «1.5 m 거리 · 폭 약 23°» 처럼 거리와 각크기를 함께 적기

측정 방법 — 각크기 로거

// 패널의 거리·각크기·글자 DMM 출력
var cam = Camera.main.transform;
var rt  = panel.GetComponent<RectTransform>();
float w = rt.rect.width * rt.lossyScale.x;               // 실제 폭 (m)
float d = Vector3.Distance(cam.position, rt.position);   // 거리 (m)
float deg = 2f * Mathf.Atan(w / (2f * d)) * Mathf.Rad2Deg;
float yaw = Vector3.SignedAngle(cam.forward, rt.position - cam.position, Vector3.up);
float textMm = label.fontSize * rt.lossyScale.y * 1000f;  // 글자 높이 (mm)
Debug.Log($"거리 {d:F2} m · 폭 {deg:F1}° · 정면에서 {yaw:F0}° · 글자 {textMm / d:F0} DMM");
