AI 가 실제로 하는 일 — 다음 조각 예측

휴대폰 자동완성의 초대형 판 : «오늘 저녁» 을 치면 «뭐 먹지» 를 추천 → 수많은 문장에서 그다음에 자주 온 말을 고른 결과 · LLM = 이 예측을 코드·문서 수십억 줄 규모로 학습한 것

비유의 한계 : LLM 은 단어 하나가 아니라 앞의 긴 맥락 전체를 보고 예측 → 그래서 맥락(컨텍스트)이 답을 좌우

  • 무엇 : 앞에 놓인 글 전체를 보고 가장 그럴듯한 다음 토큰을 하나씩 이어 붙임
  • 왜 중요 : «그럴듯함» ≠ «정확함» → 인터넷에 흔한 코드일수록 그럴듯하게 느껴짐
  • 그래서 : 흔한 예제의 습관(오일러각 누적 · deltaTime 생략 · near 0.01)이 그대로 재현 → AI 함정의 출처
- 휴대폰 자동완성을 실제로 시연해도 좋음 - 핵심 메시지 : AI 는 «정답» 이 아니라 «흔한 것» 쪽으로 기운다 → 흔한 실수도 흔하게 나온다

토큰과 컨텍스트 윈도우

시험장 책상 : 오픈북 시험이라도 책상 넓이만큼만 펼쳐 둘 수 있음 → 책상에 없는 자료는 참고 불가 · 너무 많이 쌓으면 필요한 쪽을 못 찾음

책상 넓이 = 컨텍스트 윈도우 · 책상 위 자료 = 컨텍스트 · 자료의 분량 단위 = 토큰

대화가 길어지면 생기는 일

  • 잘림·요약 : 윈도우를 넘으면 오래된 대화부터 잘리거나 짧게 요약 → 맨 처음 말한 제약(«Linear 색공간») 소실 가능
  • 중간 망각 : 긴 컨텍스트에서 앞·뒤 정보는 잘 쓰고 가운데 정보는 덜 쓰는 경향 보고 (Liu et al., 2024)
  • 오염 : 실패한 코드·틀린 가설이 쌓여 다음 답의 재료가 됨 → 같은 실수 반복

새 세션 시작 기준 : ① 같은 오류에 3번 이상 실패 ② 주제가 바뀜(조명 → 물리) ③ AI 가 앞에서 정한 제약을 어기기 시작

시스템 프롬프트와 규칙 파일

신입 사원 업무 매뉴얼 : 매번 «고객에게는 존댓말» 이라고 말하지 않아도 첫날 받은 매뉴얼이 모든 업무에 적용 · 매뉴얼에 없는 것은 신입이 자기 습관대로 처리

시스템 프롬프트 = 도구 회사가 쓴 매뉴얼 · 규칙 파일 = 우리 팀이 덧붙이는 매뉴얼

  • 규칙 파일 : 프로젝트 폴더에 두면 코딩 에이전트가 매 요청마다 자동으로 읽는 텍스트 파일
  • 이름·위치는 도구마다 다름 — 예 : OpenCode 는 프로젝트 루트의 AGENTS.md · 사용하는 도구 문서에서 확인
  • 여기에 넣을 것 : 버전(Unity 6 · URP · XRI 3.x) · 금지 패턴(함정 #1~#6) · 단위 규칙(1 unit = 1 m)
- Antigravity 등 다른 도구도 비슷한 규칙 파일 기능 있음 — 학생이 쓰는 도구 이름으로 바꿔 설명 - 매뉴얼이 길면 신입도 안 읽는다 → 규칙 파일은 짧게 (한 화면 안)

손계산 — 비용 감각

가정 단가 : 입력 100만 토큰당 3 달러 · 출력 100만 토큰당 15 달러 (설명용 가정값 · 실제 요금은 제공사·모델·시점마다 다름)

\[ \text{전체 첨부 1회} : \tfrac{100{,}000}{10^{6}} \times 3 + \tfrac{2{,}000}{10^{6}} \times 15 = 0.30 + 0.03 = 0.33\ \text{달러} \]
\[ \text{골라 첨부 1회} : \tfrac{10{,}000}{10^{6}} \times 3 + 0.03 = 0.06\ \text{달러} \]

하루 40회 요청 : 0.33 × 40 ≈ 13.2 달러 vs 0.06 × 40 = 2.4 달러 → 약 5.5배 차이
구독형 도구도 같은 구조 → 큰 컨텍스트 = 사용량 한도가 빨리 소진

대화가 이어지면 이전 대화도 매번 다시 입력으로 계산되는 구조가 일반적 → 긴 대화 = 매 요청 비용 증가

리뷰 연습 — 문제를 찾아보기

// AI 가 만든 «부드럽게 따라오는 회전 포탑»
public class Turret : MonoBehaviour {
    public float turnSpeed = 2f;
    void Update() {
        var target = GameObject.Find("Player");
        Vector3 e = transform.eulerAngles;
        e.y += turnSpeed;
        transform.eulerAngles = e;
        if (Vector3.Distance(transform.position,
            target.transform.position) < 10f)
            GetComponent<Light>().shadows = LightShadows.Soft;
    }
}

체크리스트로 찾을 것 4개 이상 · 2분

힌트 : 체크리스트 1 · 2 · 3 · 5 번

- 정답 : ① Find 매 프레임 (3번) ② GetComponent 매 프레임 (3번) ③ eulerAngles 누적 (1번) ④ turnSpeed 에 deltaTime 없음 → 프레임당 2° (2번) ⑤ 코드에서 Soft 그림자 켬 · 끄는 코드 없음 (5번) ⑥ 목표 «따라오는» 인데 실제로는 플레이어 방향과 무관하게 계속 돎 — 명세 위반 - 수정 방향 : Awake 캐싱 · Quaternion.RotateTowards(현재, LookRotation(목표 방향), 초당 각도 × deltaTime)

  • 정리된 대화 : 실패가 쌓인 긴 대화 대신 새 세션 + 요약

같은 식재료, 다른 요리사 : 운이 아니라 장보기 목록(컨텍스트)과 레시피의 계량(검증 조건)의 차이 · 그리고 그 목록을 쓸 수 있는 근거 = 8주간 배운 개념

멀미 — 측정기는 사람의 몸

  • 무엇 : 눈은 «움직인다», 속귀(전정계)는 «가만히 있다» → 감각 불일치 · 자세 불안정 등 설명 이론이 둘 이상이고 논쟁 중 (7주)
  • 왜 에디터로 불가 : 모니터는 시야의 일부만 차지 + 주변이 고정된 방 → 같은 화면도 헤드셋에서 훨씬 강한 자기운동 착각
  • 숫자 감각 : 한 연구에서 멀미 없이 견딘 일정 속도 회전의 평균 한계 약 27°/s (요 회전) · 앞으로 이동 약 1.2 m/s — 개인차 매우 큼

실기 · 5

손 닿는 거리와 스케일

  • 스케일 : 1 unit = 1 m · 문 높이 약 2 m · 책상 약 0.75 m → 어긋나면 «거인» 또는 «소인» 느낌
  • 직접 터치 UI : 몸에서 약 42~46 cm (Meta 가이드)
  • 패널형 UI : 약 1~1.5 m
  • 자세 : 팔꿈치를 허리 높이 근처에 둘 수 있게 · 심장보다 높이 팔을 계속 들게 하면 금방 피로

부엌 동선 : 도면에서는 완벽한 부엌도 실제로 서 보면 «선반이 손에 안 닿음» · 사람 몸을 기준으로 재야 하는 치수

에디터에서 불가한 이유 : 모니터 속 0.5 m 와 1.5 m 를 몸 기준으로 구분 불가 · 사람마다 키·팔 길이 다름
