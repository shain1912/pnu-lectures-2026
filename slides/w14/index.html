왜 만든 사람은 테스트할 수 없는가

  • 지식의 저주 : 이미 아는 사람은 모르는 상태를 상상하지 못함 → 만든 사람에게 «다음에 뭘 할지» 는 너무 당연
  • 적응 : 수십 번 체험 → 멀미 둔감 · 조작 숙련 → 처음 체험자와 다른 몸
  • 기대 : 의도대로 움직이는 장면만 눈에 들어옴 → 반대 증거를 지나침

내가 쓴 글의 오타 : 내 글은 «쓰려던 문장» 이 머릿속에 있어 오타를 건너뛰고 읽음 · 남이 읽으면 첫 줄에서 발견 → 문제는 눈이 아니라 이미 아는 머리

그래서 : 체험자 = 다른 팀 · 우리 팀은 말하지 않고 기록만 → 우리가 모르는 문제가 드러나는 유일한 방법

SSQ 전후 — 점수 계산

16증상 × 0~3점 (없음·약간·중간·심함) → 증상을 세 묶음으로 합산 → 묶음별 가중치 곱 (Kennedy et al. 1993)

\[ N = 9.54\,n \quad O = 7.58\,o \quad D = 13.92\,d \quad \text{Total} = 3.74\,(n+o+d) \]

n · o · d : 오심 · 안구운동 · 방향감각 상실 묶음에 속한 문항 점수의 합 (한 문항이 두 묶음에 들어가기도 함)

체험 전

n = 1 · o = 2 · d = 0
Total = 3.74 × 3 ≈ 11.2

체험 직후

n = 3 · o = 4 · d = 2 → D = 13.92 × 2 ≈ 27.8
Total = 3.74 × 9 ≈ 33.7 → 변화 +22.4

기록하는 값 = 직후 − 사전 (변화량) · 사전 점수가 이미 높은 사람(피곤·두통)을 구별하기 위해 사전 측정 필수

테스트 · 7

SSQ 를 읽을 때의 한계

  • 절단점 없음 : «몇 점 이상 = 위험» 이라는 합의된 기준 없음 · 원래 비행 시뮬레이터 사용자로 만든 척도 → 버전 간 · 전후 비교로만 사용
  • 표본이 작음 : 팀당 체험자 2~4명 → 통계적 결론 불가 → 경향 · 중단자 수 · 발화와 함께 읽기
  • 사전 설문의 암시 : 증상 목록을 먼저 읽으면 증상을 더 의식할 가능성
  • 요구 특성 : 친구 팀 앞에서 «괜찮아» → 말 대신 설문지에 직접 표기 · 진행자는 점수를 보며 반응하지 않기

② 원인 — 렌더 경로의 차이

  • 타일 기반 GPU : 타일 안에서 끝나는 작업은 빠름 · 화면 전체를 메모리에 썼다 다시 읽는 작업(후처리 · Depth/Opaque Texture 복사 · HDR)은 대역폭 소모 큼 → 데스크톱에선 거의 공짜인 설정이 헤드셋에선 비쌈

  • 발열 · 클럭 레벨 : 헤드셋은 온도·부하에 따라 CPU/GPU 속도 단계를 조정 → 처음 1분과 10분 후 수치가 다를 수 있음
  • AI 의 시야 : 코드와 사람이 붙여 준 로그만 앎 → 병목 위치를 모른 채 «일반적인 최적화 목록» 을 적용

  • 체험 대기 중인 사람 = 다른 체험자의 플레이를 보지 않기 (스포일러 방지) → 대기석은 화면 반대쪽
  • 체험자는 받은 과업 카드 외 정보 없음 · 기획서도 미리 보지 않음

도입 질문의 답

왜 처음 해 본 사람은 같은 자리에 서 있었나

만든 사람의 머릿속에만 있는 정보 = 체험 안에는 없는 정보
→ 만든 사람은 그 정보를 «보이는 것» 으로 착각 (지식의 저주)

  • «다음 목표» 를 만든 사람은 알고 있음 · 체험자에겐 시야 ±30° 밖이라 보이지 않음
  • «이건 잡을 수 있다» 를 만든 사람은 알고 있음 · 체험자에겐 잡을 수 있는 물체와 배경의 구분 단서 없음
  • 만든 사람은 수십 번 체험으로 적응 → 멀미 신호도 둔감

우리 집 가는 길 설명 : «편의점에서 꺾어» 라고 말하는 사람은 편의점이 두 개라는 사실을 의식하지 못함 · 처음 오는 사람만 갈림길에서 멈춤

해결 : 짐작이 아니라 관찰 — 남의 몸이 멈춘 지점이 곧 설계가 정보를 빠뜨린 지점
