뷰 행렬 — 카메라 이동의 실제 의미

\[ V = (\text{카메라의 월드 변환})^{-1} \]

GPU에는 "카메라"라는 물건이 없음 → 카메라는 항상 원점에서 −Z 방향을 본다고 가정 → 그래서 카메라를 움직이는 대신 세상 전체를 반대로 이동 (위 식의 역행렬 = 되돌리는 변환)

손계산 · 카메라 위치 (0, 0, 5)
→ 뷰 행렬 = 세상 전체를 (0, 0, −5) 이동
→ 월드 원점의 상자는 뷰 공간에서 \( z=-5 \)
= "카메라 정면 5m 앞"

뷰 행렬 = 고정 카메라 앞에서 무대 세트를 미는 촬영 · 카메라는 삼각대에 고정, 대신 세트 전체를 반대 방향으로 밀어 옮김 · 찍힌 화면은 카메라를 움직인 것과 똑같음 · 기차 창밖 풍경이 뒤로 흘러가는 느낌과 같은 원리

11주차 연결 : VR에서 카메라 Transform 직접 조작 금지의 근거

- 무대 세트 비유 : "영화 촬영장에서 카메라를 못 움직이게 묶어 두고, 대신 세트를 통째로 밀면 화면은 똑같이 나온다. GPU가 바로 이렇게 한다" - 손계산 : 카메라를 +Z로 5 → 세상을 −Z로 5 → 원점 물체가 카메라 앞 5m

원근의 원리 — 닮은꼴 삼각형

눈에서 화면(near 평면)까지 거리 \( n \) · 물체까지 거리 \( -z \)
(카메라가 −Z를 보므로 앞쪽 물체는 \( z \lt 0 \))

\[ \frac{x'}{x} = \frac{n}{-z} \;\Rightarrow\; x' = \frac{n\,x}{-z},\quad y' = \frac{n\,y}{-z} \]

손계산 · \( n=1 \), 점 \( (2,\,1,\,-4) \)
\( x' = 1\cdot 2 / 4 = 0.5 \), \( y' = 1\cdot 1/4 = 0.25 \)
같은 점을 8m 뒤로(\( z=-8 \)) → \( x'=0.25 \) · 두 배 멀면 절반 크기

창문 유리에 바깥 풍경 따라 그리기 · 눈을 한 자리에 고정하고 유리 위에 나무 윤곽을 그리면, 멀리 있는 나무일수록 유리 위 그림이 작아짐 · 유리 = near 평면, 그림 크기 = 실제 크기 ÷ 거리

원리 : 거리로 나눗셈 · 멀수록 \( -z \) 증가 → 나눈 결과 감소

문제 : 행렬 곱셈은 곱하고 더하기만 가능 → "z로 나누기"를 직접 표현할 방법 없음

- 창문 비유 : 뒤러(Dürer)의 원근 투시 장치와 같은 원리 · 유리창에 매직으로 따라 그리기 경험을 떠올리게 함 - 손계산을 칠판에 : 4m 거리 → 0.5, 8m 거리 → 0.25 - 마지막 줄의 문제를 다음 슬라이드가 해결

\[ P = \begin{bmatrix} \frac{1}{a\,t} & 0 & 0 & 0 \\[6pt] 0 & \frac{1}{t} & 0 & 0 \\[6pt] 0 & 0 & -\frac{f+n}{f-n} & -\frac{2fn}{f-n} \\[6pt] 0 & 0 & \color{#c2401d}{-1} & 0 \end{bmatrix} \]

깊이 값의 불균등 분포

거리 \( d \) 를 NDC 깊이(−1~+1)로 바꾸는 식

\[ z_{ndc} = \frac{f+n}{f-n} - \frac{2fn}{(f-n)\,d} \]

거리 \( d \) 가 분모에 있음 → \( 1/d \) 곡선 → near 근처는 숫자가 빠르게 변하고(촘촘), 멀어질수록 거의 안 변함(성김)

가까운 곳엔 촘촘하고 먼 곳엔 듬성듬성한 자 · 눈금 개수는 정해져 있는데 대부분이 자의 앞부분에 몰림 → 먼 곳에서는 2mm 차이를 잴 눈금이 없음

near=0.1, far=1000 이면 → 깊이 숫자의 절반이 0.1m~0.2m 구간에 배정 · 나머지 999.8m 가 남은 절반을 나눠 씀

"far 가 아니라 near 가 문제다."

정밀도를 결정하는 값 : 1/near − 1/far
far=10000 → 1/far = 0.0001 ≈ 0
near=0.01 → 1/near = 100

// near 0.01 → 0.3
// 정밀도 약 30배, 먼 시야는 그대로

// far/near 상한을 명세에 명시

위험한 이유 : 개발자 화면에서는 정상으로 보임 · 카메라가 멀리 있고 움직일 때만 드러남

- 학생들이 이 프롬프트를 그대로 입력하도록 진행 - 모델의 응답을 각자 확인하고 near 값을 소리내어 읽기 - 결과는 0.01 ~ 0.03 처럼 Unity 기본값(0.3)보다 훨씬 작은 값이 자주 나옴
함정 · 2

AI가 이 값을 반복하는 이유

  • Unity 기본값은 near 0.3 · far 1000 → 그런데 "가까이 가면 물체가 잘려요" 해결 글에서 near 를 0.01 수준으로 낮추라는 답이 흔함
  • near 를 작게 잡으면 물체가 카메라를 뚫는 문제 방지 — 즉시 보이는 안전
  • far 를 크게 잡으면 먼 물체 사라짐 방지 — 역시 즉시 보이는 안전
  • z-fighting 은 멀리서, 움직일 때만 드러나는 증상 → 정지 화면·짧은 테스트에서 잘 안 보임

이번 주 명세 예시

[목표]
지형 위를 따라다니는 3인칭 카메라. 시야 거리 500m.

[제약]
- 깊이 버퍼는 24비트를 쓴다
- nearClipPlane 은 0.1 이상일 것
- farClipPlane / nearClipPlane 비율이 5,000 을 넘지 않을 것
- 카메라 파라미터는 인스펙터에서 조정 가능할 것

[검증 조건]
- 200m 지점의 바닥 위에 두께 0 인 데칼을 올려 두고
  카메라를 좌우로 5초간 흔들었을 때 깜빡이는 픽셀이 0 일 것
- 위 공식 Δd = d²(1/n - 1/f) / 2^24 로 계산한
  200m 에서의 Δd 가 5mm 이하일 것

[비목표]
- 충돌 처리, 카메라 흔들림 연출, 후처리는 만들지 말 것

손계산 · near 0.1, far 500, 200m
\( 200^2\times 9.998 \div 2^{24} \approx 0.024\,\text{m} \) = 24mm → 불합격
5mm 이하가 되려면 near ≥ 약 0.48
→ 제약(0.1 이상)만 지켜서는 부족 · 검증 조건이 near 를 더 끌어올림

두 검증 조건의 유형 차이 : 하나는 관찰로 측정, 하나는 계산으로 측정
