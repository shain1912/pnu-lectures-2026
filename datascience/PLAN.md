상세 설계: [COURSE_DESIGN.md](COURSE_DESIGN.md) — 학습 목표·평가 연결, 2주차 시범 수업, 합성 데이터 예시, 제작 완료 기준.

## 1. 작업 범위와 기존 자료 파악

이번 단계는 독립 과목 폴더 생성과 제작 계획 작성까지다. 실제 슬라이드, 실습 코드, 데이터셋은 이후에 제작한다.

- 기존 `plato/`는 컴퓨터그래픽스·VR 강의자료 작업 공간이다. 루트 `PLAN.md`에 16주 운영과 제작 계획이 있다.
- 실제 작성된 주요 자료는 `slides/w02/index.html`, `slides/_shared/`의 테마·초기화·데모, `assignments/w02/`의 과제 2종, `figures/`의 도해·애니메이션 관련 파일이다.
- 슬라이드는 reveal.js HTML, 과제는 Markdown이다. 기존 수업은 개념 이해 → AI에 명세 작성 → 결과 검증을 강조한다.
- `syllabus/`, `setup/`, `labs/`, `starters/`, `notes/`, `rubrics/`는 마련되어 있으나 파일 목록에서 완성된 자료는 확인되지 않았다. 계획과 구현 상태를 구분한다.
- 루트의 PDF 3개는 기존 과목 참고자료로 보존한다. 이번 초안에서는 PDF 본문을 검토하지 않았다.
- 현재 경로에서 Git 저장소는 확인되지 않았다. 기존 파일의 이동·수정, Git 초기화는 수행하지 않는다.

모든 신규 산출물은 `datascience/` 안에 둔다. 기존 테마나 제작 방식을 채택하더라도 향후 필요한 파일을 이 폴더 안에 복사해 독립적으로 관리하며, 기존 파일을 직접 참조하거나 수정하는 구조는 피한다. 기존 `.venv`도 변경하지 않는다.

## 2. 확정 사항과 미정 사항

**확정:** 별도 `datascience/` 폴더에서 다른 과목의 강의자료를 계획한다. 기존 작업은 보존한다.

**초안의 가정:** 과목은 데이터사이언스 입문이며, 비전공자도 따라갈 수 있는 프로젝트 중심 수업이다. 아래 16주 구성은 분량을 검토하기 위한 가안이다.

실제 제작 전에 확인할 항목:

| 항목 | 필요한 결정 | 영향 |
|---|---|---|
| 공식 과목 정보 | 과목명, 제출된 강의계획서와 고정 주차 제목 | 주차 구성의 기준선 |
| 수강 대상 | 전공·학년, Python·통계 선수지식 | 설명 수준과 기초 보충 범위 |
| 운영 시간 | 총 주차, 주당 시간, 이론·실습 비율 | 슬라이드 분량과 실습 길이 |
| 평가 방식 | 시험·과제·프로젝트 비중, 개인·팀 여부 | 제출물과 루브릭 |
| 실습 환경 | 브라우저 노트북 또는 로컬 환경, 계정·인터넷 제약 | 설치 가이드와 배포 방식 |
| AI 활용 | 허용 범위와 사용 내역 제출 방식 | 실습 안내와 평가 기준 |
| 사례 분야 | 디자인·문화·사회·비즈니스 등 | 공통 데이터와 프로젝트 주제 |

기존 그래픽스 과목의 수강 대상·평가 비중·3시간 운영을 새 과목의 확정 조건으로 가져오지 않는다.

## 3. 수업의 중심 질문과 학습 목표

> AI가 분석 코드를 만들어주는 시대에, 우리는 데이터로 무엇을 질문하고 결과를 어떻게 믿을 수 있는가?

학기 말 학생이 할 수 있어야 하는 일:

1. 막연한 관심사를 데이터로 답할 수 있는 질문으로 바꾼다.
2. 데이터의 단위, 수집 방식, 누락과 편향을 설명한다.
3. 정제·탐색·시각화 과정을 재현 가능한 분석으로 구성한다.
4. 비교와 예측에 적절한 기준을 세우고 결과를 검증한다.
5. 분석의 한계와 불확실성을 포함해 결론을 전달한다.

매주 `질문 → 개념 → 분석 명세 → 실행 → 검증 → 해석`의 흐름을 사용한다. AI 활용 여부와 관계없이 학생이 판단 근거를 설명하게 한다. 코드 문법만 따라 치거나 모델 성능 숫자만 높이는 과제로 구성하지 않는다.

## 4. 주차별 구성 가안

공식 강의계획서를 받으면 그 제목과 일정에 맞춰 재배치한다. 15주 운영이라면 16주 내용을 최종 발표·피드백에 통합한다.

| 주 | 핵심 질문 / 개념 | 실습·산출물 | 검증할 오류 |
|---|---|---|---|
| 1 | 데이터사이언스는 어떤 질문에 답하는가? | 질문 카드, 데이터 관찰, 환경 확인 | 데이터가 답할 수 없는 질문 |
| 2 | 표의 한 행은 무엇을 뜻하는가? / Python·표 데이터 기초 | 작은 표 읽기, 데이터 사전 | 숫자처럼 보이는 식별자를 수치로 처리 |
| 3 | 필요한 정보를 어떻게 추출하는가? / 선택·집계·결합 | 질문별 집계 노트북 | 결합 후 행 수 증가와 중복 집계 |
| 4 | 깨끗한 데이터란 무엇인가? / 결측·중복·자료형 | 정제 전후 비교와 처리 근거 | 결측을 모두 0으로 치환 |
| 5 | 평균 하나로 충분한가? / 분포·변동·이상치 | 탐색적 분석 리포트 | 평균만 보고 집단 차이 무시 |
| 6 | 그래프는 무엇을 강조하고 숨기는가? | 같은 데이터의 시각화 비교 | 축·분모·구간 선택으로 생기는 왜곡 |
| 7 | 관찰한 차이를 믿을 수 있는가? / 표본·불확실성 | 표본추출 시뮬레이션 | 표본 편향과 과도한 일반화 |
| 8 | 중간: 질문에 근거 있게 답하기 | 개인 탐색 분석, 설명·피드백 | 결론과 증거의 불일치 |
| 9 | 함께 움직이면 원인인가? / 상관·교란·비교 | 집단별 분석과 해석 수정 | 상관을 인과로 단정 |
| 10 | 예측이 유용하다는 기준은? / 기준모델·데이터 분할 | 단순 기준모델, 분할 계획 | 학습 데이터로 성능 평가 |
| 11 | 수치를 어떻게 예측하는가? / 회귀·오차 | 예측과 잔차 해석 | 데이터 누수와 외삽 |
| 12 | 범주를 어떻게 구분하는가? / 분류·평가 지표 | 혼동행렬, 지표 비교 | 불균형 데이터에서 정확도만 사용 |
| 13 | 어떤 프로젝트가 검증 가능한가? | 기획서, 데이터 점검, 분석 계획 | 범위 과다와 검증 기준 누락 |
| 14 | 다른 사람이 같은 결과를 얻을 수 있는가? | 재실행·상호 검토, 분석 보완 | 숨은 실행 순서와 누락된 전처리 |
| 15 | 결과를 어떻게 설득력 있게 전달하는가? | 최종 발표, 분석물, 한계 보고 | 증거보다 강한 결론 |
| 16 | 무엇을 고치면 분석이 더 좋아지는가? | 피드백 반영, 포트폴리오 정리 | 수정 근거와 변경 기록 누락 |

범위 조정 원칙: Python 선수지식이 없으면 2~4주 기초를 늘리고 예측 모델 범위를 줄인다. 통계적 추론의 깊이는 수강 대상 확인 후 결정한다. 딥러닝·대규모 데이터 처리·배포는 초기 필수 범위에 넣지 않는다.

표는 일반 수업 주의 기본 구성이다. 프로젝트·발표 주는 기획서·평가표·피드백 양식으로 대체하여 불필요한 문서 수를 늘리지 않는다. 교수용 해설은 학생 배포 묶음에서 제외한다.

공통 자료는 상세 강의계획서, 환경 안내, AI 활용 정책, 분석 리포트 양식, 평가 루브릭, 프로젝트 가이드로 구성한다. 슬라이드 장수와 실습 시간은 주당 수업 시간 확인 후 정한다.

## 7. 제작 순서와 완료 기준

| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| P0 · 과목 설계 | 공식 계획·수강 대상·운영 조건 반영 | 주차별 목표와 평가 연결, 미정 조건 정리 |
| P1 · 표준 설계 | 주차 템플릿, 데이터 선정 기준, 환경·제출 양식 정의 | 이후 주차가 따를 자료 규격 확보 |
| P2 · 한 주 시범 제작 | 2주차를 우선 후보로 슬라이드·노트북·과제·해설 제작 | 학생 출발 수준에서 실행 가능, 실제 수업 시간 안에 완료 |
| P3 · 전반부 제작 | 1~7주 자료와 중간 프로젝트 명세 | 개념 난이도 연결, 데이터·과제 정합성 확인 |
| P4 · 후반부 제작 | 9~14주와 기말 프로젝트 명세 | 모델 평가·재현성 검증, 프로젝트 범위 적정 |
| P5 · 평가·배포 정리 | 8·15·16주 운영 자료, 전체 링크·용어·배포 점검 | 학생용 묶음 완성, 교수용 자료 분리 |

시범 주차에서 내용 밀도와 시각 스타일을 검토한 뒤 나머지 주차로 확장한다. 자료 제작 전에 필요한 도구·버전·공식 문서를 조사하고, 실제 데이터셋의 이용 조건과 접근 가능성을 확인한다. 이번 초안에서는 도구 버전과 특정 데이터셋을 확정하지 않는다.

## 8. 품질 기준

- 매주 학습 목표가 실습 활동과 평가 항목에 연결되어야 한다.
- 실습은 새 환경에서 처음부터 순서대로 실행되어야 한다. 입력 데이터와 난수 사용 조건을 기록한다.
- 그래프의 제목·축·단위·범례를 확인하고 색만으로 의미를 구분하지 않는다.
- 데이터의 출처·이용 조건·수집 및 가공 내역을 기록한다. 민감한 실제 학생 데이터 대신 공개 또는 합성 데이터를 우선 검토한다.
- 예측 실습은 기준모델, 분할 근거, 데이터 누수 여부, 지표 선택 이유를 포함한다.
- AI를 사용한 학생도 질문·처리 방식·결과 해석을 직접 설명할 수 있어야 한다.
- 모든 경로와 의존성은 `datascience/` 기준으로 관리한다. 기존 그래픽스 자료에 대한 수정 없이 배포 가능해야 한다.

## 9. 다음 논의

우선 과목의 공식 강의계획서 유무와 수강생 수준을 확인한다. 그 정보를 바탕으로 위 주차 구성을 수정하고, 주당 시간·평가·실습 환경을 정한 후 시범 주차 제작으로 넘어간다.
