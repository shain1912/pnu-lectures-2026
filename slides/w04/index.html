원근의 원리 — 닮은꼴 삼각형

눈에서 near 평면까지 거리 n, 물체까지 거리 -z (앞쪽은 z < 0) x' n n·x n·y ─── = ───── → x' = ───── , y' = ───── x (-z) (-z) (-z)

원리 : 거리로 나눗셈 · 멀수록 -z 증가 → 나눈 결과 감소

문제 : 행렬 곱셈에는 나눗셈 연산이 없음

투영 행렬 — w 에 거리 저장

t = tan(시야각/2), a = 종횡비 ⎡ 1/(a·t) 0 0 0 ⎤ P = ⎢ 0 1/t 0 0 ⎥ ⎢ 0 0 -(f+n)/(f-n) -2fn/(f-n) ⎥ ⎣ 0 0 -1 0 ⎦ ↑ 이 한 칸 → 원근 생성

마지막 행의 -1 → 곱셈 결과의 w 자리에 -z 저장

깊이 · 2

깊이 값의 불균등 분포

거리 d 를 NDC 깊이로 바꾸면 f + n 2fn z_ndc = ─────── - ───────── f - n (f - n)·d 분모에 d — 1/d 곡선 near 근처는 촘촘, 멀어질수록 급격히 성김

near=0.1, far=1000 → 깊이 값의 절반이 0.1m~0.2m 구간에 배정
나머지 999.8m 구간이 남은 절반을 분할

깊이 · 3 ★

정밀도를 결정하는 값 : near

- 붉은 선(near 0.01/far 1000)과 노란 선(near 0.01/far 100)의 겹침 짚기 - 학생에게 먼저 질문 : "far 를 10분의 1로 줄였는데 왜 안 움직이죠?" - 답 : 1/near - 1/far 에서 1/1000, 1/100 모두 1/0.01 = 100 앞에서 무의미
깊이 · 4

깊이 분해능 공식

거리 d 에서 깊이 버퍼가 구분할 수 있는 최소 간격 d² · (1/n - 1/f) Δd ≈ ────────────────── b = 깊이 버퍼 비트 수 (보통 24) 2^b
near / far1/n − 1/f100m 에서 Δd
0.01 / 10000100.060 mm깜빡임
0.01 / 10099.9960 mm동일하게 깜빡임
0.3 / 100003.332 mm정상

far 100배 감소 → 변화 없음 · near 30배 증가 → 정밀도 30배 향상
오늘 수업의 핵심 한 줄

깊이 · 5 ★

z-fighting 함정 재현

2mm 떨어진 두 면

청록 = 바닥면 · 분홍 = 그 위 2mm 에 붙인 스티커 · 왼쪽 아래 가까운 쌍은 간격이 같아도 정상

- ① far 슬라이더만 10000 → 100 으로 끝까지 감소 · 깜빡임 변화 없음 → "far 를 줄이면 된다"는 통설 반박 - ② near 를 0.01 → 0.3 으로 증가 · 즉시 해결 - ③ 왼쪽 아래 가까운 쌍 : 같은 2mm인데 정상인 이유 → Δd 는 거리의 제곱에 비례

// far / near = 1,000,000 : 1

학생이 해야 할 지적

"far 가 아니라 near 가 문제다."

정밀도를 결정하는 값 : 1/near − 1/far
far=10000 → 1/far = 0.0001 ≈ 0
near=0.01 → 1/near = 100

// near 0.01 → 0.3
// 정밀도 30배, 시야는 그대로

// far/near 상한을 명세에 명시

위험한 이유 : 개발자 화면에서는 정상으로 보임
카메라가 멀리 있고 움직일 때만 드러남

- 학생들이 이 프롬프트를 그대로 입력하도록 진행 - 모델의 응답을 각자 확인하고 near 값을 소리내어 읽기 - 결과는 거의 전부 0.01 ~ 0.03
함정 · 2

AI가 이 값을 반복하는 이유

  • 학습 데이터의 튜토리얼 대부분이 near=0.01, far=1000 으로 시작
  • near 를 작게 잡으면 물체가 카메라를 뚫는 문제 방지 — 즉시 보이는 안전
  • far 를 크게 잡으면 먼 물체 사라짐 방지 — 역시 즉시 보이는 안전
  • z-fighting : 통계적 증상 · 정지 화면에서는 잘 드러나지 않음

AI의 응답 경향 : 즉시 보이는 실패 회피 우선
나중에 드러나는 정밀도 붕괴는 요구가 없으면 미고려

따라서 명시적 요구 필요 → 명세의 역할

실습 · 2

이번 주 명세 예시

[목표]
지형 위를 따라다니는 3인칭 카메라. 시야 거리 500m.

[제약]
- 깊이 버퍼는 24비트를 쓴다
- nearClipPlane 은 0.1 이상일 것
- farClipPlane / nearClipPlane 비율이 5,000 을 넘지 않을 것
- 카메라 파라미터는 인스펙터에서 조정 가능할 것

[검증 조건]
- 200m 지점의 바닥 위에 두께 0 인 데칼을 올려 두고
  카메라를 좌우로 5초간 흔들었을 때 깜빡이는 픽셀이 0 일 것
- 위 공식 Δd = d²(1/n - 1/f) / 2^24 로 계산한
  200m 에서의 Δd 가 5mm 이하일 것

[비목표]
- 충돌 처리, 카메라 흔들림 연출, 후처리는 만들지 말 것

두 검증 조건의 유형 차이 확인
하나는 관찰로 측정, 하나는 계산으로 측정
