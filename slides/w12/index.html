VR 에서 «느림» 이 «불편» 이 되는 이유

  • 모니터 게임 : 프레임이 떨어지면 화면이 끊겨 보임 → 짜증 · 그래도 몸은 편함
  • VR : 화면이 머리에 붙어 있음 → 고개를 돌리는 순간에도 새 그림이 늦게 도착 → 같은 그림이 두 번 표시 → 세상이 머리와 함께 끌려가다 툭 튀는 장면 (저더, judder)
  • 그래서 : 눈이 본 움직임 ≠ 귀 속 평형 기관이 느낀 움직임 → Part II 의 감각 충돌 → 멀미

정시 출발 기차 : 디스플레이는 11.1 ms 마다 정확히 출발하는 기차 · 그림(승객)이 늦으면 기차는 기다리지 않고 지난번 승객을 다시 태워 출발 → 화면에는 낡은 그림이 한 번 더 표시

비유의 한계 : 실제 헤드셋은 낡은 그림을 머리 회전에 맞춰 살짝 비틀어 보냄 (재투영) → 회전은 일부 보정 · 움직이는 물체는 보정 불가

결론 : VR 의 성능 목표 = «평균 fps» 가 아니라 모든 프레임이 마감 안에 도착

- 기차 비유 : vsync = 정시 출발 · 프레임 = 승객 - 평균 89fps 라도 1초에 몇 번 마감을 놓치면 그때마다 저더 → "평균" 이 아니라 "최악의 프레임" 이 중요

앱이 주사율을 따로 요청하지 않으면 72 Hz 로 동작하는 경우가 많음 (기기·OS 버전마다 다름)

- 3주차에서 한 계산 재확인 · 칠판에 1000 ÷ 90 을 같이 써 보기 - 120Hz 는 8.3ms — 더 매끄럽지만 예산이 1/4 줄어듦 → 우리 수업은 90 고정

CPU 병목 vs GPU 병목

식당 주방 : CPU = 주문을 받아 조리 지시서를 쓰는 홀 직원 · GPU = 실제로 요리하는 화구 · 둘은 동시에 일함 → 손님 대기 시간은 더 느린 쪽이 결정

비유의 한계 : 실제 GPU 는 화구 수천 개가 같은 조리법을 동시에 처리 → 픽셀이 많을수록 느려짐

두 눈 = 픽셀 2배

손계산 — Quest 3 패널 한 눈 2064 × 2208

\[ 2064 \times 2208 \approx 456\text{만} \ \text{픽셀} \]

두 눈 : 약 911만 픽셀 · 90 Hz : 1초에 약 8.2억 픽셀 칠하기
비교 : 1080p 모니터 60 Hz = 207만 × 60 ≈ 1.2억 → 약 7배

패널 해상도 기준 · 실제 렌더 해상도는 렌더 스케일 설정마다 다름

싱글패스 인스턴싱Single Pass Instanced
두 눈을 주문서 한 장으로 동시에 그리는 방식 (4주차) → 드로우콜은 두 배가 되지 않음

정리 : 두 눈 렌더링에서
CPU 쪽 (주문서 수) → 싱글패스로 거의 그대로

전정계는 «속도» 가 아니라 «가속» 을 느낀다

엘리베이터 : 출발·정지하는 순간에만 몸이 쑥 꺼지거나 눌리는 느낌 · 일정한 속도로 오르는 중간에는 눈을 감으면 움직이는지 모름

함정 · 원인

② 원인 — 코드에 숨은 가속

// AI 가 내놓은 "부드러운" 이동 (요약)
Vector3 vel, velRate;
void Update() {
    Vector3 target = MoveDir() * 4f;                               // 최고 4 m/s
    vel = Vector3.SmoothDamp(vel, target, ref velRate, 0.8f);      // 0.8초에 걸쳐 가속·감속
    rig.position += vel * Time.deltaTime;
    rig.Rotate(0f, TurnInput() * 90f * Time.deltaTime, 0f);        // 부드러운 회전 90°/s
}

// 스타터 MotionLogger.cs 핵심 (리그에 부착)
Vector3 lastPos, lastVel; float lastYaw;
void Update() {
    float dt = Time.deltaTime;
    Vector3 vel = (rig.position - lastPos) / dt;               // 속도 (m/s)
    float acc   = (vel - lastVel).magnitude / dt;              // 가속도 (m/s²)
    float yawRate = Mathf.DeltaAngle(lastYaw, rig.eulerAngles.y) / dt; // 회전 (°/s)
    if (acc > 0.7f) accelFrames++;                             // 임계 초과 프레임 수
    lastPos = rig.position; lastVel = vel; lastYaw = rig.eulerAngles.y;
}

비교 지표 : 최대 가속도 · 0.7 m/s² 초과 프레임 수 · 최대 회전 속도 · 체험 시간

SSQ : 체험 직전 · 직후 종이 설문 → N·O·D·TS 손계산 → 워크북 기록표

- 스냅 턴은 한 프레임에 22.5° → yawRate 가 순간적으로 매우 큼 (2025°/s @90Hz) → 회전 속도 지표는 "연속 회전 시간" 으로 함께 볼 것 - 텔레포트도 순간 가속이 매우 큼 → 그래서 "초과 프레임 수" 가 더 의미 있는 지표
