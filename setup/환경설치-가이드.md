### 폴더 규칙 (중요)

- 프로젝트 폴더 경로에 **한글 · 공백 · 특수문자 금지**
  - 좋은 예 : `C:\UnityProjects\PerceptionLab` · `~/UnityProjects/PerceptionLab`
  - 나쁜 예 : `C:\Users\홍길동\바탕 화면\컴그 과제\`
- **OneDrive · iCloud Drive · Google Drive 동기화 폴더 안에 만들지 않기** → 파일 잠금·충돌로 프로젝트 손상 가능
- 이유 : Unity 와 안드로이드 빌드 도구 일부가 한글·공백 경로에서 오류를 냄

## 2. Unity Hub · 계정 · 라이선스

1. https://unity.com/download 에서 **Unity Hub** 다운로드 · 설치
   - Windows : `UnityHubSetup.exe` 실행

## 4. 코드 에디터 연결

둘 중 하나 선택 · 수업 예시는 VS Code 기준

### 4-A. VS Code

1. https://code.visualstudio.com 에서 설치
2. VS Code 확장(Extensions) 에서 **Unity** (Microsoft 제작) 설치 → 필요한 **C# Dev Kit** · **C#** 확장이 함께 설치됨
   - C# Dev Kit 이 **.NET SDK** 설치를 요구하면 안내에 따라 설치
3. Unity 에서 연결
   - Windows : **Edit → Preferences → External Tools**
   - macOS : **Unity → Settings → External Tools**
   - **External Script Editor** = Visual Studio Code
4. Unity 패키지 **Visual Studio Editor** (`com.unity.ide.visualstudio`) 가 설치되어 있는지 확인 : **Window → Package Manager** → In Project 목록
   - 이 패키지가 VS Code 연동을 담당 · 템플릿에 기본 포함
5. 확인 : Project 창에서 아무 스크립트나 더블클릭 → VS Code 에서 열리고 `transform.` 입력 시 자동완성 목록 표시

### 4-B. JetBrains Rider

1. https://www.jetbrains.com/rider/ 에서 설치 · **비상업 용도 무료** 라이선스 또는 학생 교육용 라이선스
2. Unity 의 External Tools → External Script Editor = **Rider**
3. Unity 패키지 **JetBrains Rider Editor** 확인 (템플릿에 기본 포함)

## 5. Git · GitHub

### 5-1. Git 설치

| OS | 방법 |
|---|---|
| Windows | https://git-scm.com 에서 **Git for Windows** 설치 · 옵션은 기본값 · 함께 설치되는 **Git Bash** 사용 가능 |
| macOS | 터미널에서 `git --version` 입력 → 없으면 **Xcode Command Line Tools** 설치 창이 뜸 → 설치 · 또는 Homebrew `brew install git` |

설치 후 터미널에서 1회 설정 :

```bash
git config --global user.name "홍길동"
git config --global user.email "github에-등록한-메일@example.com"
git config --global init.defaultBranch main
```

### 5-2. GitHub 계정

- https://github.com 가입 · 학생이면 **GitHub Student Developer Pack** 신청 가능 (선택)
- 로그인 방법 : 첫 `git push` 때 브라우저 로그인 창 → 허용 (Windows 는 Git Credential Manager 가 처리)
  - 비밀번호 입력을 요구하면 → 계정 비밀번호가 아니라 **Personal Access Token** 필요 → [FAQ G6](트러블슈팅-FAQ.md#g6)
- 명령어가 부담되면 **GitHub Desktop** 앱 사용 가능 · 단, 수업 예시는 명령어 기준

## 6. AI 코딩 도구

### 6-1. 세 갈래

| 종류 | 예 | 내 프로젝트를 보는 범위 | 이 수업에서의 쓰임 |
|---|---|---|---|
| **채팅형** | 웹·앱 대화창 AI | 붙여 넣은 내용만 | 개념 질문 · 짧은 코드 · 오류 메시지 해석 |
| **에디터 통합형** | VS Code·Rider 의 AI 확장 · AI 내장 에디터 | 열린 파일 중심 | 스크립트 작성·수정 |
| **에이전트형** | OpenCode · Claude Code · Antigravity 등 | **프로젝트 폴더 전체**를 읽고 파일 수정·명령 실행 | 여러 파일에 걸친 작업 · 씬 구성 안내 |

- 하나만 골라도 됨 · 요금제·무료 사용량은 도구마다 다르고 자주 바뀜 → 각 공식 사이트 확인
- 어떤 도구든 **도구 이름과 모델 이름을 프롬프트 로그에 기록** ([AI 사용 정책](../syllabus/AI-사용-정책.md))

### 6-2. 에이전트형 설치 (일반 절차)

설치 명령은 도구 공식 문서가 정답 · 아래는 공통 흐름

1. 공식 사이트의 설치 안내 확인
   - 터미널 도구(OpenCode · Claude Code 등) : 설치 스크립트 한 줄 또는 `npm` 으로 설치하는 방식이 흔함
   - `npm` 방식이면 먼저 **Node.js LTS** 설치 (https://nodejs.org)
   - 에디터형(Antigravity 등) : 설치 파일 다운로드 후 실행
2. 설치 확인 : 터미널을 **새로 열고** 도구 이름 입력 → 실행되면 성공 (`command not found` → [FAQ A6](트러블슈팅-FAQ.md#a6))
3. 로그인 또는 API 키 설정 (도구 안내에 따름)
4. **실행 위치 = Unity 프로젝트 폴더** : `cd C:\UnityProjects\PerceptionLab` 후 도구 실행 → 그래야 프로젝트 파일을 읽음

### 6-3. 에이전트형 안전 수칙

- 실행 **전에 커밋** — AI 가 파일을 고친 뒤 되돌릴 지점 확보
- 작업 후 `git status` 로 **바뀐 파일 목록 확인** — 의도하지 않은 파일 수정 여부
- `Library/` · `Temp/` 폴더 수정 요청은 거절 (Unity 가 자동 생성하는 폴더)
- 실행 권한 묻는 창 : 명령 내용을 읽고 이해한 것만 허용 · 삭제(`rm`, `del`) 명령은 특히 주의
- 개인정보·API 키를 프롬프트나 저장소에 넣지 않기

## 7. 첫 프로젝트 `PerceptionLab`

### 7-1. 만들기

1. Hub → **Projects → New project**
2. 에디터 버전 : 설치한 Unity 6 LTS
3. 템플릿 : **Universal 3D** (URP) — 처음 쓰면 템플릿 다운로드 버튼 먼저
4. Project name : `PerceptionLab` · Location : 한글·공백 없는 폴더 (예 `C:\UnityProjects`)
5. Unity Cloud 연결 옵션은 **꺼도 됨** (이 수업은 GitHub 사용)
6. **Create project** → 첫 실행은 수 분 소요 (Library 폴더 생성)

### 7-2. 열자마자 확인

| 확인 | 위치 | 기대값 |
|---|---|---|
| 색공간 | Edit → Project Settings → Player → Other Settings → **Color Space** | **Linear** (5주차 이유 설명) |
| 렌더 파이프라인 | Edit → Project Settings → Graphics | URP Asset 지정됨 |
| 기본 씬 | Project 창 `Assets/Scenes/SampleScene` | Hierarchy 에 Main Camera · Directional Light 등 (템플릿 버전마다 조금 다름) |

### 7-3. Git 저장소 만들기 · 첫 업로드

1. **`.gitignore` 먼저** — Unity 용 표준 파일 사용
   - https://github.com/github/gitignore 의 `Unity.gitignore` 내용을 복사 → 프로젝트 폴더 **최상위**(Assets 와 같은 위치)에 `.gitignore` 이름으로 저장
   - 위치가 틀리면 `Library/` (수 GB) 가 통째로 올라감
2. GitHub 에서 **New repository** → 이름 `PerceptionLab` · **README 추가하지 않기**(빈 저장소) · Public 또는 Private
   - Private 이면 과제 확인을 위해 교수 계정 초대 (PLATO 공지)
3. 터미널 :

```bash
cd C:/UnityProjects/PerceptionLab     # macOS : cd ~/UnityProjects/PerceptionLab
git init
git add .
git status                            # Library/ · Temp/ 가 목록에 없어야 정상
git commit -m "1주차: 빈 URP 프로젝트"
git branch -M main
git remote add origin https://github.com/내아이디/PerceptionLab.git
git push -u origin main
```

4. 확인 : GitHub 저장소 페이지에 `Assets` · `Packages` · `ProjectSettings` 세 폴더 · `Library` 는 **없어야 함**

> 습관 : **AI 에게 큰 수정을 맡기기 직전마다 커밋** · 망가지면 `git restore .` 또는 직전 커밋으로 복구

### 7-4. (선택) 큰 파일 — Git LFS

- GitHub 는 **100 MB 넘는 파일 업로드 거부**
- 고해상도 텍스처·영상·3D 에셋을 넣을 계획이면 **Git LFS** 사용 (https://git-lfs.com) — 필요해지면 그때 설정해도 됨
