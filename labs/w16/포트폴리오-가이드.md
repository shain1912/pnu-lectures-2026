# VR 팀 프로젝트 포트폴리오 가이드 — 16주차

- 목표 : 완성 사진 한 장이 아니라 **문제 → 결정 → 검증 → 결과** 가 보이는 케이스 스터디
- 재료 : 이미 가진 것 — 기획서 · 공간 스케치 · 플레이테스트 기록표 · 개선 기록표 · 15주 시연 녹화 · 16주 피드백 1장 요약
- 결과물 : 개인별 1부 (팀 작업이지만 **내 역할과 기여**를 명시)

**용어**

- 케이스 스터디 : 결과물과 함께 만드는 과정의 판단·검증을 보여 주는 포트폴리오 형식
- 헤드셋 녹화 : 체험자가 보는 화면(1인칭)을 헤드셋에서 녹화한 영상
- 외부 촬영 : 카메라로 체험자의 몸과 동작(3인칭)을 찍은 영상
- 캐스팅 : 헤드셋 화면을 휴대폰·PC 로 실시간 전송하는 기능 · 녹화도 가능
- 분할 화면 : 1인칭 · 3인칭 영상을 한 화면에 나란히 배치한 편집

## 1. 구성 7섹션

| # | 섹션 | 분량 | 재료 |
|---|---|---|---|
| 1 | 한 줄 정의 · 내 역할 | 3줄 | 기획서 ① · 역할 4종 |
| 2 | 시연 영상 | 60~90초 | 15주 캐스팅 녹화 + 16주 외부 촬영 |
| 3 | 설계 근거 | 표 1개 + 스케치 1장 | 기획서 ② 지각적 근거 · 공간 스케치 |
| 4 | 검증 결과 | 5~8줄 | 플레이테스트 기록 · SSQ 전후 · 관찰 인용 |
| 5 | 성능 수치 | 표 1개 | 예산표 vs 실측 · 개선 기록표 전후 |
| 6 | AI 활용과 함정 | 3~5줄 | 프롬프트 로그 · 해결한 함정 번호 |
| 7 | 회고 · 다음에 바꿀 것 | 3줄 | 16주 피드백 1장 요약 |

## 2. 시연 영상 촬영

### 두 대의 카메라

| | 헤드셋 녹화 (1인칭) | 외부 촬영 (3인칭) |
|---|---|---|
| 보여 주는 것 | 체험자가 본 것 | 체험자의 몸 · 손 동작 · 공간 |
| 방법 | 헤드셋 내장 녹화 · 캐스팅 화면 녹화 · Meta Quest Developer Hub (메뉴·단축키는 OS 버전마다 다름) | 휴대폰·카메라를 삼각대에 고정 · 가로 촬영 |
| 흔한 실패 | 머리를 빨리 돌려 어지러운 영상 · 녹화 중 프레임 저하 | 역광 · 손이 화면 밖 · 플레이 구역 잘림 |
| 대책 | 촬영용 체험자는 **천천히 · 목표를 오래 응시** · 녹화와 성능 측정은 **따로** | 창을 등지지 않게 · 구역 전체가 들어가는 거리 · 단순한 배경 |

### 촬영 체크리스트

- [ ] 촬영 체험자 = VR 에 익숙한 팀원 (천천히 움직이기 쉬움)
- [ ] 시작할 때 **손뼉 1회** → 두 영상을 소리·동작으로 시간 맞추기
- [ ] 헤드셋 배터리 · 저장 공간 확인
- [ ] 같은 장면을 2~3회 촬영 → 가장 매끄러운 것 사용
- [ ] 체험자 얼굴·목소리 공개 **동의** · 다른 학생이 배경에 찍히지 않게
- [ ] 녹화 영상은 한쪽 눈 기준으로 잘린 화면 → 자막으로 «헤드셋 녹화 화면» 표기

### 편집

- 길이 60~90초 · 첫 10초 안에 핵심 장면
- 분할 화면 (1인칭 크게 · 3인칭 작게) 또는 교차 편집
- 자막으로 **설계 근거 한 줄씩** (예 : «텔레포트 + 스냅 22.5° — 벡션 회피»)
- 끝 화면 : 실측 fps · 체험자 수 · 팀원과 역할

## 3. 문서화 항목

### 3-1. 설계 근거

- 기획서 ② 표를 그대로 옮기되 **14주 측정 결과로 갱신**
- 공간 스케치(평면도) 1장 — 실제 씬 스크린샷과 나란히

### 3-2. 검증 결과

- 체험자 수 · 과업 완료 비율 · SSQ 변화(직후 − 사전) 평균 · 중단자 수
- 관찰 인용 1~2개 (예 : «다음 어디?» 0:42)
- 한계 한 줄 : 표본 수 · SSQ 절단점 부재 · 설문의 한계

### 3-3. 성능 수치

| 항목 | 예산 | 개선 전 실측 | 개선 후 실측 | 측정 조건 |
|---|---|---|---|---|
| 평균 fps | 90 | | | Quest 3 · 배포 빌드 · OVR Metrics · 30초 |
| 드로우콜 | | | | Unity Profiler · Development Build |
| 삼각형 | | | | |
| 실시간 그림자 | | | | |

- 숫자에는 반드시 **측정 조건** (기기 · 빌드 종류 · 도구 · 시간)

### 3-4. AI 활용과 함정

- 사용한 AI 도구와 범위 (프롬프트 로그 제출 의무와 같은 기준)
- 해결한 함정 번호 · 증상 · 진단 방법 · 바꾼 명세 문장

### 3-5. 내 역할과 기여

- «팀으로 만들었다» 대신 «나는 ○○ 를 맡아 △△ 를 했다» · 산출물 이름 · 커밋·파일 근거

## 4. 문장 예시

| 흔한 문장 | 근거가 보이는 문장 |
|---|---|
| 몰입감 있는 숲 VR 을 만들었습니다 | 앉은 자세로 4분간 연못에 돌을 던지는 VR — 이동은 텔레포트와 22.5° 스냅 턴으로 제한 (벡션 회피) |
| 최적화로 부드럽게 만들었습니다 | URP 후처리를 끄고 그림자를 베이크해 Quest 3 실측 평균 61 → 88fps (배포 빌드 · OVR Metrics 30초) |
| 사용자들이 만족했습니다 | 다른 팀 체험자 4명 중 4명이 안내 없이 완료 · SSQ 증가폭 평균 +30 → +12 |
| 팀원들과 협업했습니다 | 나는 검증 담당 — 플레이테스트 진행 · 측정 · 개선 기록표 관리 |

**규칙** : 한 문장에 결정 · 이유 · 숫자 · 내 역할 중 최소 셋

## 5. 제출 전 점검

- [ ] 7섹션 모두 존재
- [ ] 영상 60~90초 · 1인칭 + 3인칭 · 공개 동의 확인
- [ ] 모든 숫자에 측정 조건
- [ ] 에디터 fps 를 성능 근거로 쓰지 않음
- [ ] 프레즌스·몰입감 주장은 관찰·수치로 뒷받침
- [ ] 에셋 출처·라이선스 표기
- [ ] 내 역할과 기여 명시
- [ ] 개인 AI 함정 체크리스트 첨부 (확인 질문 · 확인 위치)
