# Quest 빌드 가이드 — Windows 실습실 · macOS 노트북 (C4)

**컴퓨터그래픽스 (VF3500076) · 11주차 VR 실기 준비 · 조성호**

- 목표 : 지각 실험실 씬을 **Quest 3 에서 실행되는 앱(APK)** 으로 빌드해 헤드셋에 설치
- 기준 : **Unity 6 (6000.x) · URP · OpenXR · XR Interaction Toolkit 3.x · Quest 3**
- 수업 기본 경로 : **USB Build and Run** · 보조 : Meta Quest Developer Hub · 에디터 스트리밍(Link)은 **디버깅 전용**
- 10주차까지 1~5절 미리 진행 → 11주차 수업 시간에는 6절(빌드)부터
- **주의** : Unity·패키지·Meta 메뉴 이름은 버전마다 조금씩 다름 — «버전마다 다름» 표시 항목은 비슷한 이름 탐색

## 0. 용어 풀이

| 용어 | 쉬운 뜻 |
|---|---|
| APK | Android 앱 설치 파일 — Quest 는 Android 기반이라 Unity 가 APK 를 만듦 |
| Android Build Support | Unity 가 Android 용으로 빌드하게 해 주는 추가 모듈 |
| OpenJDK · SDK · NDK | Android 빌드에 필요한 도구 묶음 (Java 실행기 · Android 개발 도구 · C/C++ 컴파일러) |
| XR Plug-in Management | Unity 가 어떤 VR 기기 방식으로 실행할지 고르는 설정 창 |
| OpenXR | 여러 VR 기기를 같은 방식으로 다루는 업계 표준 규격 |
| IL2CPP | C# 코드를 C++ 로 바꿔 기기용으로 컴파일하는 방식 — Quest(ARM64) 필수 |
| ARM64 | Quest 칩의 명령어 체계 (휴대폰과 같은 계열) |
| adb | PC ↔ Quest 연결 도구 (`setup/Quest-운영-매뉴얼.md` 4절) |
| Build Profiles | Unity 6 에서 예전 «Build Settings» 창을 대체한 빌드 설정 창 |

## 2. Unity 6 + Android Build Support 설치

1. **Unity Hub** → Installs → 사용하는 Unity 6 버전의 **⚙ (톱니) → Add modules**
2. **Android Build Support** 체크 → 하위 항목 **OpenJDK** · **Android SDK & NDK Tools** 모두 체크
3. 라이선스 동의 → 설치 (수 GB · 10~30분)
4. 확인 : Unity 에디터 → **Edit → Preferences → External Tools** (macOS : Unity → Settings → External Tools)
   - JDK · Android SDK · NDK · Gradle 이 **«Installed with Unity (recommended)»** 체크 상태
   - 직접 설치한 다른 버전을 지정하면 호환 문제 → 체크 유지

> 실습실 PC : 10주차에 조교가 동일 버전 설치 확인 · 학생 노트북은 **수업과 같은 Unity 버전**(PLATO 공지) 사용

## 3. 플랫폼 전환 (Android)

1. **File → Build Profiles** (Unity 6 · 예전 이름 Build Settings)
2. 왼쪽 목록 **Android** 선택 → **Switch Platform**
   - Unity 6.1 이후 버전에는 **Meta Quest** 전용 프로필이 따로 보일 수 있음 (버전마다 다름) → 있으면 그것을 사용해도 무방
3. 첫 전환은 에셋 재임포트로 수 분 소요 — 이 시간 동안 다음 절 읽기
4. **Scene List** 에 실습 씬 추가 (Add Open Scenes) · 맨 위 씬이 시작 씬

## 4. XR 플러그인 — OpenXR (권장) 또는 Oculus

### 4-1. 패키지 설치 (Window → Package Manager)

| 패키지 | 용도 |
|---|---|
| **XR Plugin Management** | XR 설정 창 (보통 자동 포함) |
| **OpenXR Plugin** | OpenXR 실행 |
| **Unity OpenXR: Meta** (`com.unity.xr.meta-openxr`) | Quest 전용 기능 묶음 (Meta Quest feature group) |
| **XR Interaction Toolkit** 3.x + Starter Assets 샘플 | XR Origin · 광선 · 텔레포트 · UI 상호작용 (11주) |

- 대안 : Meta 의 **Meta XR Core SDK** (Asset Store / Meta 레지스트리) — Meta 전용 기능(패스스루 등)이 필요할 때 · 수업 기본은 위 Unity 패키지 조합

### 4-2. XR Plug-in Management 설정

1. **Edit → Project Settings → XR Plug-in Management**
2. **Android 탭 (로봇 아이콘)** 선택 — PC 탭이 아님
3. **OpenXR** 체크
   - 대안 경로 : **Oculus** 체크 (Oculus XR Plugin) — 구형 방식 · 두 개 동시 체크 금지
4. **OpenXR** 하위 항목 → Android 탭
   - **OpenXR Feature Groups** : **Meta Quest** (또는 Meta Quest Support 기능) 체크 — 이름 버전마다 다름
   - **Enabled Interaction Profiles** : **+** → **Oculus Touch Controller Profile** · Quest 3 는 **Meta Quest Touch Plus Controller Profile** 도 추가
5. **Project Validation** (XR Plug-in Management 아래) → 빨간·노란 항목 **Fix All**
   - 6절의 Player 설정 일부를 자동으로 맞춰 줌 · 남은 항목은 하나씩 읽고 Fix

> 확인 습관 : 빌드 전 Project Validation 에 **빨간 항목 0개**

## 5. URP · Player 설정

### 5-1. URP (Quest 성능 기준선 : 90 Hz = 11.1 ms)

Unity 6 Universal 3D 템플릿은 **PC 용 · Mobile 용** 렌더 파이프라인 에셋 두 벌 포함

1. **Project Settings → Quality** → Android 열(아래쪽 초록 체크)의 기본 품질 = **Mobile** 계열
2. 그 품질 레벨의 **Render Pipeline Asset** (예 : `Mobile_RPAsset`) 선택 후 확인

| 항목 | 권장 | 이유 |
|---|---|---|
| HDR | 끔 | 모바일 GPU 대역폭 절약 |
| Anti Aliasing (MSAA) | **4x** | VR 계단 현상 완화 · 타일 GPU 에서 비교적 저렴 |
| Render Scale | 1.0 | 낮추면 흐려짐 · 성능 문제일 때만 조정 |
| SRP Batcher | 켬 | 드로우콜 비용 절감 (12주) |
| Post-processing | 끔 (필요한 것만) | 두 눈 × 전체 화면 비용 |
| Shadows | Directional 1개 · 거리 짧게 | 5주 함정 #4 |
| Color Space (Player) | **Linear** | 5주 |

### 5-2. Player 설정 (Project Settings → Player → Android 탭)

| 위치 | 항목 | 값 |
|---|---|---|
| Other Settings | **Minimum API Level** | Android 10 (API 29) 이상 — **Project Validation 이 권하는 값 우선** (패키지 버전에 따라 32 등 상향 · 버전마다 다름) |
| Other Settings | Target API Level | Automatic (highest installed) |
| Other Settings | **Scripting Backend** | **IL2CPP** |
| Other Settings | **Target Architectures** | **ARM64 만** 체크 (ARMv7 해제) |
| Other Settings | Graphics APIs | **Vulkan** 권장 (Auto Graphics API 해제 후 Vulkan 위) · 문제 시 OpenGLES3 |
| Other Settings | Active Input Handling | Input System Package (New) — 10주 |
| Other Settings | Package Name | `com.본인영문이름.cglab` — 학생마다 다르게 (설치 충돌 방지) |
| Other Settings | Color Space | Linear |
| Resolution and Presentation | Default Orientation | Landscape Left (Validation 이 맞춰 줌) |
| Publishing Settings | Keystore | 비워 둠 (개발용 기본 서명 사용) |

## 6. Build and Run (USB) — 수업 기본 경로

1. 헤드셋 : 개발자 모드 켬 · 데이터 케이블 연결 · **USB 디버깅 «항상 허용»** (`Quest-운영-매뉴얼.md` 3~4절)
2. PC 에서 연결 확인

```bash
# Windows (Unity 6000.x 기본 설치 위치 · 버전 폴더명은 각자 다름)
"C:\Program Files\Unity\Hub\Editor\6000.x.xf1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe" devices

# macOS
/Applications/Unity/Hub/Editor/6000.x.xf1/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb devices
```

3. **File → Build Profiles → Android**
   - **Run Device** : 목록에서 Quest 선택 (안 보이면 Refresh · 그래도 없으면 10절 FAQ 1·2)
   - **Development Build** : 체크 권장 (로그 확인 · 단, 성능 측정 시에는 해제)
4. **Build And Run** → APK 저장 위치 지정 (프로젝트 밖 `Builds/` 폴더 · 영문 경로)
5. 첫 빌드 : IL2CPP 컴파일로 **5~15분** · 이후 증분 빌드 **약 3~6분**
6. 완료되면 헤드셋에서 앱 자동 실행
7. 다시 실행 : 헤드셋 **라이브러리 → 알 수 없는 출처 (Unknown Sources)** 에서 앱 선택 (버전마다 다름 — 라이브러리 필터 메뉴 안에 있을 수 있음)

### 빌드 직후 확인 (지각 실험실 기준)

- [ ] 바닥 높이가 실제 바닥과 일치 (XR Origin Tracking Origin = Floor · 11주)
- [ ] 1 unit = 1 m — 1 m 큐브가 실제 1 m 로 보이는가
- [ ] 10주 UI : Overlay 버전 소실 · World Space 버전 1.5 m 에 보임
- [ ] 프레임 끊김 없음 (OVR Metrics Tool 측정은 12주)

## 7. Windows 실습실 · macOS 노트북 분기 요약

### Windows 실습실

1. (조교 사전) Unity 동일 버전 · Android 모듈 · **Oculus ADB Drivers** 설치
2. 프로젝트를 **`C:\Unity\학번_CGLab`** 처럼 영문 경로로 복사 (바탕화면·`문서` 폴더 아래 한글 경로 피함)
3. Windows 사용자 이름이 한글이면 Gradle 캐시 경로 오류 가능 → FAQ 4
4. 실습실 PC 는 재부팅 시 초기화될 수 있음 → **프로젝트는 개인 저장장치 · Git 에 보관**

### macOS 노트북

1. Unity Hub → Android Build Support (OpenJDK · SDK & NDK) 설치 — 드라이버 설치 없음
2. 케이블 연결 시 «액세서리 연결 허용» 창 → 허용 (macOS 버전마다 다름)
3. USB-C 허브 경유 시 인식 불안정 → **본체 포트 직결**
4. Quest Link 미지원 → 에디터 Play 로 헤드셋 미리보기 불가 → 매번 Build and Run (또는 Meta XR Simulator 로 헤드셋 없이 동작 확인 — 선택)
5. 처음 빌드 시 «개발자를 확인할 수 없음» 경고가 adb·도구에 뜨면 시스템 설정 → 개인정보 보호 및 보안 → 허용 (버전마다 다름)

## 8. 보조 경로

### 8-1. Meta Quest Developer Hub (MQDH) — Windows · macOS

- Meta 개발자 사이트에서 설치 → Meta 계정 로그인 → 헤드셋 연결 → **Device Manager** 에 기기 표시
- **APK 드래그 앤 드롭**으로 설치 (Build 만 하고 Run 은 MQDH 로) — 소요 2~4분
- 기타 : 헤드셋 화면 캐스트 (발표·스포터 화면 공유) · 로그(Logcat) · **ADB over Wi-Fi** 토글 · 성능 지표
- Unity 의 Run Device 에 Quest 가 안 보일 때 MQDH 로 원인 확인 (권한·드라이버 상태)

### 8-2. 무선 설치

- `Quest-운영-매뉴얼.md` 5절 (adb tcpip · MQDH ADB over Wi-Fi) · 학교망 차단 가능성

### 8-3. 에디터 Play 스트리밍 (Quest Link) — 디버깅 전용

- **Windows 만** · Meta Quest Link 앱 + USB(Link 케이블) 또는 Air Link
- XR Plug-in Management **PC 탭(Windows)** 에도 OpenXR 체크 · Meta Quest feature group 활성 → 에디터 Play 시 헤드셋에 표시
- **PC GPU 로 렌더** → 프레임·발열·성능은 실제 Quest 와 다름 → **성능 판정에 사용 금지** (14주 함정 #10 «에디터 기준 최적화»)
- 이름 주의 : Unity 의 «Play to Device» 기능은 **visionOS(Apple Vision Pro)용** · Quest 에서는 위의 Link 방식이 그 역할

## 10. 흔한 오류와 해결 (FAQ)

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | Run Device 목록에 Quest 없음 | 개발자 모드 꺼짐 · 충전 전용 케이블 · ADB 드라이버 미설치(Windows) · USB 디버깅 미허용 | 순서대로 확인 → 헤드셋 재시작 → 다른 포트 · 케이블 교체 → `adb devices` |
| 2 | `adb devices` 에 `unauthorized` | 헤드셋 안의 허용 창을 아무도 누르지 않음 | 헤드셋 착용 → «항상 허용» 체크 → OK · 창이 안 뜨면 케이블 재연결 · 개발자 설정의 USB 디버깅 권한 취소(있으면) 후 재연결 |
| 3 | «Android SDK / JDK not found» | Android 모듈 일부 미설치 · External Tools 경로 변경 | Unity Hub → Add modules → OpenJDK · SDK & NDK 체크 재설치 · External Tools «Installed with Unity» 체크 |
| 4 | `Gradle build failed` (특히 Windows) | 프로젝트·사용자 경로의 **한글·공백** · 디스크 부족 · 백신 실시간 검사 | 영문 경로로 프로젝트 이동 · 디스크 15 GB 확보 · 한글 사용자명이면 환경 변수 `GRADLE_USER_HOME=C:\gradle` 지정 후 Unity 재시작 · 콘솔의 **첫 번째** 빨간 오류부터 읽기 |
| 5 | 앱은 실행되는데 **허공에 2D 창**으로 뜸 | XR Plug-in Management 의 **Android 탭**에 OpenXR 미체크 (PC 탭만 체크) | Android 탭 → OpenXR + Meta Quest feature group 체크 → 재빌드 |
| 6 | 검은 화면 · 즉시 종료 | Feature group 누락 · Graphics API 문제 · 시작 씬 없음 | Project Validation Fix All · Vulkan ↔ OpenGLES3 전환 시험 · Scene List 맨 위 씬 확인 · Development Build + Logcat(MQDH) 로 오류 확인 |
| 7 | 컨트롤러가 안 보이거나 입력 무반응 | Interaction Profile 미추가 · XR Origin 의 컨트롤러 액션 미연결 | Oculus Touch / Meta Quest Touch Plus Controller Profile 추가 · XRI Starter Assets 의 Input Action Manager 존재 확인 (11주) |
| 8 | UI 가 안 보임 · 눈앞에 붙음 · 광선이 통과 | **AI 함정 #7** — Overlay · Camera 모드 · 레이캐스터 | World Space · Scale 0.001 · Tracked Device Graphic Raycaster · XR UI Input Module (10주 슬라이드) |
| 9 | `INSTALL_FAILED_UPDATE_INCOMPATIBLE` · 설치 실패 | 같은 패키지 이름의 다른 서명 앱이 이미 설치 (다른 학생·다른 PC 빌드) | `adb uninstall com.본인.cglab` 후 재설치 · 패키지 이름을 학생마다 다르게 |
| 10 | 빌드 설정 오류 «ARMv7 / IL2CPP 필요» · 스토어 규격 경고 | Scripting Backend Mono · ARMv7 체크 | IL2CPP · ARM64 만 · Minimum API Level 은 Validation 권장값 |
| 11 | 첫 빌드가 20분 이상 | IL2CPP 전체 컴파일 · 셰이더 변형 컴파일 | 정상 범위일 수 있음 · 두 번째부터 증분 · 백신 예외 폴더에 프로젝트 추가 (실습실은 전산 확인) |
| 12 | 프레임 끊김 · 발열 | URP PC 에셋 사용 · 실시간 그림자 다수 · 포스트 프로세싱 | Quality Android 기본 = Mobile · 5-1절 표 적용 · 12주 프로파일링 |
