셰이더의 두 공정

① 정점 셰이더 — 자리 잡기

입력 : 꼭짓점 위치 · 법선 · UV
하는 일 : 모델 → 뷰 → 투영 변환 (4주차)
출력 : 화면 위치 + 다음 공정에 넘길 값 (UV · 법선 등)

② 프래그먼트 셰이더 — 색칠

입력 : 보간된 UV · 법선
하는 일 : 텍스처 읽기 · 조명 계산 (5주차)
출력 : 그 픽셀의 최종 색 + 투명도

사이 단계 : 래스터화 (4주차) — 삼각형이 덮는 픽셀 찾기 → 픽셀마다 꼭짓점 값을 섞어 전달

가구 공장 : 1공정 = 부품 꼭짓점에 위치 표시 (몇 개 안 됨) · 2공정 = 표면을 한 칸씩 도색 (칸 수가 엄청 많음) → 비싼 작업은 칸 수가 많은 2공정

비유의 한계 : 실제로는 두 공정 모두 수천 개 코어에서 동시에 병렬 실행

- 4주차 파이프라인 그림을 다시 띄우고 "셰이더 = 이 중 프로그래밍 가능한 두 칸" - 5주차 Lambert 계산이 바로 ② 프래그먼트 셰이더 안에서 돌던 코드

보간 — 세 꼭짓점 값을 섞어 안쪽 채우기

무게중심 좌표Barycentric coord.
삼각형 안의 한 점이 세 꼭짓점에 각각 얼마나 가까운지를 합이 1 인 비율 세 개 (w₁, w₂, w₃) 로 표현
\[ v = w_1 v_1 + w_2 v_2 + w_3 v_3 \qquad (w_1 + w_2 + w_3 = 1) \]

손계산 : 비율 (0.5, 0.3, 0.2)
꼭짓점 색 빨강 (1,0,0) · 초록 (0,1,0) · 파랑 (0,0,1)
→ 색 = (0.5, 0.3, 0.2) 붉은 갈색

같은 점의 UV : 꼭짓점 UV (0,0) · (1,0) · (0,1)
→ 0.5·(0,0) + 0.3·(1,0) + 0.2·(0,1) = (0.3, 0.2)
→ 텍스처의 이 주소를 읽음

세 가지 물감을 짠 팔레트 : 빨강 물감 쪽에 가까운 자리일수록 빨강이 많이 섞임 · 삼각형 안 모든 점 = 세 물감을 거리 비율대로 섞은 색

- 핵심 : UV 도 색과 똑같이 보간된다 → 그래서 텍스처가 삼각형 안에서 매끄럽게 펼쳐짐 - 원근 보정 보간(perspective-correct)은 GPU 가 자동 처리 — 이름만 언급

UV — 표면의 점마다 붙은 그림 주소

U = 가로 · V = 세로 · 둘 다 0 ~ 1 (그림 크기와 무관)
Unity : 왼쪽 아래 (0,0) · 오른쪽 위 (1,1)

\[ \text{텍셀} = (u \times \text{가로},\ v \times \text{세로}) \]

손계산 : 1024 × 1024 텍스처 · UV (0.25, 0.75)
→ 텍셀 (256, 768) · 512 로 바꿔도 UV 는 그대로 → (128, 384)

상자 전개도 : 과자 상자를 펼친 종이에 인쇄 → 접으면 입체 · UV = 입체의 각 점이 펼친 종이의 어디에 해당하는지 적은 표

비유의 한계 : 곡면(얼굴·구)은 종이처럼 찢지 않고 펼 수 없음 → 늘어남·이음매 발생 (다음 장)

0~1 비율 주소의 장점 : 텍스처 해상도를 바꿔도 모델 수정 불필요 → 밉맵(축소판)이 같은 UV 로 동작하는 이유

확대Magnification

Bilinear : 주변 텍셀 4개를 거리 비율로 섞음 → 매끄러움

손계산 — 텍셀 4개 : 왼위 0 · 오위 1 · 왼아래 1 · 오아래 1
샘플 위치 : 왼쪽에서 0.25 · 위에서 0.4 지점

위 줄 : \(0 + 0.25 \times (1-0) = 0.25\)
아래 줄 : \(1\)
세로 섞기 : \(0.25 + 0.4 \times (1 - 0.25) = \mathbf{0.55}\)

주파수Frequency

LODLevel of Detail

\[ \text{LOD} = \log_2\left(\text{픽셀 하나가 덮는 텍셀 수 (한 변 기준)}\right) \]

Trilinear — 레벨 사이의 계단 없애기

문제 : LOD 는 2.3 처럼 소수로 나옴 → 반올림해 한 레벨만 쓰면 바닥에 흐림이 갑자기 바뀌는 띠 발생 (밉맵 경계선)

눈의 한계 — 왜 60 PPD 인가

시력 1.0 (20/20) = 시야 1/60° 크기 디테일 구분
→ 줄무늬로 치면 30 사이클/도

나이퀴스트 (Part I) : 한 주기에 픽셀 2개
→ 30 사이클 × 2 = 60 PPD 필요

\[ \text{PPD}_{\text{필요}} = 2 \times 30 = 60 \]

손계산 — Quest 3 약 25 PPD 가 보여 줄 수 있는 최대 디테일
25 ÷ 2 = 12.5 사이클/도 → 눈 한계 30 의 약 42%
→ 시력표로 환산하면 약 20/48 (시력 약 0.4) 수준의 세상

최근 측정 (2025) : 집단 평균 약 94 PPD · 개인 최대 120 PPD → 60 PPD 는 «충분» 이 아닌 하한에 가까움

PPD 손계산 — 모니터 vs 헤드셋

모니터 : 27″ QHD (가로 2560 픽셀, 폭 약 59.8 cm) · 눈에서 60 cm

픽셀 하나 폭 = 59.8 ÷ 2560 ≈ 0.023 cm
60 cm 에서 시야 1° 의 폭 = \(60 \times \tan 1° \approx 1.05\) cm
PPD = 1.05 ÷ 0.023 ≈ 약 45
