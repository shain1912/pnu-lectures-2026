사용자 중심 설계 — 4단계 반복

설계 · 2

VR 에서 사용자 중심이 특히 중요한 이유

  • 만든 사람 = 가장 둔감한 체험자 → 수십 번 반복 체험으로 적응 · 동선을 이미 앎 → 처음 쓰는 사람의 멀미·막힘을 못 느낌
  • 몸이 사람마다 다름 → 키 · 팔 길이 · 앉음/섬 · 안경 착용 → 내 몸에 맞춘 높이가 남에게는 닿지 않음
  • 멀미 감수성의 개인차 → 현세대 HMD 사용자 최소 1/3 이 증상 경험 · 연구 참가자 중도 포기 평균 15.6% (Souchet et al. 2023)

맞춤 정장의 가봉 : 재단사는 원단을 자르기 전에 시침질로 대충 꿰매 손님에게 입혀 봄 → 어깨·소매 길이를 그 자리에서 수정 · 완성 후 고치면 원단을 버려야 함

→ 페이퍼 프로토타입 = VR 의 가봉 · 손님(체험자)의 몸에 먼저 대 보기

출처 : Souchet, Lourdeaux, Pagani & Rebenitsch (2023) Virtual Reality — 실증 연구 44편 집계

설계 · 4

VR 필요성 테스트 — «모니터로 만들어도 같은가?»

질문«예» 가 나와야 VR 다운 기획
① 몸의 크기·거리 감각이 경험의 핵심인가실물 크기 공룡 앞에 서기 · 좁은 방의 압박감
② 머리·손의 실제 움직임이 주된 입력인가고개를 숙여 들여다보기 · 손으로 집어 돌려 보기
③ 둘러싸임이 의미를 바꾸는가사방에서 오는 소리 · 뒤를 돌아봐야 보이는 단서

세 질문 모두 «아니오» → 화면 안 게임·영상이 더 나은 매체 → 교수 반려 대상
예 : 메뉴 버튼 누르기 위주 퀴즈 · 정면 화면에 영상만 재생 · 키보드로 하던 조작을 컨트롤러로 옮긴 것

근거 : 몰입형 VR 학습 효과 전체 g ≈ 0.38 (작은 효과, Coban et al. 2022) · 몰입이 높아도 인지 부하가 커지면 학습 저하 (Makransky et al. 2019) → «VR 이면 자동으로 좋아짐» 은 성립하지 않음

- g : 두 집단 평균 차이를 표준편차 단위로 잰 효과 크기 · 0.2 작음 · 0.5 중간 · 0.8 큼 정도로 읽음 - 반려는 아이디어를 버리라는 뜻이 아니라 «VR 이 꼭 필요한 한 장면» 을 찾으라는 뜻

공간 스케치 — 1 m 격자 위에 그리기

- 칠판에 1 m 격자를 그리고 같은 그림을 직접 그려 보임 - 빨간 상자 : 학생 기획에서 가장 흔한 실수 (등 뒤에 중요한 물체) - 측면도 : 선 사람 눈높이 약 1.6 m · 앉은 사람 약 1.2 m 를 둘 다 그림 → 앉아서도 되는지 확인

바디스토밍 — 몸으로 리허설

  1. 바닥에 마스킹 테이프로 2 m × 2 m 구역 표시
  2. 의자·상자·종이컵으로 가상 물체의 대역 배치 (평면도 치수 그대로)
  3. 역할 셋 : 체험자 (눈 가리지 않음) · 시스템 역 (화면 변화를 말로 알려 줌 · «문이 열립니다») · 관찰자 (기록)
  4. 시나리오를 처음부터 끝까지 실제 속도로 연기 · 3~5분 시간 재기

연극의 블로킹 리허설 : 대사·조명 없이 배우가 무대 위에서 «어디에 서고 어디로 걷는지» 만 맞춰 봄 → 부딪힘·가림을 무대 세트 짓기 전에 해결

스케일 검수 체크리스트

  • 1 unit = 1 m : 씬에 1 m 기준 큐브 하나를 두고 모든 물체와 비교
  • 친숙한 크기 물체 : 문 높이 약 2.1 m · 의자 좌판 약 0.45 m · 책상 약 0.75 m → 뇌의 크기 기준 역할 → 늘리거나 줄이지 않음
  • 임포트 스케일 : 외부 모델이 cm 단위로 만들어졌으면 100배 크기로 들어옴 → Model Import Settings 의 Scale Factor 확인
  • 눈높이 : XR Origin 의 Tracking Origin Mode = Floor → 실제 키가 그대로 반영 · AI 코드가 카메라 높이를 1.8 같은 숫자로 고정했는지 확인 (함정 #8 연결)
  • 헤드셋에서 확인 : 에디터 화면으로는 크기 판단 불가 → 기준 큐브 옆에 서서 무릎·허리 높이와 대조

[목표]
팀 프로젝트의 그레이박스 씬을 만든다. 평면도(첨부 사진)의 배치를 그대로 옮긴다.

[제약]
- Unity 6 · URP · XR Interaction Toolkit 3.x · XR Origin (XR Rig) 사용
- 1 unit = 1 m · 모든 물체는 회색 기본 머티리얼의 큐브/실린더로 대체
- Tracking Origin Mode = Floor · 카메라 높이를 코드로 고정하지 않음
- 이동은 텔레포트 + 스냅 턴 22.5° 만 · 연속 이동·가속 없음
- 실시간 그림자 0개

[검증 조건]
- 1 m 기준 큐브와 문(높이 2.1 m)이 씬에 존재
- 시작 위치에서 핵심 물체가 정면 ±30° 안에 보임
- Quest 3 빌드에서 Stats 대신 헤드셋 실측으로 fps 기록

[비목표]
- 텍스처 · 조명 연출 · 사운드 · 최종 에셋

측정 — 스켈레톤이 맞게 섰는지

// 씬 시작 시 눈높이와 정면 각도 확인 (헤드셋에서 로그 확인)
void Start() {
    var cam = Camera.main.transform;
    Debug.Log($"눈높이 {cam.position.y:F2} m");          // 앉음 약 1.2 · 섬 약 1.6

    Vector3 toTarget = (target.position - cam.position);
    toTarget.y = 0;                                        // 수평 각도만
    Vector3 fwd = cam.forward; fwd.y = 0;
    Debug.Log($"핵심 물체 각도 {Vector3.Angle(fwd, toTarget):F0}°"); // 30 이하
}

판정 : 눈높이가 매번 체험자 키에 따라 달라지면 정상 (Floor 모드) · 항상 같은 숫자면 카메라 높이 고정 의심 → 함정 #8
