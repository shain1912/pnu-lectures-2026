> 한 줄 요약 : **AI 사용은 허용 · 권장. 대신 무엇을 요구했고 어떻게 확인했는지 기록 의무.**

## 1. 이 정책의 이유

- 이 수업의 실습 = **개념 → 명세 → 검증** 루프 · 코드 작성은 AI, 요구와 판별은 학생
- 그래서 채점 대상 = 결과물 + **요구(프롬프트 명세)** + **판별(검증 리포트)**
- 기록이 없으면 → 무엇을 이해했는지 증명할 방법이 없음 → 결과물만 남고 점수의 절반이 사라짐
- 비유 : 요리 경연에서 사 온 소스를 써도 됨 · 단, 재료 영수증 첨부 → 심사는 소스가 아니라 **고르고 조합한 판단**에 대해

## 3. 의무 기록

### 3-1. 무엇을 기록하나

- 제출물에 영향을 준 **모든 의미 있는 AI 요청** → 프롬프트 로그 1건씩
- 사소한 요청(오타 수정, 단순 문법 질문)은 생략 가능 · 판단이 애매하면 기록
- **실패한 요청도 기록** — 틀린 결과를 어떻게 발견했는지가 가장 높은 점수를 받는 부분

### 3-2. 제출물별 기록 요구

| 제출물 | 프롬프트 로그 | 검증 리포트 | 비고 |
|---|---|---|---|
| 실습과제 | 핵심 요청 **최소 1건** (과제별 공지) | 필수 | 실습과제 30% 중 명세 30 · 검증 30 |
| 중간 프로젝트 (8주) | **전문** (첫 요청부터 최종까지) | 필수 · 측정값 포함 | 로그 자체가 20점 |
| 기말 팀 프로젝트 (15주) | 팀 로그 + 개인별 기여 표시 | 필수 | 프롬프트 플레이북(9주) 첨부 |

### 3-3. 결과물 표기

- 결과물(README 또는 보고서 첫 장)에 **AI 사용 요약** 3줄 :
  1. 사용한 도구 · 모델
  2. AI 가 만든 부분 / 내가 직접 수정한 부분
  3. 프롬프트 로그 파일 위치

## 4. 프롬프트 로그 양식

### 4-1. 항목 정의

| 항목 | 쓰는 법 | 예 |
|---|---|---|
| **날짜** | 요청한 날짜 · 시각(선택) | 2026-09-10 16:12 |
| **도구** | 사용한 프로그램 이름 | OpenCode / 웹 채팅 / VS Code 확장 |
| **모델** | 도구 안에서 선택된 AI 모델 이름 · 모르면 도구 설정 화면 확인 | 모델 이름 그대로 (예 : ○○-4.5) |
| **프롬프트 원문** | 보낸 문장 **그대로 복사** · 붙여 넣은 파일·로그는 «[Hierarchy 목록 첨부]» 처럼 표시 | 아래 예시 |
| **결과 요약** | AI 가 무엇을 내놓았는지 2~3줄 · 생성·수정한 파일 이름 | `Spin.cs` 생성 · eulerAngles 누적 방식 |
| **검증** | **어떻게 확인했고 결과가 어땠나** · 측정값·스크린샷 번호 | 30fps·120fps 10초 후 각도 비교 → 312° vs 318° · 불일치 |
| **수정 이유** | 다음 요청을 어떻게 바꿨고 **왜** — 어떤 개념 때문인지 | deltaTime 누락 → 프레임 독립성 위반 → 제약에 명시 |

- **검증**과 **수정 이유**가 채점의 핵심 · «잘 됨», «안 됨» 만 적으면 점수 없음
- 같은 대화 안의 연속 요청 → 번호를 이어 붙여 한 파일에 기록

### 4-2. 복사해서 쓰는 양식 (Markdown)

```markdown
## 로그 #01

- 날짜 : 2026-MM-DD HH:MM
- 도구 :
- 모델 :

### 프롬프트 원문
(보낸 문장 그대로 · 첨부한 자료는 [ ] 로 표시)

### 결과 요약
-

### 검증
- 확인 방법 :
- 결과 (수치·스크린샷 번호) :
- 판정 : 통과 / 실패 / 부분 통과

### 수정 이유
- 문제 :
- 원인이 된 개념 :
- 다음 요청에서 바꾼 점 :
```

### 4-3. 작성 예시

```markdown
## 로그 #02

- 날짜 : 2026-09-17 16:20
- 도구 : OpenCode (터미널)
- 모델 : (도구 설정 화면에 표시된 이름)

### 프롬프트 원문
[목표] 큐브를 월드 Y축 기준으로 초당 45° 등속 회전시킨다.
[제약] eulerAngles 누적 금지 · Quaternion 으로 누적 · Time.deltaTime 사용
[검증 조건] 30fps 와 120fps 에서 10초 뒤 각도 차이 1° 이하
[비목표] 입력 처리, UI

### 결과 요약
- Spin.cs 생성 · transform.rotation = Quaternion.AngleAxis(45 * Time.deltaTime, Vector3.up) * transform.rotation

### 검증
- 확인 방법 : Application.targetFrameRate 를 30 · 120 으로 바꿔 10초 후 각도 Debug.Log
- 결과 : 30fps → 90.2° · 120fps → 90.0° (스크린샷 2-1, 2-2)
- 판정 : 통과

### 수정 이유
- 로그 #01 에서는 «부드럽게 회전» 으로만 요청 → eulerAngles 누적 코드 → 짐벌락 재현
- 원인 개념 : 오일러각의 축 겹침 · 프레임 독립성
- 바꾼 점 : 회전 표현(Quaternion)과 시간 기준(deltaTime)을 제약에 명시
```

### 4-4. 제출 형식

- 파일 : `prompt-log.md` (Markdown) · 프로젝트 저장소 루트 또는 `docs/` 폴더
- 스크린샷 : `docs/img/` 에 번호 붙여 저장 · 로그에서 번호로 참조
- 대화 전체 내보내기(공유 링크·텍스트 파일)가 가능하면 **추가 첨부 권장** · 로그 양식을 대신하지는 못함

## 5. 금지 사항

| 금지 행위 | 이유 |
|---|---|
| **로그 사후 위조** — 실제로 보내지 않은 프롬프트를 나중에 지어내 작성 | 검증 과정 자체를 꾸며 낸 것 → 평가 불가 |
| **타인 로그·결과물 복사** (다른 학생 · 이전 학기 · 인터넷) | 표절 |
| 구술 방어 · 크리틱 발표 · 동료 평가에서 AI 사용 | 본인 이해를 확인하는 자리 |
| 이해하지 못한 코드를 «내가 설계했다» 고 주장 | 구술 방어에서 확인 · 설명 못 하면 해당 부분 감점 |
| 개인정보 입력 — 본인·타인의 학번·연락처·얼굴 사진, 동료 평가 내용 | 외부 서비스로 전송됨 |
| 저작권 있는 자료 무단 입력 — 유료 에셋 원본, 타 강의 자료, 교재 전문 | 라이선스 위반 가능 |
| 계정 공유로 유료 AI 도구 사용 | 서비스 약관 위반 |

## 7. 자주 묻는 질문

**Q. AI 가 거의 다 짰는데 점수가 깎이나요?**
- 아니요. 깎이는 경우 = 요구가 모호했거나, 결과를 확인하지 않았거나, 기록이 없을 때

**Q. AI 가 틀린 답을 줬고 결국 못 고쳤어요.**
- 틀린 지점을 어떻게 발견했고 어디까지 원인을 좁혔는지 기록하면 검증 점수 인정 · 실패 기록도 평가 대상

**Q. 도구마다 모델이 여러 개라 이름을 모르겠어요.**
- 도구 설정·모델 선택 메뉴에 표시된 이름 그대로 · 끝까지 모르면 «확인 불가» 로 적고 도구 이름과 요금제 기재

**Q. 대화가 너무 길어서 원문 복사가 어려워요.**
- 결과에 영향을 준 요청만 원문으로 · 나머지는 «중간 요청 5건 : 오류 메시지 해석» 처럼 요약 가능 (중간 프로젝트는 전문 원칙)
