# 개선 기록표 — 14주차 (16주 보완까지 계속 사용)

- 팀당 1부 · 검증 담당이 관리 · 14주 제출 시 최소 2행 + 재측정
- 흐름 : **문제 → 원인 → 조치 → 재측정**
- 15주 발표 «개선 전후 수치» · 16주 포트폴리오 «성능 수치 · 검증 결과» 의 원본

---

## 쓰는 규칙

1. **문제** = 관찰 또는 수치 · «별로였다» 금지 → «체험자 3명 중 2명 20초 이상 탐색», «평균 61fps»
2. **원인** = 근거와 함께 · 성능 문제는 먼저 **병목 판정** (CPU 인가 GPU 인가)
3. **조치** = 한 행에 **하나만** → 여러 개를 동시에 바꾸면 무엇이 효과였는지 분리 불가
4. **재측정** = 같은 조건 (같은 빌드 종류 · 같은 경로 · 같은 시간 길이) · **단위 있는 숫자** · 나빠진 결과도 그대로
5. 성능 수치는 **헤드셋 실측만** (OVR Metrics Tool · 헤드셋에 연결한 Unity Profiler) · 에디터 수치 불인정 (AI 함정 #10)

**비유** : 국 간 맞추기 — 소금·간장·마늘을 한꺼번에 넣으면 무엇 때문에 맛이 변했는지 모름 → 하나 넣고 맛보고, 또 하나 넣고 맛보기
