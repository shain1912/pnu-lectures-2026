# 컴퓨터그래픽스 학기 용어집

**컴퓨터그래픽스 (VF3500076) · 디자인앤테크놀로지전공 · 조성호 · 2026-2**

- 수록 범위 : 1~16주 슬라이드의 용어 풀이(`dl.terms`)와 «용어 미리보기» 전체 — 슬라이드에서 자동 생성
- 항목 구성 : **뜻** (쉬운 말) · **예** (구체적 숫자·장면) · **왜** (모르면 무엇이 틀어지나) · **어디서** (Unity·Quest 에서 보이는 곳)
- 같은 용어를 여러 주에서 풀이한 경우 → 가장 자세한 풀이 채택 · **첫 등장** / **다시 나온 주** 표기
- 쓰는 법 : 프롬프트에 넣을 정확한 용어를 고를 때 · AI 답변에 모르는 말이 나왔을 때 먼저 찾기

> 용어를 모르면 프롬프트를 쓸 수 없고, 결과를 검수할 수 없음 — 이 수업의 명제

## ㄱ

### 가디언

**가디언** · *Guardian · Boundary* — 11주

- **뜻** : 헤드셋에 «여기까지가 안전한 바닥» 을 알려 주는 가상 울타리
- **예** : 2 m × 2 m 사각형 · 손이나 머리가 경계에 가까워지면 격자 벽이 나타남
- **왜** : 몰입하면 실제 책상·벽이 안 보임 → 충돌·넘어짐 방지의 1차 장치
- **어디서** : Quest 설정 → 경계(Boundary) · 최신 OS 에서는 «물리적 공간» 메뉴 (버전마다 이름 다름)

### 가속도계

**가속도계** · *Accelerometer* — 11주

- **뜻** : 속도가 얼마나 빨리 바뀌는지(가속도)를 재는 센서 · 단위 m/s² · 가만히 있어도 중력 9.8 m/s² 이 잡힘
- **예** : 책상 위 정지 : 아래쪽 9.8 · 엘리베이터가 올라가기 시작하는 순간 : 잠깐 더 큰 값
- **왜** : 중력 방향 = «어느 쪽이 아래인가» → 기울기의 절대 기준 · 좌우 회전(yaw)은 모름

### 가중치

**가중치** · *Skin weight* — 7주

- **뜻** : 정점 하나가 각 뼈를 «몇 % 따라갈지» 적어 둔 숫자 · 합은 항상 100%
- **예** : 팔꿈치 정점 = 위팔 0.5 + 아래팔 0.5 · 손등 정점 = 손 1.0
- **왜** : 잘못 칠하면 팔을 들 때 옆구리 살이 같이 끌려 올라감
- **어디서** : Blender Weight Paint 모드에서 칠함 · Unity 는 Quality → Skin Weights 로 정점당 뼈 수 제한

### 각크기

**각크기** · *Angular size* — 10주

- **뜻** : 물체가 눈에서 차지하는 각도(°) — 실제 크기와 거리를 함께 반영한 «보이는 크기»
- **예** : 폭 0.6 m 패널 · 1.5 m → 약 22.6° · 같은 패널 3 m → 약 11.4°
- **왜** : «0.6 m» 만 적으면 거리에 따라 크게도 작게도 보임 → 명세에 각도를 함께
- **어디서** : Unity : 직접 표시 안 됨 · 실습의 각크기 로거로 계산해 Console 에 출력

### 간접광

**간접광** · *Indirect light* — 5주

- **뜻** : 광원에서 바로 오지 않고 벽·바닥·하늘에 한 번 이상 튕겨서 오는 빛 — «당구공의 쿠션 샷» 같은 빛
- **예** : 창으로 든 햇빛이 흰 바닥에 튕겨 천장까지 밝힘 · 해가 직접 안 닿는 천장도 보임
- **왜** : 실내 밝기의 상당 부분 = 간접광 → 빠지면 비친 곳만 밝고 나머지는 동굴처럼 어두움
- **어디서** : Unity : Light → Indirect Multiplier · Lighting 창 → Lightmapping Settings (베이크 GI)

### 감각 충돌

**감각 충돌** · *Sensory conflict* — 7주 · 다시 : 12주

- **뜻** : 눈이 보고한 움직임과 귀 속 전정계가 보고한 움직임이 서로 다른 상태
- **예** : VR 스틱 이동 : 눈 «앞으로 빨라짐» · 전정계 «가만히 있음» → 불일치
- **왜** : 멀미 설명의 대표 이론 · 무엇을 줄여야 할지(가속·회전·흐름) 알려 줌
- **어디서** : 이동 방식 설정 — 연속 이동(Continuous Move) vs 텔레포트 · 회전 방식

### 감각 충돌 이론

**감각 충돌 이론** · *Sensory conflict theory* — 2주

- **뜻** : 눈이 본 움직임과 몸(전정계)이 느낀 움직임이 서로 다른 말을 하면 메스꺼움이 생긴다는 설명
- **예** : VR 에서 조이스틱으로 전진 : 눈 «앞으로 가는 중» · 귀 «가만히 서 있음» → 어긋남
- **왜** : 멀미를 줄이는 설계 = 두 감각의 어긋남 줄이기 (텔레포트 · 시야 가리개 · 고정된 기준물)
- **어디서** : 가장 널리 쓰이는 설명이지만 «왜 토하게 되는가» 는 여러 가설이 경쟁 중

### 감김 방향

**감김 방향** · *Winding order* — 4주

- **뜻** : 삼각형 세 꼭짓점이 화면에서 시계 / 반시계로 도는 순서 — 앞면 · 뒷면을 가리는 표식
- **예** : Unity = 화면에서 시계 방향으로 보이면 앞면 · 같은 삼각형을 뒤에서 보면 반시계 → 뒷면
- **왜** : 모델링 툴에서 면이 뒤집히면 Unity 에서 구멍 난 듯 보임
- **어디서** : Blender : Viewport Overlays → Face Orientation (파랑 앞 · 빨강 뒤)

### 감마

**감마** · *Gamma* — 5주

- **뜻** : sRGB 눈금과 실제 빛 사이의 휘어진 변환 곡선 (지수 약 2.2) — 눈금 → 에너지는 «2.2 제곱»
- **예** : \(0.5^{2.2} \approx 0.22\) · 거꾸로 \(0.22^{1/2.2} \approx 0.5\) → 저장할 땐 펴고, 계산할 땐 다시 휨
- **왜** : Unity 의 «Gamma» 설정 = 이 변환 없이 눈금 숫자로 바로 계산 → 조명 덧셈이 과장됨
- **어디서** : Unity : Player → Other Settings → Color Space = Gamma (구형 방식 · 비권장)

### 감쇠

**감쇠** · *Attenuation* — 5주

- **뜻** : 광원에서 멀어질수록 빛이 약해지는 정도 — 촛불 가까이는 밝고 방 구석은 어두운 현상
- **예** : 전구에서 1 m 밝기 100 → 2 m 25 → 3 m 약 11 («조명 · 4» 역제곱 손계산)
- **왜** : 감쇠를 모르고 Intensity 만 올리면 광원 근처만 하얗게 타고 먼 곳은 그대로 어두움
- **어디서** : Unity : Point · Spot Light 컴포넌트의 Range · Intensity (Directional 에는 Range 없음)

### 강체

**강체** · *Rigid body* — 7주

- **뜻** : 힘을 받아도 모양이 변하지 않는다고 가정한 물체 — 위치·회전만 바뀌는 쇳덩이
- **예** : 바닥에 떨어진 상자 : 굴러가고 튕기지만 찌그러지지는 않음
- **왜** : 찌그러짐을 빼서 계산이 빠름 → 천·젤리처럼 휘는 물체는 별도 기법 필요
- **어디서** : Unity 기본 3D 물리(PhysX) = 강체 · 천은 Cloth 컴포넌트

### 개발자 모드

**개발자 모드** · *Developer Mode* — 11주

- **뜻** : 헤드셋에 내가 만든 앱을 직접 설치할 수 있게 여는 잠금 해제 설정
- **예** : 꺼져 있으면 USB 로 연결해도 Unity Run Device 목록에 Quest 가 안 뜸
- **어디서** : 휴대폰 Meta Horizon 앱 → 기기 → 헤드셋 설정 → 개발자 모드 (개발자 계정 인증 필요 · 버전마다 다름)

### 개입

**개입** · *Intervention* — 14주

- **뜻** : 진행자가 힌트·설명으로 체험자의 행동을 바꾸는 것 — 오늘 금지
- **예** : «오른쪽 버튼 눌러 보세요» = 개입 · «지금 무엇을 보고 계세요?» = 허용
- **왜** : 힌트 한마디로 «막히는 곳» 이 사라져 기록에서 빠짐 — 15주 관람자에겐 힌트를 줄 사람이 없음

### 거리 과소추정

**거리 과소추정** · *Distance compression* — 13주

- **뜻** : VR 속 거리를 실제보다 가깝게 느끼는 현상 (5주) — 방이 실측보다 좁아 보임
- **예** : 씬에서 4 m 떨어진 문 → 평균 약 74% · 약 3 m 로 느낌 (연구 종합 평균 · 개인차 큼)
- **왜** : 실측 치수 그대로 만들면 «좁다» 는 피드백 → 간격 조정 · 단안 단서 보강 필요
- **어디서** : 이 덱 «스케일 · 1» · 기획서 ② 에 근거로 인용 (Renner et al. 2013)

### 거칠기

**거칠기** · *Roughness* — 5주

- **뜻** : 표면의 눈에 안 보이는 미세한 울퉁불퉁함 — 클수록 빛이 여러 방향으로 흩어져 로브가 넓어짐
- **예** : 새 볼링공 거칠기 약 0.1 → 형광등이 또렷이 비침 · 사포질한 공 약 0.7 → 뿌연 얼룩만
- **왜** : Unity 는 반대 이름(Smoothness)을 씀 → 다른 툴의 Roughness 값을 그대로 넣으면 광택이 뒤집힘
- **어디서** : Unity URP Lit : Smoothness = 1 − Roughness · Source = Metallic Alpha 또는 Albedo Alpha

### 검증 리포트

**검증 리포트** · *Verification report* — 8주

- **뜻** : «이 코드가 맞다» 를 말이 아닌 측정값으로 보인 문서 — 체중계 숫자처럼 누가 봐도 같은 결과
- **예** : «30fps · 120fps 에서 10초 이동 거리 모두 50.0 m» · «피치 89~91° 회전 튐 0회»
- **어디서** : Unity : Console 로그 · Stats 창(Game 뷰 오른쪽 위) · Profiler 의 ms 값

### 게임오브젝트

**게임오브젝트** · *GameObject* — 3주

- **뜻** : 씬 안 모든 물체의 기본 틀 · 그 자체로는 아무 기능 없는 빈 판
- **예** : Create Empty 로 만든 «GameObject» — 이름과 위치만 있고 화면엔 안 보임
- **어디서** : Hierarchy 빈 곳 우클릭 → Create Empty · 또는 3D Object → Cube

### 경계 · 가디언

**경계 · 가디언** · *Boundary · Guardian* — 15주

- **뜻** : 헤드셋에 미리 그려 둔 안전한 플레이 구역의 테두리 — 가까이 가면 가상 벽이 나타남
- **예** : 스테이지 2 m × 2 m 를 따라 바닥에 선을 그어 둠 → 손이 다가가면 격자 벽 표시
- **어디서** : Quest 설정 → 물리적 공간 → 경계(Boundary) · 예전 이름 Guardian — 메뉴 이름은 버전마다 다름

### 고유감각

**고유감각** · *Proprioception* — 1주

- **뜻** : 눈을 감아도 내 팔다리가 어디 있는지 아는 몸속 감각 — 근육·관절이 보내는 위치 신호
- **예** : 눈 감고 검지로 코끝 짚기 · 어두운 방에서 스위치 찾기
- **왜** : 가상 손이 실제 손보다 몇 cm 만 어긋나도 «내 손이 아닌» 어색함
- **어디서** : Quest : 손 추적(Hand Tracking) · 컨트롤러 위치 → Unity XRI 의 손·컨트롤러 오브젝트

### 고정 타임스텝

**고정 타임스텝** · *Fixed Timestep* — 3주

- **뜻** : fps 와 무관하게 항상 같은 간격으로 물리를 계산하는 방식 — 메트로놈 박자
- **예** : 기본값 0.02초 = 초당 50번 · FixedUpdate 가 이 박자로 호출
- **왜** : 간격을 크게 늘리면 물리가 거칠어지고, 너무 줄이면 계산량이 늘어 fps 하락
- **어디서** : Edit → Project Settings → Time → Fixed Timestep

### 고정 포비티드 렌더링

**고정 포비티드 렌더링** · *Fixed Foveated Rendering* — 14주

- **뜻** : 시야 가장자리는 거칠게, 가운데만 선명하게 그려 GPU 일을 줄이는 기법 — 렌즈 가장자리는 원래 흐릿하게 보임
- **예** : 화면 바깥 테두리 픽셀을 2×2 · 4×4 묶음으로 한 번에 계산
- **왜** : GPU 병목일 때 체감 화질 손해가 적은 처방 · 단계를 너무 올리면 가장자리 글자가 뭉개짐
- **어디서** : 설정 위치는 XR 플러그인·버전마다 다름 (OpenXR 기능 목록 또는 Meta XR 설정)

### 공간 비디오

**공간 비디오** · *Spatial video* — 16주

- **뜻** : 사람 눈 간격만큼 떨어진 두 렌즈로 동시에 찍어 왼눈 · 오른눈에 다른 영상을 보여 주는 입체 영상
- **예** : 생일 케이크 장면을 찍어 헤드셋으로 보면 촛불이 화면 앞으로 튀어나와 보임
- **어디서** : 일부 스마트폰 · 헤드셋의 촬영 기능 · 재생 앱과 파일 형식은 기기 · 버전마다 다름

### 공간 스케치

**공간 스케치** · *Spatial sketch* — 13주

- **뜻** : 위에서 본 평면도 · 옆에서 본 측면도 · 눈에 보이는 범위를 실제 치수(m)로 그린 그림
- **예** : 격자 한 칸 = 1 m · 체험자 위치에서 0.7 m 원 = 손 닿는 범위 · 정면 ±30° 부채꼴 = 주요 시야
- **왜** : «대충 저쪽» 으로 그리면 등 뒤 물체 · 손 안 닿는 버튼이 구현 후에야 드러남
- **어디서** : 이 수업 : 1 m 격자 종이 · Unity 에서는 그대로 1 unit = 1 m 로 옮김

### 과업

**과업** · *Task* — 14주

- **뜻** : 체험자에게 주는 구체적 목표 한 문장 — 보물찾기 쪽지
- **예** : «연못에 돌 3개를 던지기» (좋음) · «자유롭게 둘러보기» (나쁨 — 끝났는지 판정 불가)
- **왜** : 목표가 분명해야 «어디서 막혔나 · 몇 분 걸렸나» 를 숫자로 기록 가능
- **어디서** : 진행자가 체험 전에 건네는 과업 카드 · 조작 방법은 적지 않음

### 광역·정밀 판정

**광역·정밀 판정** · *Broad · Narrow phase* — 7주

- **뜻** : 후보를 대충 거르는 단계(광역) → 후보만 정확히 검사하는 단계(정밀) — 공항 문형 탐지기 → 몸수색
- **예** : 물체 1,000개 = 499,500쌍 → 광역에서 대부분 탈락 · 소수 후보만 정밀 검사
- **왜** : 전부 정밀 검사하면 0.02초 안에 못 끝남 → 물체가 많을수록 프레임 저하
- **어디서** : Project Settings → Physics → Broadphase Type (메뉴 위치는 버전마다 다름)

### 광원 방향 L

**광원 방향 L** · *Light vector* — 5주

- **뜻** : 표면에서 광원 쪽을 가리키는 길이 1 화살표 — 빛이 날아오는 방향의 반대 («빛을 마중 나가는 화살표»)
- **예** : 해가 머리 위 → L = (0, 1, 0) · 해가 비스듬히 위 → L = (0.6, 0.8, 0)
- **왜** : 방향을 거꾸로(빛이 오는 쪽으로) 넣으면 N·L 부호가 뒤집혀 밝은 면과 그늘이 바뀜
- **어디서** : Unity : Directional Light 의 회전 = 빛이 날아가는 방향 (L 은 반대) · Shader Graph Main Light Direction 노드 (버전별 상이)

- **어디서** : Unity URP : s 를 직접 입력하지 않음 · Smoothness (0~1) 가 내부에서 이 값으로 환산됨

**비균등 스케일** · *Non-uniform scale* — 2주

- **뜻** : 축마다 다른 배율로 늘리는 것 — 사진을 가로세로 비율 무시하고 한쪽만 잡아 늘리기
- **예** : Scale (1, 3, 1) = 세로만 3배 · 균등 스케일 (2, 2, 2) = 모양 그대로 크기만 2배
- **왜** : 부모가 비균등 스케일이면 회전한 자식이 찌그러짐 · 콘솔 경고도 없음
- **어디서** : Inspector Transform → Scale · 옆 사슬 아이콘(비율 고정)을 켜면 세 값이 함께 바뀜

### 비네팅

**비네팅** · *Vignetting* — 4주

- **뜻** : 화면 가장자리가 점점 어두워지는 현상 — 오래된 사진 모서리의 그늘
- **예** : 헤드셋이 눈보다 몇 mm 위로 올라가면 아래쪽 시야가 어두워짐
- **왜** : 아이박스 이탈의 신호 · 반대로 이동 멀미를 줄이려고 일부러 가장자리를 어둡게 하기도 함
- **어디서** : XRI 의 Tunneling Vignette (12주 컴포트) · URP 후처리 Volume 의 Vignette

### 비대칭 절두체

**비대칭 절두체** · *Asymmetric frustum* — 4주

- **뜻** : 좌우 폭이 서로 다른 카메라 상자 — VR 각 눈은 코 쪽이 좁고 귀 쪽이 넓음
- **예** : 왼눈 상자 = 코 쪽 40° · 귀 쪽 50° 처럼 한쪽으로 쏠림 (값은 기기마다 다름)
- **왜** : fieldOfView 숫자 하나로는 표현 불가 → 코드로 덮어쓰면 두 눈 상이 어긋남
- **어디서** : XR 런타임이 매 프레임 주입 · 스크립트 Camera.GetStereoProjectionMatrix 로 읽기만

### 비목표

**비목표** · *Non-goals* — 13주

- **뜻** : «이번에는 일부러 하지 않는 것» 을 명시한 목록 — 할 일 목록의 반대편
- **예** : «멀티플레이 · 대사 많은 캐릭터 · 최종 텍스처 = 비목표»
- **왜** : 적어 두지 않으면 AI 가 «친절하게» 기능을 덧붙이고 팀원도 범위를 넓힘 → 마감 붕괴
- **어디서** : 프롬프트 명세 [비목표] 칸 · 기획서 범위 분류의 «이번엔 안 함»

### 사이버 멀미

**사이버 멀미** · *Cybersickness* — 2주

- **뜻** : VR·화면 속 움직임 때문에 생기는 어지러움·메스꺼움·눈 피로 — 차멀미의 VR 판
- **예** : 조이스틱으로 앞으로 걷는 장면 3분 만에 속이 울렁거림
- **어디서** : 설문 SSQ 로 측정 · XRI 의 Snap Turn(뚝뚝 끊어 돌기) · Tunneling Vignette(시야 가리개)로 줄임

### 사이버멀미

**사이버멀미** · *Cybersickness · VR sickness* — 9주 · 다시 : 12주

- **뜻** : VR 체험 중·후에 생기는 메스꺼움 · 어지러움 · 눈 피로 같은 증상 묶음 — 차멀미의 VR 판
- **예** : 스틱 이동 2분 뒤 식은땀·침 분비 → 헤드셋을 벗어도 30분 넘게 남기도 함
- **왜** : 개인의 «약함» 이 아니라 설계가 만든 결과 → 설계로 줄일 수 있음
- **어디서** : 체험 직후 SSQ 설문 · 실기 3단계 대응표 · 스토어 컴포트 표시

### 사이클/도

**사이클/도** · *cycles per degree* — 6주

- **뜻** : 시야 1° 안에 흰·검 줄무늬 쌍이 몇 개 들어가는지 — 무늬의 촘촘함을 각도로 잰 값
- **예** : 1° 안에 흰·검 쌍 30개 = 30 사이클/도 = 시력 1.0 의 한계
- **왜** : 화면 PPD ÷ 2 = 그 화면이 보여 줄 수 있는 최대 사이클/도 (나이퀴스트)

### 사전 동의

**사전 동의** · *Informed consent* — 13주

- **뜻** : 체험 내용·위험·중단 방법을 먼저 설명하고 참여 여부를 스스로 정하게 하는 절차
- **예** : «높이 소재 포함 · 멀미 시 손을 들면 즉시 중단 · 언제든 그만둘 수 있음» 안내 후 서명
- **왜** : VR 은 몰입도가 높아 불쾌 자극이 강하게 전달 → 고지 없는 공포·높이 체험은 연구 윤리 위반
- **어디서** : 14주 플레이테스트 동의 절차 · 체험자마다 시작 전 진행 · 기획서 ① 민감 소재 · 중단 방법 줄

### 사후 설문

**사후 설문** · *Post-experience questionnaire* — 15주

- **뜻** : 체험이 끝난 뒤 기억을 떠올려 답하는 설문 — 그 순간이 아니라 회상을 잼
- **예** : «체험 중 그곳에 있는 느낌이 들었다 (1~7점)»
- **왜** : 기억은 마지막 장면·기분에 끌려감 → 체험 중 행동 관찰과 함께 써야 함

### 상보 필터

**상보 필터** · *Complementary filter* — 11주

- **뜻** : 빠른 센서 값은 대부분(α), 기준 센서 값은 조금(1−α)만 섞는 가장 단순한 융합 공식
- **예** : α = 0.98 · 자이로 32° · 기준 30° → 0.98 × 32 + 0.02 × 30 = 31.96°
- **왜** : α 크게 → 매끄럽지만 드리프트 회수가 느림 · α 작게 → 회수는 빠르지만 화면이 떨림
- **어디서** : 아두이노·드론 자세 계산 예제의 단골 · 헤드셋 내부는 더 정교한 필터 사용

### 상속

**상속** · *Inheritance* — 3주

- **뜻** : 기존 설계도를 물려받아 기능을 덧붙인 새 설계도 작성 (FlyingEnemy ← Enemy)
- **예** : 이동 3종 × 공격 4종 = 설계도 최대 12개 · 새 공격 1종 추가 → 3개 더
- **왜** : 조합이 늘수록 설계도가 곱셈으로 불어남 · 두 부모의 기능을 동시에 물려받기 불가
- **어디서** : 코드의 콜론 class Spinner : MonoBehaviour — Unity 에서는 주로 이 한 번만 사용

### 상태

**상태** · *State* — 10주

- **뜻** : 지금 시스템이 놓인 상황 하나 — 한 번에 딱 하나만 참
- **예** : 자판기 «대기» · «금액 투입» · «배출» / 게임 Menu · Playing · Paused
- **왜** : 같은 버튼이라도 상태에 따라 결과가 달라짐 → 상태를 모르면 버그 재현 불가
- **어디서** : 코드 : enum GameState { … } 변수 하나 · Unity Animator 창의 네모 상자

### 상태 기계

**상태 기계** · *State machine* — 7주 · 다시 : 10주

- **뜻** : «지금 어떤 상태인가» 와 «무엇이 오면 어디로 넘어가나» 만으로 동작을 정하는 설계 — 자판기

- **왜** : bool 플래그 여러 개로 짜면 말이 안 되는 조합(죽었는데 일시정지)이 생김

### 색 번짐

**색 번짐** · *Color bleeding* — 5주

- **뜻** : 색 있는 표면에서 튕긴 빛이 옆 표면을 그 색으로 물들이는 현상 — 간접광이 «색을 실어 나름»
- **예** : 빨간 소파 옆 흰 벽 아랫부분이 분홍빛 · 잔디밭 위 흰 공의 아랫면이 연두빛
- **왜** : 물체들이 «같은 공간에 함께 있다» 는 인상을 주는 단서 → 없으면 물체가 합성 사진처럼 따로 놂

**색수차** · *Chromatic aberration* — 4주

- **뜻** : 렌즈가 빨강 · 초록 · 파랑 빛을 조금씩 다르게 꺾어 가장자리에 무지개 테두리가 생기는 현상 — 프리즘 무지개
- **예** : 렌즈 가장자리의 흰 글자 → 한쪽은 빨강, 반대쪽은 파랑으로 번짐
- **왜** : 보정하려면 R · G · B 를 서로 다른 배율로 왜곡 → 후처리 비용 증가

### 샘플 · 표본

**생각 말하기** · *Think-aloud* — 14주

### 선형

**선형** · *Linear* — 5주

- **뜻** : 숫자 2배 = 실제 빛 에너지 2배인 곧은 눈금 — 빛을 더하고 곱하는 계산의 기준
- **예** : 전구 두 개 0.22 + 0.22 = 0.44 → 실제로 빛 2배 → 화면용 변환 후 약 0.7 (흰색 아님)
- **왜** : PBR 값 범위 · 라이트맵 · 조명 세기 모두 선형 계산 전제 → 프로젝트 시작 시 결정
- **어디서** : Unity : Player → Other Settings → Color Space = Linear (URP 템플릿 기본값)

### 선형변환

**선형변환** · *Linear transform* — 2주

- **뜻** : 직선은 직선으로, 원점은 원점에 남기는 변환 — 고무판을 늘리거나 돌리기만 하고 밀지는 않음
- **예** : 스케일 · 회전 = 선형 · 이동 (원점이 (3, 0) 으로 감) = 선형 아님
- **왜** : 2×2·3×3 행렬로는 선형변환만 가능 → 이동을 넣으려고 4×4 와 동차좌표가 등장

### 성능 예산

**성능 예산** · *Performance budget* — 13주

- **뜻** : 한 프레임 안에 쓸 수 있는 처리량의 상한을 미리 정한 표 — 한 달 «용돈 한도»
- **예** : 90Hz = 11.1 ms · 드로우콜 150 · 삼각형 50만 · 실시간 그림자 0~1 · 텍스처 2048 이하
- **왜** : 예산 없이 에셋을 넣다 보면 14주 헤드셋 실측에서 72 fps 강등 → 이미 늦은 시점에 발견
- **어디서** : 기획서 ④ 항목 · 측정 : Unity Profiler · Game 뷰 Stats · 헤드셋 OVR Metrics Tool

### 세션

**세션** · *Session* — 9주

- **뜻** : AI 와 주고받은 대화 한 묶음 — 새 세션 = 책상을 비우고 다시 시작
- **예** : 같은 오류로 3번 실패 → 새 세션 + 지금까지의 결론 5줄 요약
- **왜** : 긴 세션에는 실패한 코드·틀린 가설이 쌓여 다음 답을 오염
- **어디서** : 채팅 도구의 «새 대화» · 코딩 에이전트의 새 세션 명령 (도구마다 다름)

### 센서 융합

**센서 융합** · *Sensor fusion* — 11주

- **뜻** : 장단점이 다른 센서 여러 개의 값을 섞어 하나의 더 믿을 만한 값을 만드는 계산
- **예** : 자이로(빠르지만 흘러감) + 카메라(느리지만 안 흘러감) → 빠르고 안 흘러가는 자세
- **왜** : 센서 하나로는 «빠름» 과 «정확함» 을 동시에 못 얻음 · 헤드셋이 자동 처리 → Unity 는 결과 자세만 받음

### 셰이더

**셰이더** · *Shader* — 1주 · 다시 : 4주, 5주, 6주

- **뜻** : 그래픽 카드가 화면을 그릴 때 점·픽셀마다 한 번씩 돌리는 짧은 계산 규칙 — 도색 공장의 작업 지시서
- **예** : 정육면체 하나 = 꼭짓점 24번 + 픽셀 수만 번 같은 지시서 반복 실행
- **왜** : 표면 색·광택·투명도 모두 셰이더 결과 → 재질이 이상하면 셰이더 설정부터 의심
- **어디서** : Material Inspector 맨 위 Shader 드롭다운 (예 : Universal Render Pipeline/Lit)

### 수렴

**수렴** · *Vergence* — 5주 · 다시 : 10주, 12주

- **뜻** : 가까운 것을 볼 때 두 눈이 안쪽으로 모이는 움직임 — 코끝을 보면 «사팔눈» 이 되는 그 동작
- **예** : 30 cm 앞 책 → 두 눈이 크게 모임 · 먼 산 → 두 시선이 거의 평행
- **왜** : VR 에서 수렴은 물체 거리에 맞게 바뀌지만 초점(조절)은 고정 → 두 신호 불일치 = 눈 피로 원인
- **어디서** : 10주차 공간 UI : 패널을 0.5 m 보다 가깝게 두지 말라는 규칙의 근거

### 수직

**수직** · *Perpendicular* — 2주

- **뜻** : 두 방향이 서로 90° 로 만나는 관계 — 바닥과 그 위에 똑바로 선 기둥
- **예** : 오른쪽 (1, 0, 0) 과 위 (0, 1, 0) · 내적 = 1×0 + 0×1 + 0×0 = 0
- **왜** : «내적 0 = 수직» 한 줄로 직각 여부를 숫자로 확인 · 외적 결과는 언제나 두 재료 모두에 수직
- **어디서** : Scene 뷰 축 기즈모의 X·Y·Z 세 화살표 = 서로 수직인 세 방향

### 수직 단면

**수직 단면** · *Vertical slice* — 13주

- **뜻** : 완성품의 모든 층(공간·조작·피드백)을 갖춘 짧은 한 구간 — 케이크를 위에서 아래로 자른 «한 조각»
- **예** : 방 하나 · 돌 집기 → 던지기 → 물수제비 소리·진동 · 4분 → 시작부터 끝까지 완성
- **왜** : 넓게 얕게 만들면 15주에 «아무것도 끝나지 않은» 데모 → 좁게 깊게가 완성도 점수에 유리
- **어디서** : 이 덱 «범위 · 1~2» · 기획서 «반드시 / 있으면 좋음 / 이번엔 안 함» 분류표

### 수치 적분

**수치 적분** · *Numerical integration* — 7주

- **뜻** : «속도 × 짧은 시간» 을 계속 더해 다음 위치를 구하는 계산 — 배의 추측항법
- **예** : 위치 0 m · 속도 5 m/s → 0.02초 뒤 0 + 5 × 0.02 = 0.1 m
- **왜** : 매 스텝 조금씩 오차 → 순서를 잘못 짜면 흔들림이 점점 커져 폭발
- **어디서** : 엔진 내부에서 자동 · AI 에게 «물리 직접 구현» 을 시키면 코드에 등장

### 순서 효과

**순서 효과** · *Order effect* — 12주

- **뜻** : 무엇을 먼저 겪었느냐가 결과를 바꾸는 현상 — 매운 음식 다음 먹은 음식은 다 싱거움
- **예** : 유발본 → 완화본 순서만 쓰면 완화본 점수에 앞 체험의 남은 멀미가 섞임
- **왜** : 완화 효과가 실제보다 작게(또는 크게) 보임 → 조의 절반은 순서를 바꿔 상쇄
- **어디서** : 실기 4단계 «절반 조는 B 먼저» · ComfortModeSwitcher 로 순서 전환

### 스냅 턴

**스냅 턴** · *Snap turn* — 13주

- **뜻** : 몸 방향을 부드럽게 돌리지 않고 정해진 각도만큼 «툭» 끊어서 돌리는 회전 방식
- **예** : 스틱 오른쪽 1회 = 오른쪽으로 22.5° 즉시 회전 · 4번 = 90°
- **왜** : 회전 중 시야가 흐르는 구간이 없음 → 부드러운 회전보다 멀미 적음 (12주 Farmani & Teather)
- **어디서** : Unity XRI 3.x : Snap Turn Provider → Turn Amount (기본값 45° · 이 수업 권장 22.5°)

### 스칼라

**스칼라** · *Scalar* — 2주

- **뜻** : 방향 없이 크기만 있는 숫자 하나 — 길이, 속력, 각도, 밝기
- **예** : 속력 5 m/s (스칼라) vs 동쪽으로 5 m/s (벡터)
- **어디서** : C# 의 float · Light 의 Intensity, Camera 의 Field of View 같은 숫자 칸 하나

### 스케일

**스케일** · *Scale* — 9주

- **뜻** : 가상 물체 크기가 실제 크기와 맞는 정도 — 1 unit = 1 m 약속
- **예** : 문 높이 2 · 책상 0.75 · 문이 1.5 면 몸이 거인처럼 느껴짐
- **왜** : 모니터로는 크기 판단 불가 · 헤드셋에서는 몸이 바로 알아챔
- **어디서** : Transform → Scale · 기본 Cube (1 m 정육면체) 를 옆에 두고 비교

### 스크린도어 효과

**스크린도어 효과** · *Screen-door effect* — 6주

- **뜻** : 픽셀 사이 빛나지 않는 틈이 렌즈로 확대되어 방충망처럼 보이는 현상
- **예** : 초기 헤드셋에서 밝은 하늘을 보면 가는 검은 격자가 겹쳐 보임
- **왜** : 가는 선·작은 글자가 격자에 끊겨 보임 → 세밀한 무늬 설계 시 고려
- **어디서** : Quest 3 : 고밀도 LCD + 팬케이크 렌즈로 크게 감소 · 밝은 단색 배경에서 확인

### 스크립트

**스크립트** · *Script (C#)* — 3주

- **뜻** : C# 언어로 내가 직접 만드는 행동 부품 — 회전·점프처럼 Unity 에 없는 동작
- **왜** : 파일 이름과 안의 클래스 이름이 다르면 부품으로 붙일 수 없음 — 이름을 바꿀 땐 둘 다
- **어디서** : Project 창 우클릭 → Create → Scripting → MonoBehaviour Script (Unity 6 · 이전 버전은 C# Script)

### 스키닝

**스키닝** · *Skinning* — 7주

- **뜻** : 뼈가 움직일 때 피부(메시 정점)가 따라 움직이게 하는 계산 — 철사 인형 위에 씌운 천
- **예** : 팔꿈치 정점 = 위팔 결과 50% + 아래팔 결과 50% 를 섞어 위치 결정
- **왜** : 섞는 방식 때문에 관절을 크게 꺾으면 부피가 줄어 쭈그러짐 (뒤 손계산 0.71)
- **어디서** : Skinned Mesh Renderer 컴포넌트 · Project Settings → Quality → Skin Weights

### 스택 트레이스

**스택 트레이스** · *Stack trace* — 9주

- **뜻** : 오류가 났을 때 «어떤 함수가 어떤 함수를 불러 여기까지 왔는가» 를 적은 호출 경로 목록 — 사고 경위서
- **예** : PlayerMover.FixedUpdate () (at Assets/Scripts/PlayerMover.cs:27) → 27행
- **왜** : 줄 번호·함수 이름 = 원인 범위를 좁히는 핵심 단서 → 요약하지 말고 원문 그대로
- **어디서** : Unity Console 창에서 에러 클릭 → 아래 칸에 표시 · 줄 더블클릭 = 해당 코드로 이동

### 스테일 프레임

**스테일 프레임** · *Stale frame* — 14주

- **뜻** : 새 프레임이 제때 준비되지 않아 이전 프레임을 다시 보여 준 횟수 — 3주차 «프레임 드랍» 의 실측 숫자
- **예** : 90Hz 로 1분 = 5400장 중 스테일 300 → 고개 돌릴 때 덜컥
- **어디서** : OVR Metrics Tool 의 Stale Frames 항목

### 스포터

**스포터** · *Spotter* — 11주 · 다시 : 15주

- **뜻** : 체험자 곁에서 안전만 지켜보는 팀원 1명 — 헤드셋 쓴 사람의 눈 대신 주변을 보는 사람
- **예** : 체험자가 케이블을 밟으려 하거나 관람자에게 팔을 휘두르기 직전 → 어깨를 가볍게 잡아 멈춤
- **왜** : 헤드셋을 쓴 사람은 실제 공간을 못 봄 → 스포터가 없으면 충돌 사고

### 시각 예민도

**시각 예민도** · *Visual acuity* — 6주

- **뜻** : 얼마나 작은 디테일까지 구분해 보는가 — 흔히 말하는 «시력»
- **예** : 시력 1.0 (20/20) = 시야 1/60° (1각분) 크기 틈까지 구분
- **왜** : 눈 한계보다 작은 디테일은 만들어도 안 보임 → 해상도 낭비 판단 기준
- **어디서** : 안과 시력표 (한국식 1.0 = 영미식 20/20)

### 시선 방향 V

**시선 방향 V** · *View vector* — 5주

- **뜻** : 표면의 한 점에서 카메라(눈) 쪽을 가리키는 길이 1 화살표 — «이 점에서 나를 올려다보는 방향»
- **예** : 카메라가 점의 바로 위 → V = (0, 1, 0) · 고개를 옆으로 옮기면 V 도 같이 기울어짐
- **왜** : 정반사 식에만 V 가 들어감 → 하이라이트가 시점 따라 움직이는 이유 · VR 은 두 눈의 V 가 서로 다름
- **어디서** : Unity : Shader Graph 의 View Direction 노드 · 카메라 Transform 위치에서 계산

### 시스템 역

**시스템 역** · *Wizard of Oz* — 13주

- **뜻** : 사람이 컴퓨터 대신 반응을 흉내 내는 시험 방식 — 「오즈의 마법사」 커튼 뒤에서 마법사 흉내를 낸 사람에서 유래
- **예** : 체험자가 상자를 집는 동작 → 시스템 역이 «딸깍, 상자가 손에 붙습니다» 라고 말로 알려 줌
- **왜** : 코드 한 줄 없이 «반응이 이렇게 오면 이해가 되나» 를 시험 → 말로 설명이 길어지는 장면 = 설계 위험 신호
- **어디서** : 오늘 바디스토밍 · 시스템 역은 시나리오 대본을 들고 체험자 옆 1 m 에서 진행

**시스템 프롬프트** · *System prompt* — 9주

- **예** : «너는 코딩 도우미 · 파일을 고치기 전에 계획부터 말할 것» 같은 문장
- **왜** : 사용자 눈에 안 보이는 곳에서 답의 말투·행동을 좌우
- **어디서** : 도구 회사가 내장 · 사용자는 규칙 파일(예 : AGENTS.md)로 덧붙임

**시야각** · *FOV · Field of view* — 5주

- **왜** : 주변시 자극이 줄면 거리·속도 판단 근거도 줄어듦 → VR 거리 과소추정 원인 후보
- **어디서** : Unity : XR 실행 중 Camera 의 Field of View 는 헤드셋이 덮어씀 → 직접 바꿔도 무시됨

### 원점

**원점** · *Origin* — 2주

- **뜻** : 모든 위치를 재는 출발 기준점 — 좌표 (0, 0, 0) · 지도의 «여기가 0 km» 표지석
- **예** : 원점에서 오른쪽 2, 위 1 떨어진 점 = (2, 1, 0)
- **왜** : 기준점이 바뀌면 같은 물체의 위치 숫자가 전부 바뀜 — 점은 바뀌고 벡터는 그대로
- **어디서** : Scene 뷰 격자 한가운데 · Transform 컴포넌트 ⋮ 메뉴 → Reset 하면 Position (0, 0, 0)

### 월드 좌표

**월드 좌표** · *World* — 2주 · 다시 : 3주

- **뜻** : 씬 전체 기준의 절대 위치 — 방 원점에서 잰 거리 · 부모들의 변환을 차례로 곱해 계산 (2주차 행렬 곱)
- **예** : 쟁반 이동 전 110cm → 이동 후 260cm
- **왜** : «두 물체 사이 거리» 처럼 서로 다른 부모의 물체를 비교할 땐 반드시 월드 값
- **어디서** : Inspector 엔 직접 안 보임 · 코드 transform.position

### 월드 축 · 자기 축

**월드 축 · 자기 축** · *World · Local (Self) space* — 2주

- **뜻** : 월드 축 = 씬 전체에 고정된 방향 (방 안의 동서남북) · 자기 축 = 물체에 붙어 함께 도는 방향 (내 몸 기준 앞·옆)
- **예** : 비행기가 옆으로 누운 뒤 «위로» 돌기 : 월드 위(하늘) vs 비행기 자기 위(지금은 옆쪽)
- **왜** : 같은 «Y 90°» 라도 기준 축이 다르면 다른 자세 → 도입 질문 A·B 가 갈린 이유
- **어디서** : transform.Rotate(…, Space.Self)(기본값) vs Space.World · Scene 뷰 툴바 Global / Local

### 이동 기법

**이동 기법** · *Locomotion* — 11주

- **뜻** : 실제로 걷지 않고 컨트롤러 조작으로 가상 공간 안을 옮겨 다니는 방법의 총칭
- **예** : 텔레포트(순간 이동) · 스냅 턴(뚝 끊어 회전) · 연속 이동(스틱으로 미끄러지듯)
- **왜** : 방식마다 시야가 흐르는 양이 다름 → 멀미 위험이 크게 달라짐
- **어디서** : XR Origin 자식 Locomotion → Teleportation · Turn · Move (XRI 3.x)

### 이방성 필터링

**이방성 필터링** · *Anisotropic filtering* — 6주

- **뜻** : 비스듬히 본 면에서 길쭉해진 픽셀 영역을 긴 방향으로 여러 번 읽어 평균 — 방향마다 다르게 다루기
- **예** : 영역 가로 2 · 세로 8 텍셀 → Aniso 4× : 레벨 1 에서 세로로 4번 읽기
- **왜** : Trilinear 만 쓰면 먼 바닥이 뿌옇게 뭉개짐 · 대신 읽기 횟수 증가
- **어디서** : 텍스처 Inspector → Aniso Level (0~16) · Project Settings → Quality → Anisotropic Textures

### 이벤트

**이벤트** · *Event* — 10주

- **뜻** : «눌렸다» 는 일이 생겼을 때 알림을 받는 방식 — 초인종이 울리면 나가기
- **예** : 1분에 1번 눌림 → 알림 1번 · 확인 코드 5,400번 → 0번
- **왜** : «무슨 일이 생기면 무엇을 한다» 가 한 곳에 모임 → 기능을 붙이고 떼기 쉬움
- **어디서** : Unity : Button 인스펙터 On Click () 칸 · 코드 jump.performed += …

### 이벤트 함수

**이벤트 함수** · *Event Function* — 3주

- **뜻** : 정해진 이름으로 만들어 두면 Unity 가 알맞은 때에 자동 호출하는 함수 — 무대감독의 큐 목록
- **예** : Awake · Start · Update · FixedUpdate · LateUpdate · OnCollisionEnter (부딪힌 순간)
- **왜** : 이름이 한 글자라도 다르면(update) 오류 없이 그냥 안 불림
- **어디서** : Unity 매뉴얼 «Order of execution for event functions» 에 전체 순서표

### 이석기관

**이석기관** · *Otolith organs* — 2주 · 다시 : 7주

- **뜻** : 젤리 위에 얹힌 작은 돌가루 — 기울거나 가속하면 돌가루가 쏠려 «기울었다·출발했다» 신호
- **예** : 버스 출발 때 뒤로 쏠림 · 엘리베이터 출발 순간 몸이 무거워짐
- **왜** : 등속(일정한 속도)은 못 느낌 → VR 조이스틱 이동의 «눈은 움직임, 몸은 정지» 어긋남

### 이징

**이징** · *Easing* — 7주

- **뜻** : 출발·도착 근처에서 속도를 줄여 «부드럽게» 만드는 보간 방식 — 살살 출발하는 버스
- **예** : 문 열림 0.25초 시점 : 직선 22.5° vs 이징 약 14°
- **왜** : 없으면 출발·정지 순간 «쿵» → 로봇 같은 움직임 · 단 VR 카메라엔 오히려 해로움 (Part II)
- **어디서** : Unity 키 우클릭 → Flat · Figma · After Effects 의 Ease In/Out · CSS ease-in-out

### 인사이드아웃

**인사이드아웃** · *Inside-out tracking* — 11주

- **뜻** : 헤드셋에 달린 카메라가 안에서 바깥(방)을 보고 자기 위치를 알아내는 방식
- **예** : Quest 3 · 외부 장치 설치 없이 켜면 바로 사용
- **왜** : 설치가 필요 없는 대신 → 조명·벽 무늬 같은 방 환경에 성능이 좌우됨

### 인시

**인시** · *Person-hour* — 13주

- **뜻** : «한 사람이 한 시간 일한 양» 을 1 로 세는 작업량 단위
- **예** : 4명 × 2주 × 주 6시간 = 48 인시 · 그중 빌드·검증에 절반 → 순수 제작 약 24 인시
- **왜** : 기능 목록을 인시로 바꿔 보면 «2주 안에 될 일» 과 «안 될 일» 이 숫자로 갈림
- **어디서** : 이 덱 «범위 · 2» 손계산 · 팀별 실제 가능 시간으로 다시 계산

### 입력 모듈

**입력 모듈** · *Input Module* — 10주

- **뜻** : 마우스·컨트롤러 입력을 «포인터가 여기를 눌렀다» 로 번역하는 통역사
- **예** : 모니터 = InputSystemUIInputModule · VR = XR UI Input Module
- **왜** : 모니터용만 있으면 컨트롤러 버튼이 UI 에 전달되지 않음
- **어디서** : Unity : EventSystem 오브젝트의 인스펙터 컴포넌트 목록

### 입력 추상화

**입력 추상화** · *Input abstraction* — 10주

- **뜻** : 게임 코드는 «무엇을 하려는가» 만 알고, «어떤 버튼이었나» 는 설정 파일이 맡는 설계
- **예** : TV 리모컨 · 휴대폰 앱 · 본체 버튼 → TV 는 «채널 올림» 명령 하나만 받음
- **왜** : 다음 주 Quest 컨트롤러로 옮길 때 코드 수정 0 · 바인딩만 추가
- **어디서** : Unity : Input System 패키지 (Unity 6 새 프로젝트 기본값)

## ㅈ

### 자력계

**자력계** · *Magnetometer* — 11주

- **뜻** : 지구 자기장 방향을 재는 센서 — 휴대폰 지도 앱의 전자 나침반
- **예** : 북쪽을 보면 0° · 동쪽을 보면 90° 같은 절대 방향 제공
- **왜** : 좌우 회전 드리프트를 잡는 기준 후보 · 철골·스피커 자석 근처에서 쉽게 틀림 → 실내 헤드셋은 카메라 기준을 주로 사용 (기기마다 다름)

### 자세

**자세** · *Pose* — 11주

- **뜻** : 위치(어디에 서 있나) + 방향(어느 쪽을 보나) 두 가지를 한 묶음으로 부르는 말
- **예** : 위치 (0.2, 1.6, −0.1) m + 방향 «오른쪽으로 30°» = 자세 하나
- **어디서** : Inspector 의 Transform → Position · Rotation (2주차 그대로)

### 자세 불안정

**자세 불안정** · *Postural instability* — 7주

- **뜻** : 몸의 균형 제어가 흔들리는 상태 — 멀미를 설명하는 또 하나의 이론
- **예** : 멀미가 난 사람은 증상 이전부터 몸의 흔들림이 커짐 (Smart et al. 2002)
- **왜** : 서서 하는 VR 에서 시야 흔들기 = 균형 교란 → 앉은 자세·고정 기준점이 도움

### 자유도

**자유도** · *DoF · Degrees of Freedom* — 2주 · 다시 : 11주

- **뜻** : 몸이 서로 따로 움직일 수 있는 방향의 가짓수 — 고개 돌리기 3가지 + 몸 옮기기 3가지 = 6
- **예** : 회전 3 : 도리도리(yaw) · 끄덕끄덕(pitch) · 갸웃(roll) / 이동 3 : 좌우 · 위아래 · 앞뒤
- **왜** : 3DoF 기기는 몸을 숙여도 시점 그대로 → 가까운 물체가 얼굴에 «붙어 다니는» 어색함
- **어디서** : Tracked Pose Driver → Tracking Type : Rotation And Position(6DoF) · Rotation Only(3DoF)

### 자이로 · 가속도계

**자이로 · 가속도계** · *Gyroscope · Accelerometer* — 2주

- **뜻** : 자이로 = 초당 몇 도 도는지 · 가속도계 = 어느 쪽으로 얼마나 밀리는지(중력 포함) — 둘을 묶으면 IMU
- **예** : 책상 위 휴대폰 가속도계 = 아래로 약 9.8 m/s² (중력) · 고개를 90°/s 로 돌리면 자이로 90
- **어디서** : 헤드셋·컨트롤러 내부 · Unity 입력 deviceAngularVelocity · deviceAcceleration (기기마다 다름)

### 자이로스코프

**자이로스코프** · *Gyroscope* — 11주

- **뜻** : «지금 초당 몇 도로 돌고 있나» (회전 속도 · 각속도) 를 재는 센서 · 단위 °/s
- **예** : 1초 동안 고개를 오른쪽으로 90° 돌리면 → 90 °/s · 멈추면 0 °/s
- **왜** : 방향 = 이 값을 계속 더해서 구함 → 측정의 작은 어긋남도 같이 더해짐 → 드리프트의 원인

### 재투영

**재투영** · *Reprojection* — 1주 · 다시 : 11주, 12주

- **뜻** : 새 그림이 늦을 때 직전 그림을 최신 고개 방향에 맞춰 살짝 돌려 다시 보여 주는 응급 처치
- **예** : 90Hz 중 한 장을 못 그림 → 직전 프레임을 고개가 돈 만큼 밀어서 표시
- **왜** : 세상이 끌려오는 느낌(지연)을 줄임 · 대신 가장자리 일그러짐이 생기기도 함
- **어디서** : Meta : Asynchronous TimeWarp · Application SpaceWarp (이름·기본값은 버전마다 다름)

### 재현

**재현** · *Reproduce* — 8주

- **뜻** : 같은 조건을 만들어 같은 문제를 일부러 다시 일으켜 보이기 — «어제 고장 났어요» 대신 지금 눈앞에서 고장 내기
- **예** : fps 를 30 으로 고정 → 이동 속도가 느려지는 장면을 시연 중 다시 보여 줌
- **왜** : 재현 못 하는 문제는 고쳤는지도 확인 불가 → 함정 증명의 출발점

### 재현 절차

**재현 절차** · *Repro steps* — 9주

- **뜻** : 결함을 다시 일으키는 단계별 순서 — 누가 따라 해도 같은 증상이 나와야 함
- **예** : «Play → W 키 3초 → 벽에 돌진 → 10회 중 3회 통과»
- **왜** : 재현이 안 되면 AI 도 사람도 고쳤는지 판정 불가
- **어디서** : 증상 요약의 [조건] 칸 · 플레이북 4절 검증 조건

### 저더

**저더** · *Judder* — 12주

- **뜻** : 고개를 돌릴 때 세상이 머리에 끌려가다 툭 튀는 듯한 떨림 — 같은 그림이 두 번 표시된 결과
- **예** : 90 Hz 에서 한 프레임 놓침 → (재투영이 없다면) 같은 그림이 22.2 ms 동안 머무름 → 그 사이 고개는 계속 회전
- **왜** : 모니터에서는 «끊김» 정도지만 VR 에서는 눈과 귀의 보고가 어긋나 멀미로 이어짐
- **어디서** : 헤드셋 안에서 고개를 좌우로 빠르게 돌릴 때 체감 · OVR Metrics 놓친 프레임 수

### 저장소 · push

**저장소 · push** · *Repository · Push* — 1주

- **뜻** : 저장소 = 커밋 기록이 쌓이는 프로젝트 폴더 · push = 내 컴퓨터의 커밋을 인터넷(GitHub) 저장소로 올리기
- **예** : git push -u origin main → github.com/내아이디/PerceptionLab 에 파일 표시
- **왜** : 노트북이 고장 나도 GitHub 에 사본 · 과제 제출 = 이 저장소 주소

### 전단

**전단** · *Shear* — 2주

- **뜻** : 직사각형의 윗변을 옆으로 밀어 평행사변형으로 만드는 변형 — 쌓아 둔 책 더미를 옆으로 밀기
- **예** : 90° 였던 네 각이 37° · 143° 로 바뀜 (다음 장 도해)
- **왜** : Transform 에는 «전단» 칸이 없음 → 부모 스케일 × 자식 회전 조합에서만 몰래 생김 → 원인 찾기 어려움
- **어디서** : 빈 부모(Create Empty)를 사이에 두어 «부모에서 회전, 자식에서 스케일»로 분리

### 전역조명

**전역조명** · *Global Illumination · GI* — 5주

- **뜻** : 광원에서 바로 온 빛 + 여러 번 튕긴 간접광까지 «장면 전체(전역)» 를 따져 계산하는 조명
- **예** : 창 하나뿐인 방 : 직접광만 → 창가 바닥만 밝은 사각형 · GI → 벽·천장까지 은은하게 밝음
- **왜** : GI 가 빠진 실내 = 무대 조명 같은 인상 · 매 프레임 계산은 너무 비쌈 → VR 은 베이크로 해결
- **어디서** : Unity : Window → Rendering → Lighting → Scene 탭 → Baked Global Illumination · Generate Lighting

### 전이

**전이** · *Transition* — 10주

- **뜻** : 어떤 사건(이벤트)이 오면 다른 상태로 넘어가는 규칙 — «A 에서 X 가 오면 B 로»
- **예** : Playing 에서 Esc → Paused · Paused 에서 Esc → Playing · Menu 에서 Esc → 변화 없음
- **왜** : 규칙에 없는 전이는 일어나지 않음 → «죽었는데 일시정지 메뉴가 뜨는» 조합 차단
- **어디서** : 코드 : SetState(next) 함수 하나 · Animator 창의 상자 사이 화살표

### 전정계

**전정계** · *Vestibular system* — 1주 · 다시 : 2주, 3주, 7주, 9주, 12주, 13주

- **뜻** : 속귀 안에서 머리의 기울기와 속도의 변화(가속)를 느끼는 기관 — 몸 안의 «수평계 + 가속도계»
- **예** : 엘리베이터가 출발·정지할 때만 몸이 쑥 꺼지는 느낌 → 등속 구간에서는 거의 못 느낌
- **왜** : 눈은 «움직인다», 전정계는 «가만있다» 로 보고가 엇갈리면 멀미 → VR 이동 설계의 핵심 제약
- **어디서** : 12주 함정 #9 (가속 이동) · 기획서 ② 지각적 근거에 자주 등장하는 원리

### 절두체

**절두체** · *Frustum* — 4주

- **뜻** : 카메라에 찍힐 수 있는 공간 전부 — 꼭대기를 잘라낸 피라미드 모양 유리 상자
- **예** : 시야각 60° · near 0.3 · far 1000 → 앞벽 높이 약 35 cm · 뒷벽 높이 약 1.15 km
- **왜** : 상자 밖 물체는 그리지 않음 → 성능의 출발점 · 상자 모양 = 투영 행렬
- **어디서** : Scene 뷰에서 Camera 선택 시 보이는 흰 선 피라미드

### 접선

**접선** · *Tangent* — 7주

- **뜻** : 키프레임에서 곡선이 출발하는 기울기 = 그 순간의 속도 — 비탈길의 경사
- **예** : 접선 0 = 키에서 멈춘 상태 · 접선 20 = 키에서 초당 20 씩 변하며 출발
- **왜** : 모르면 «키마다 멈칫» 하는 움직임의 원인(전부 Flat 접선)을 못 찾음
- **어디서** : Curves 탭에서 키 선택 시 양쪽 핸들 · 우클릭 → Free Smooth · Broken

### 접촉 그림자

**접촉 그림자** · *Contact shadow* — 5주

- **뜻** : 물체가 바닥에 닿는 지점 바로 아래 생기는 짙고 좁은 그림자 — «여기 붙어 있음» 표시
- **예** : 책상 위 컵 밑의 진한 테두리 · 컵을 1 cm 들어 올리면 그림자와 컵 사이 틈이 생김
- **왜** : 없으면 물체가 바닥에서 떠 보임 → VR 에서 잡기·놓기 위치 판단 오류
- **어디서** : Unity : 물체 밑에 흐린 원판 텍스처를 붙인 Quad 1장 (가장 싼 방법) · 베이크 AO 로도 일부 표현

### 정규화

**정규화** · *Normalize* — 2주 · 다시 : 5주

- **뜻** : 방향은 그대로 두고 길이만 1 로 맞추는 계산 — 화살표를 «표준 길이 자» 에 맞춰 자르기
- **예** : (3, 4, 0) 의 길이 5 → 각 칸 ÷ 5 → (0.6, 0.8, 0) · 방향 같음 · 길이 1
- **왜** : 길이 1 이 아니면 내적 ≠ cos θ → 길이 2 짜리 화살표는 밝기 2배라는 엉뚱한 결과
- **어디서** : Unity : C# vector.normalized · Shader Graph 의 Normalize 노드

### 정반사

**정반사** · *Specular* — 5주

- **뜻** : 빛이 거울처럼 한 방향으로 튕기는 반사 — 반짝이는 하이라이트 · 보는 위치 따라 이동
- **예** : 당구공의 흰 반짝임 점 → 고개를 옮기면 점도 공 위에서 따라 움직임
- **왜** : 재질감(광택·금속)의 주된 단서 — 빠지면 모든 물체가 종이처럼 보임
- **어디서** : Unity URP Lit : Smoothness 슬라이더 · Advanced Options → Specular Highlights

### 정점

**정점** · *Vertex* — 1주 · 다시 : 4주

- **뜻** : 3D 모델을 이루는 꼭짓점 하나 — 위치뿐 아니라 색 · 법선 · UV 를 함께 적은 «점 카드»
- **예** : 정육면체 = 꼭짓점 8개지만 면마다 법선이 달라 Unity 에서는 정점 24개
- **왜** : 정점 셰이더가 정점마다 한 번씩 실행 → 정점 수 = 계산 비용의 한 축
- **어디서** : Game 뷰 Stats 의 Verts · 메시 Inspector 아래 미리보기의 Vertices 수

### 정점 법선

**정점 법선** · *Vertex normal* — 5주

- **뜻** : 한 꼭짓점을 공유하는 면들의 법선을 평균 낸 법선 — 면 사이 경계를 «사포로 문지른» 효과
- **예** : 면 법선 (0, 1, 0) 과 (1, 0, 0) 이 만나는 꼭짓점 → 평균 후 정규화 ≈ (0.71, 0.71, 0)
- **왜** : 면 수를 늘리지 않고도 둥근 표면처럼 보이게 함 → 삼각형 예산 절약 (VR 에 중요)
- **어디서** : Unity : Import Settings → Normals · Smoothing Angle (기본 60°) · Blender 의 Shade Smooth

### 정점 셰이더

**정점 셰이더** · *Vertex shader* — 6주

- **뜻** : 꼭짓점 하나마다 한 번 실행 → 그 점이 화면 어디에 찍힐지 계산 — 자리 잡기 담당
- **예** : 꼭짓점 24개 → 24회 실행 · 출력 = 화면 좌표 + 다음 공정에 넘길 UV·법선
- **왜** : 실행 횟수가 적은 싼 자리 → 픽셀마다 같은 계산은 여기로 옮겨 비용 절감
- **어디서** : Shader Graph 마스터 스택의 Vertex 블록 (Position · Normal · Tangent)

### 조절

**조절** · *Accommodation* — 5주 · 다시 : 10주, 12주

- **뜻** : 거리에 맞춰 수정체 두께를 바꿔 초점을 맞추는 작용 — 카메라 렌즈의 «자동 초점»
- **예** : 책을 보다 창밖을 보면 잠깐 흐렸다가 선명해짐 = 조절이 다시 맞춰지는 시간
- **왜** : HMD 화면은 렌즈로 일정 거리에 고정된 상 → 가까운 물체든 먼 물체든 초점은 같은 자리
- **어디서** : Quest 3 : 렌즈 초점 거리 고정 (정확한 값은 기기마다 다름 · 대략 1~2 m 대)

### 조절-수렴 충돌

**조절-수렴 충돌** · *Vergence-accommodation conflict* — 10주 · 다시 : 12주

- **뜻** : 원래 함께 움직이는 초점(조절)과 모임(수렴)이 서로 다른 거리를 가리키는 상태 (5주차)
- **예** : 초점 약 1.5 m 고정 · 글자 패널 0.3 m → 수렴은 0.3 m · 조절은 1.5 m
- **왜** : 눈 피로 · 글자 겹쳐 보임 · SSQ O 묶음 상승 → 오래 보는 UI 는 약 1 m 이상
- **어디서** : World Space Canvas 의 위치 (리그에서의 거리) · 손 메뉴는 짧게 쓰는 조작만

### 조합

**조합** · *Composition* — 3주

- **뜻** : 설계도를 늘리지 않고 부품을 골라 붙여 기능 구성 — 레고 방식
- **예** : 걷기·날기·헤엄 3개 + 공격 4개 = 부품 7개로 12가지 적 전부
- **어디서** : Inspector 의 부품 목록 자체 · Add Component 로 붙이고 ⋮ → Remove Component 로 떼기

### 좌표계

**좌표계** · *Local · World · View* — 1주 · 다시 : 2주

- **뜻** : 위치를 말할 때의 «기준점» — 물체 자신 기준(로컬) · 씬 전체 기준(월드) · 카메라 기준(뷰)
- **예** : 로컬 (0, 0.5, 0) 인 점 + 의자를 월드 (3, 0, 2) 에 배치 → 월드 (3, 0.5, 2)
- **어디서** : Unity : Inspector 의 Transform Position = 부모 기준 값 · Scene 뷰 툴바 Local / Global 전환

### 좌표계 체인

**좌표계 체인** · *Coordinate chain* — 2주

- **뜻** : 월드 → 리그 → 카메라 → 눈으로 이어지는 부모-자식 사슬 — 계층 · 2 의 행렬 곱 연쇄 그대로
- **예** : 리그를 앞으로 1 m 옮기면 사슬 끝의 두 눈도 함께 1 m 이동
- **어디서** : Hierarchy : XR Origin → Camera Offset → Main Camera

### 주변시

**주변시** · *Peripheral vision* — 6주

- **뜻** : 시선 중심 바깥의 넓은 시야 — 흐릿하지만 움직임·깜빡임에 민감한 경비원
- **예** : 책을 읽는 중에도 옆에서 날아드는 벌레는 바로 알아챔
- **왜** : 쳐다보지 않은 먼 바닥의 반짝임까지 거슬리는 이유
- **어디서** : 헤드셋 렌즈 가장자리 영역 = 고정 포비티드 렌더링이 해상도를 낮추는 구역

### 주사율

**주사율** · *Refresh rate · Hz* — 3주 · 다시 : 12주

- **뜻** : 디스플레이가 1초에 그림을 몇 번 바꾸는지 — 플립북을 1초에 몇 장 넘기는가
- **예** : Quest 3 : 72 · 90 · 120 Hz 선택 가능 · 수업 기준 90 Hz = 1초에 그림 90장
- **왜** : 주사율을 올리면 매끄러워지지만 한 장당 시간(예산)이 줄어듦 → 같은 씬이 갑자기 초과
- **어디서** : OpenXR Meta Quest 기능 설정 또는 스크립트 요청 · 실제 값은 OVR Metrics 에 표시 (버전마다 다름)

### 주파수

**주파수** · *Frequency* — 6주

- **뜻** : 일정 거리·시간 안에서 무늬가 반복되는 횟수 — 촘촘할수록 «고주파»
- **예** : 화면 100 픽셀 안에 흰·검 쌍 10개 = 10 픽셀마다 1주기
- **왜** : 같은 무늬도 멀어질수록 화면에서 촘촘해짐 → 거리만으로 주파수 상승
- **어디서** : 바닥 Tiling 값을 올리거나 카메라를 멀리 두면 → 둘 다 화면상 주파수 상승

### 중간 망각

**중간 망각** · *Lost in the middle* — 9주

- **뜻** : 긴 컨텍스트에서 앞·뒤 정보는 잘 쓰고 가운데 정보는 덜 쓰는 경향 (Liu 외, 2024)
- **예** : 긴 대화 중간에 말한 «Linear 색공간» 제약이 어느새 무시됨
- **왜** : 중요한 제약은 규칙 파일이나 질문 끝에 다시 적어야 안전 · 정도는 모델마다 다름

### 중심와

**중심와** · *Fovea* — 1주 · 다시 : 5주, 6주

- **뜻** : 망막 한가운데 가장 선명하게 보는 작은 영역 (시야 중심 약 2°) — 팔 뻗은 엄지손톱 정도 크기
- **예** : 이 문장의 한 글자를 보면 옆 줄은 이미 흐림 → 선명한 곳은 시선이 닿은 아주 좁은 범위
- **왜** : 시야 가장자리는 덜 선명하게 그려도 티가 덜 남 → 렌더링 비용 절약 기법의 근거
- **어디서** : Quest : 고정 포비티드 렌더링(가장자리 해상도 낮추기) · Unity OpenXR Meta 설정에서 지원 (버전마다 다름)

### 지각

**지각** · *Perception* — 1주

- **뜻** : 눈·귀로 들어온 신호를 뇌가 해석해 «무엇이 어디에 있다» 고 알아차리는 과정 — 받은 그대로가 아니라 추론
- **예** : 같은 (118, 118, 118) 회색 두 칸이 그림자 때문에 다른 밝기로 보임 (오늘 착시 실험)
- **왜** : VR 은 화면 숫자가 아니라 뇌의 해석을 설계하는 일

### 지각 실험실

**지각 실험실** · *Perception Lab* — 8주

- **뜻** : 2주부터 각자 키워 온 씬 — 예쁜 작품이 아니라 개념을 하나씩 켜고 끄며 확인하는 실험대
- **예** : 한 씬 안에 부모-자식 회전 · 그림자 · 밉맵 바닥 · 이동 스크립트 2종
- **왜** : 11주차에 이 씬을 Quest 3 로 옮겨 직접 들어감 → 오늘이 VR 진입 전 점검

### 지각·컴포트 근거

**지각·컴포트 근거** · *Perceptual rationale* — 15주

- **뜻** : 설계 결정을 지각 원리 + 측정 숫자로 설명할 수 있는 정도 (기획서 ② ③)
- **예** : «스냅 회전 22.5° 사용 → 시야 흐름(벡션) 감소 → 14주 SSQ 전후 차이 작음»
- **왜** : 25점 · «느낌상 편해요» 는 근거로 불인정

### 지각적 근거

**지각적 근거** · *Perceptual rationale* — 13주

- **뜻** : «이 설계가 왜 편안·자연스러운가» 를 사람의 지각 원리로 설명한 문장 — 설계 결정의 «이유서»
- **예** : «회전 = 스냅 턴 22.5° — 회전 중 시야 흐름이 벡션을 만들기 때문 (7·12주) · SSQ 로 확인»
- **왜** : 채점 «설계 근거 25점» 의 직접 대상 → «보기 좋게» «자연스럽게» 만 있는 문장은 근거로 인정 안 됨
- **어디서** : 기획서 ② 항목 · 표 형식 : 설계 결정 / 지각 원리 / 주차 / 측정

### 지식의 저주

**지식의 저주** · *Curse of knowledge* — 14주

- **뜻** : 이미 아는 사람은 모르는 상태를 상상하지 못하는 현상 — 내 글의 오타가 안 보이는 이유
- **예** : 만든 사람 1분 · 처음 체험자 5분째 같은 자리 (도입 질문)
- **왜** : 만든 사람의 «쉽다» 는 판단은 근거가 못 됨 → 다른 팀이 체험해야 하는 이유

### 지연

**지연** · *Latency* — 3주

- **뜻** : 원인(움직임·입력)과 결과(화면 변화) 사이의 시간 차 — 생방송이 몇 초 늦게 나오는 것
- **예** : 버튼을 누르고 0.1초(100ms) 뒤 캐릭터가 점프 = 지연 100ms
- **왜** : fps 가 높아도 지연이 길면 «매끄럽지만 늦은» 화면 — VR 에서는 멀미

### 짐벌락

**짐벌락** · *Gimbal lock* — 2주 · 다시 : 9주

- **뜻** : 세 회전축 중 두 축이 한 줄로 겹쳐 한 방향 회전을 잃는 상태 — 손잡이는 셋인데 실제로는 둘만 움직임
- **예** : Inspector Rotation X = 90 으로 두고 Y 와 Z 를 각각 바꿔 보면 → 둘 다 같은 방향으로 돎
- **왜** : 오일러각을 누적하는 회전 코드가 이 자세 근처에서 갑자기 튀거나 멈춤 → VR 에서는 화면이 홱 돌아 멀미
- **어디서** : Inspector Transform → Rotation 칸 · 코드 transform.eulerAngles 를 더해 가는 곳

### 축소

**축소** · *Minification* — 6주

- **뜻** : 화면 픽셀 하나가 텍셀 여러 개를 덮는 상황 — 멀리 있거나 비스듬히 본 면
- **예** : 먼 바닥 픽셀 1개 = 텍셀 16 × 16 = 256개 영역
- **왜** : 256개 중 몇 개만 읽으면 결과가 흰↔검 사이에서 널뜀 → 반짝임
- **어디서** : Scene 뷰 Draw Mode → Mipmaps : 빨강 = 텍스처가 화면 대비 과함 · 파랑 = 부족

### 침투 해소

**침투 해소** · *Depenetration* — 7주

- **뜻** : 이미 겹쳐 버린 두 물체를 엔진이 가장 가까운 바깥쪽으로 밀어내는 처리
- **예** : 공이 벽에 0.067 m 파고듦 → 다음 물리 스텝에서 0.067 m 밀려 나옴
- **왜** : 파고든 깊이가 크면 «가장 가까운 바깥» 이 벽 뒤 → 벽 통과로 이어짐
- **어디서** : Project Settings → Physics → Default Max Depenetration Velocity (밀어내는 최대 속도)

### 칼만 필터

**칼만 필터** · *Kalman filter* — 11주

- **뜻** : 각 값이 «지금 얼마나 믿을 만한가» (불확실성)를 숫자로 계산해 섞는 비율을 매 순간 자동으로 정하는 필터

- **어디서** : Photoshop 필터 → 기타 → 오프셋 으로 이음매 점검 · 재질 라이브러리 소재 대부분 타일러블

### 타일링

**타일링** · *Tiling* — 6주

- **뜻** : UV 에 배수를 곱해 같은 그림을 여러 번 반복해 붙이기 — 작은 벽지 한 장을 이어 붙여 벽 전체 덮기
- **예** : Tiling (4, 4) → 바닥 한 면에 그림 16장
- **왜** : 반복이 많을수록 멀리서 한 픽셀에 무늬 여러 장이 겹침 → 반짝임 재료
- **어디서** : URP Lit 재질 Inspector → Base Map 아래 Tiling · Shader Graph Tiling And Offset 노드

### 타임라인

**타임라인** · *Timeline* — 7주

- **뜻** : 여러 물체의 움직임·소리·카메라를 하나의 시간표에 배치하는 Unity 도구 — 영상 편집기 트랙
- **예** : 0초 조명 켜짐 → 2초 문 열림 → 3초 안내 음성 = 전시 오프닝 한 편
- **왜** : 카메라(사용자 시점) 트랙 = 사용자 의사와 무관한 이동 → VR 멀미 원인
- **어디서** : Window → Sequencing → Timeline · Playable Director 컴포넌트

### 타임스텝

**타임스텝** · *Timestep, Δt* — 7주

- **뜻** : 물리 계산 한 번의 간격 — 메트로놈 박자
- **예** : Unity 기본 0.02초 = 초당 50번 · 90Hz 화면에 맞추면 1/90 ≈ 0.0111초
- **왜** : 크면 벽 통과·적분 오차 증가 · 작으면 물리 계산량 증가
- **어디서** : Project Settings → Time → Fixed Timestep · 코드 Time.fixedDeltaTime

### 타임워프

**타임워프** · *Timewarp* — 4주

- **뜻** : 그림을 다 그린 뒤 내보내기 직전, 그사이 돌아간 머리 방향만큼 그림을 살짝 밀어 맞추는 보정
- **예** : 그리는 동안 머리가 오른쪽으로 1° 회전 → 내보내기 직전 그림을 1° 만큼 이동
- **왜** : 세상이 머리보다 늦게 따라오는 느낌(멀미 원인) 감소 · 11주 motion-to-photon 에서 다시

### 탄젠트 공간

**탄젠트 공간** · *Tangent space* — 6주

- **뜻** : 표면의 각 점에 세운 작은 좌표계 T · B · N — 손바닥에 붙인 스티커의 «위쪽» 은 손을 뒤집어도 손바닥 기준
- **예** : 노멀맵 값 (0.71, 0, 0.71) = T 쪽으로 45° 기울어진 법선
- **왜** : 메시에 탄젠트 정보가 없거나 틀리면 요철이 엉뚱한 방향으로 비침
- **어디서** : 모델 Import Settings → Model 탭 → Tangents (Calculate Mikktspace 등)

### 터널링

**터널링** · *Tunneling* — 3주 · 다시 : 7주

- **뜻** : 빠른 물체가 한 스텝 사이에 얇은 벽을 건너뛰는 현상 — 개울보다 큰 보폭의 징검다리
- **예** : 30 m/s × 0.02초 = 한 번에 0.6 m 순간이동 → 벽 0.2 m + 공 0.2 m 를 통째로 건너뜀
- **왜** : 시작 위치에 따라 됐다 안 됐다 하는 «운에 맡긴 버그» → 한 번 테스트로는 못 찾음
- **어디서** : 던진 물체 · 총알 · 대시 이동 · 빠르게 휘두른 컨트롤러

### 텍스처 · 텍셀

**텍스처 · 텍셀** · *Texture · Texel* — 6주

- **뜻** : 표면에 입히는 그림 파일 · 그 그림을 이루는 칸 하나 — 화면 칸(픽셀)과 구분하려고 따로 부르는 이름
- **예** : 1024 × 1024 텍스처 = 텍셀 약 105만 개 · 화면 픽셀 수와 무관
- **왜** : «픽셀 하나가 텍셀 몇 개를 덮는가» = 오늘 반짝임 문제의 핵심 비율
- **어디서** : Project 창에서 이미지 선택 → Inspector 하단 미리보기에 해상도 표시

### 텔레포트

**텔레포트** · *Teleport* — 2주 · 다시 : 13주

- **뜻** : 가리킨 지점으로 화면 전환 없이 «순간이동» 하는 이동 방식 — 걷는 도중의 흐름 자체를 없앰
- **예** : 컨트롤러 스틱을 앞으로 → 바닥에 포물선 표시 → 놓으면 그 자리로 즉시 이동
- **왜** : 시야 흐름(벡션)과 가속이 0 → 전정계와 눈의 충돌이 없음 · 대신 «어디로 왔지?» 방향 상실 주의

- **예** : 영어 약 4글자 ≈ 1토큰 · C# 스크립트 200줄 ≈ 2,000~3,000토큰
- **왜** : 요금 · 사용량 한도 · 한 번에 볼 수 있는 양이 모두 토큰으로 계산
- **어디서** : 도구 화면의 토큰 사용량 표시 · OpenAI Tokenizer 웹 페이지에서 직접 세어 보기

### 투영

**투영** · *Projection* — 2주

- **뜻** : 한 화살표를 다른 화살표 위에 그림자처럼 눕힌 것 — «저 방향으로 따지면 얼마만큼인가»
- **예** : 길이 1 막대 b = (0.6, 0.8, 0) 을 바닥선 a = (1, 0, 0) 위에 눕히면 그림자 길이 0.6
- **왜** : 경사면 미끄러짐·벽 따라 미끄러지기·«앞으로 얼마나 다가왔나» 계산이 전부 투영

- **예** : 시야각 60° · 종횡비 16:9 · near 0.3 · far 1000 → 이 네 숫자로 16칸 행렬 완성
- **왜** : VR 에서는 헤드셋이 눈마다 다른 행렬을 넣음 → 코드로 덮어쓰면 입체 붕괴

### 트래킹

**트래킹** · *Tracking* — 1주 · 다시 : 2주, 11주

- **뜻** : 머리·손이 지금 어디에 있고 어느 쪽을 보는지 매 순간 재서 가상 카메라에 넘기는 일 — 몸에 붙은 실시간 GPS
- **예** : Quest 3 : 1초에 수백~1000번 머리 방향 측정 → 화면 1장(90Hz)마다 최신값을 카메라에 넣음
- **왜** : 트래킹 값이 틀리면 세상이 아니라 «내 눈의 자리» 가 틀림 → 세상 전체가 미끄러져 보임
- **어디서** : Unity : Main Camera 에 붙은 Tracked Pose Driver 가 이 값을 받음

### 트래킹 원점

**트래킹 원점** · *Tracking origin mode* — 11주

- **뜻** : 트래킹 좌표의 «높이 0» 을 실제 바닥(Floor)에 둘지 앱을 켠 순간의 헤드셋 위치(Device)에 둘지 정하는 설정
- **예** : Floor : 눈높이 1.63 m 그대로 · Device : 0 + 1.1176 m = 1.12 m
- **어디서** : XR Origin 컴포넌트 → Tracking Origin Mode (Not Specified · Device · Floor)

### 트래킹 원점 모드

**트래킹 원점 모드** · *Tracking Origin Mode* — 2주

- **뜻** : 헤드셋이 재는 좌표의 0 을 어디에 둘지 정하는 설정 — 키를 «바닥부터» 잴지 «머리부터» 잴지
- **예** : Floor : 서 있는 사람 머리 y ≈ 1.7 m · Device : 시작 순간 머리 y = 0
- **왜** : 잘못 고르면 사용자가 바닥에 파묻히거나 공중에 뜸 — 코드 한 줄 없이 생기는 사고
- **어디서** : XR Origin 컴포넌트 → Tracking Origin Mode (Not Specified / Device / Floor)

### 트랜스폼

**트랜스폼** · *Transform* — 3주

- **뜻** : 위치·회전·크기 · 모든 게임오브젝트에 반드시 1개, 뗄 수 없음
- **예** : Rotation Y 를 0 → 90 으로 바꾸면 물체가 위에서 볼 때 시계 방향 90° 회전
- **왜** : 부모가 있으면 여기 숫자는 부모 기준 — 값이 이상해 보이면 부모부터 확인
- **어디서** : Inspector 맨 위 칸 · 칸 오른쪽 ⋮ 메뉴 → Reset 으로 0 · 0 · 1 초기화

- **예** : 좋음 : 책상 모서리 · 포스터 글자 · 콘센트 / 나쁨 : 흰 벽 한가운데 · 빈 바닥
- **왜** : 점이 적으면 위치 계산 실패 → 흰 벽 앞에서 위치가 미끄러지는 이유
- **어디서** : 직접 볼 수는 없음 · 실습실 흰 벽 앞에 포스터·테이프 표시를 붙이면 트래킹 안정

### 프래그먼트 셰이더

**프래그먼트 셰이더** · *Fragment shader* — 6주

- **뜻** : 삼각형이 덮는 픽셀 후보마다 한 번 실행 → 그 픽셀이 무슨 색일지 계산 — 색칠 담당
- **예** : 화면 300 × 300 픽셀 차지 → 약 90,000회 실행
- **왜** : VR 비용 대부분이 여기 — 두 눈 × 높은 해상도 × 90 Hz 로 곱해짐
- **어디서** : Shader Graph 마스터 스택의 Fragment 블록 (Base Color · Normal · Alpha …)

### 프러스텀 컬링

**프러스텀 컬링** · *Frustum culling* — 4주

- **뜻** : 절두체(카메라 상자) 밖에 있는 물체 전체를 그리기 전에 제외
- **예** : 시야각 60° 카메라 → 왼쪽 90° 방향의 의자는 그리기 목록에서 빠짐
- **왜** : Unity 가 물체 단위로 자동 수행 → 씬 전체를 메시 하나로 합치면 일부만 보여도 통째로 그려야 함
- **어디서** : 자동 · 결과는 Game 뷰 Stats 의 Batches · Frame Debugger 그리기 목록에서 확인

### 프레임

**프레임** · *Frame* — 1주 · 다시 : 3주

- **뜻** : 화면에 한 번 그려지는 정지 그림 한 장 — 플립북의 종이 한 장 · 1초에 몇 장인가 = fps · 모자라면 끊김
- **예** : 90 fps = 1초에 90장 → 한 장에 쓸 수 있는 시간 약 11.1 ms
- **어디서** : Unity : Game 뷰 오른쪽 위 Stats 버튼 → FPS · ms 표시

### 프레임 드랍

**프레임 드랍** · *Frame Drop* — 3주

- **뜻** : 제한 시간 안에 그림을 완성하지 못해 한 장을 놓치는 현상 — 짐을 못 싣고 떠난 버스
- **왜** : 모니터에선 잠깐 끊김, VR 에선 고개를 돌릴 때 세상이 덜컥 → 어지럼
- **어디서** : Quest : OVR Metrics Tool 의 스테일 프레임 수 (14주차에 실측)

### 프레임 예산

**프레임 예산** · *Frame budget* — 3주 · 다시 : 12주

- **뜻** : 그림 한 장을 완성하는 데 쓸 수 있는 최대 시간 — 시험 한 문제에 주어진 제한 시간
- **예** : 90 Hz → 1000 ÷ 90 ≈ 11.1 ms · 72 Hz → 13.9 ms · 120 Hz → 8.3 ms
- **왜** : 한 번이라도 넘기면 같은 그림이 두 번 나감 → 화면 튐(저더) → 멀미 위험
- **어디서** : 헤드셋 OVR Metrics Tool 의 프레임 시간 · Unity Profiler CPU/GPU ms

### 프레임률 종속

**프레임률 종속** · *Frame-rate dependent* — 3주

- **뜻** : 게임 속 속도가 PC 의 fps 에 따라 달라지는 결함
- **예** : 매 프레임 5cm 이동 → 30fps 노트북 초당 150cm · 120fps 데스크톱 초당 600cm
- **왜** : 개발자 PC 에서는 정상처럼 보여 화면만으로는 발견 어려움 — fps 를 바꿔 재야 드러남

### 프레임타임

**프레임타임** · *Frame time* — 5주 · 다시 : 9주

- **뜻** : 화면 한 장을 그리는 데 걸린 시간 (ms) — fps 의 뒤집은 값 · «한 장당 마감 시간»
- **예** : 90Hz → 1000 ÷ 90 ≈ 11.1 ms · 그림자 추가로 13.8 ms 가 되면 → 약 72 fps 로 떨어짐
- **왜** : fps 평균만 보면 가끔 튀는 느린 프레임이 숨음 → ms 로 보면 «마감 초과» 가 바로 보임
- **어디서** : Unity : Window → Analysis → Profiler · Game 뷰 Stats (에디터 기준이므로 참고만)

- **예** : 바닥의 한 점 : 머리 위 하늘 · 옆 벽 · 천장 등 들어오는 방향이 무한히 많음 → 전부 합산

- **예** : 영수증 한 줄 = 단가 \(f\) × 수량 \(L_i\) × 할인율 cos θ → 비스듬히 들어온 빛은 «할인» 되어 덜 기여

- **예** : Device 모드에서 Camera Y Offset 1.1 m → 머리가 0 이 아니라 앉은키 높이에서 시작

### canceled

### CCD

**CCD** · *Continuous Collision Detection* — 7주 · 다시 : 9주

### cos θ

**cos θ** · *cosine · 코사인* — 2주

- **뜻** : 두 화살표 사이 각도 θ 를 −1 ~ 1 숫자로 바꾼 값 — 반지름 1 원 위 점의 가로 위치
- **예** : cos 0° = 1 (같은 방향) · cos 30° ≈ 0.866 · cos 60° = 0.5 · cos 90° = 0 · cos 180° = −1
- **왜** : 길이 1 인 두 벡터의 내적 = cos θ → 각도를 따로 구하지 않고 숫자 비교만으로 «시야 안» 판정
- **어디서** : Mathf.Cos 는 라디안을 받음 → 도(°) 는 Mathf.Deg2Rad 를 곱해 넣기

### deltaTime

- **어디서** : 코드 : jump.started += … · Input Debugger 의 Phase 열 «Started»

### State

**State** · *상태* — 7주

- **뜻** : 지금 재생 중인 동작 하나 — 노선도의 역 하나
- **예** : Idle(가만히) · Walk · Jump 가 각각 상자 하나 · 한 번에 하나만 켜짐
- **왜** : 상태의 Motion 칸에 클립을 연결하지 않으면 그 상태에선 아무 동작도 안 나옴
- **어디서** : Animator 창 (Window → Animation → Animator) 의 상자 · 기본 상태는 주황색

### Teleportation Anchor

**Teleportation Anchor** · *정류장형 착지점* — 11주

- **뜻** : 정해진 한 지점으로만 착지시키는 «정류장» — 도착 후 바라볼 방향까지 지정
- **예** : 관찰 지점 3곳 · 앵커 판 어디를 겨눠도 중심에 서서 지정한 방향을 보며 도착
- **왜** : 관찰 위치·시선을 수업 의도대로 고정 → 학생마다 같은 장면을 비교 가능

### Teleportation Area

**Teleportation Area** · *착지 가능 바닥* — 11주

- **뜻** : «이 바닥 어디든 착지 가능» 으로 지정하는 컴포넌트 — 착지점 = 레이가 맞힌 자리
- **예** : 실험실 바닥 Plane 에 추가 → 레이 끝이 닿는 곳마다 착지
- **어디서** : 바닥 오브젝트(Collider 필요) → Add Component → Teleportation Area · Interaction Layer Mask = Teleport

### Teleportation Provider

**Teleportation Provider** · *이동 담당자* — 11주

- **뜻** : 텔레포트 요청을 받아 실제로 XR Origin 을 옮기는 담당 컴포넌트
- **예** : 내 코드 : QueueTeleportRequest(목적지 · 방향) 호출 → 다음 처리 시점에 리그 이동
- **왜** : 카메라 대신 이 담당자에게 요청 → 함정 #8 원천 차단

### Tracked Device Graphic Raycaster

**Tracked Device Graphic Raycaster** — 12주

- **뜻** : 컨트롤러 광선이 UI 버튼에 닿았는지 판정해 주는 부품 — 마우스 대신 레이저로 클릭
- **예** : 광선이 «시작» 버튼에 닿음 → 버튼 강조 → 트리거 → OnClick 실행
- **왜** : 빠지면 패널은 보이는데 광선 클릭이 전혀 안 먹힘 · 흔한 «UI 무반응» 원인
- **어디서** : Canvas → Add Component → Tracked Device Graphic Raycaster · EventSystem 에 XR UI Input Module

### Tracked Pose Driver

**Tracked Pose Driver** · *Input System 패키지* — 11주

- **뜻** : 헤드셋·컨트롤러가 잰 자세를 매 프레임 자기 Transform 에 받아 적는 컴포넌트
- **예** : Main Camera 에 붙어서 localPosition (0.2, 1.6, −0.1) 처럼 실제 머리값을 기록
- **왜** : 이 컴포넌트가 쓰는 Transform 에 내 코드도 쓰면 → 덮어쓰기 경쟁 (함정 #8)
- **어디서** : Main Camera Inspector → Tracked Pose Driver (Input System) → Tracking Type · Update Type

### Tracking Origin Mode

**Tracking Origin Mode** · *추적 기준점* — 13주

- **뜻** : 헤드셋 위치를 «바닥 기준» 으로 잴지 «시작 위치 기준» 으로 잴지 정하는 설정
- **예** : Floor : 키 175 cm 체험자 → 눈높이 약 1.6 m 자동 · 앉으면 약 1.2 m 로 자동 변경
- **왜** : Device 모드 + 카메라 높이 고정 → 키·자세와 무관하게 같은 높이 → 바닥이 발밑에 안 맞음
- **어디서** : Unity XRI : XR Origin 컴포넌트 → Tracking Origin Mode = Floor (Not Specified · Device · Floor)

### Transition

**Transition** · *전이* — 7주

- **뜻** : 상태에서 상태로 넘어가는 화살표 · 넘어가는 동안 두 동작을 잠깐 섞음
- **예** : Idle → Walk 화살표 · Transition Duration 0.25 = 0.25초 동안 섞으며 바뀜
- **왜** : 화살표가 없으면 그 동작으로 절대 못 감 · 섞는 시간이 길면 반응이 굼뜸
- **어디서** : 상태 우클릭 → Make Transition · 화살표 선택 → Inspector 의 Conditions

### Trilinear

**Trilinear** · *삼선형* — 6주

- **뜻** : 위·아래 두 밉맵 레벨에서 각각 Bilinear 로 읽은 뒤 그 둘을 다시 섞는 필터 — 계단 대신 경사로
- **예** : LOD 2.3 → 레벨 2 값 × 0.7 + 레벨 3 값 × 0.3
- **왜** : 바닥에 흐림이 갑자기 바뀌는 띠(밉맵 경계선) 제거
- **어디서** : 텍스처 Inspector → Filter Mode = Trilinear (밉맵이 켜져 있어야 의미)

### Unity Hub

**Unity Hub** — 1주

- **뜻** : Unity 에디터 여러 버전과 프로젝트 목록을 한곳에서 관리하는 런처 — 게임 런처 같은 시작 화면
- **예** : Installs 탭 : 설치된 에디터 버전 · Projects 탭 : PerceptionLab 등 내 프로젝트
- **왜** : 프로젝트마다 맞는 에디터 버전이 다름 → 다른 버전으로 열면 변환 경고·깨짐

### UnityEvent

**UnityEvent** · *인스펙터 이벤트* — 10주

- **뜻** : 코드 대신 인스펙터에서 구독자를 끌어다 연결하는 이벤트 — 디자이너용 배선판
- **예** : Button 의 onClick : 오브젝트를 끌어 놓고 함수 이름 선택 → 클릭 시 실행
- **왜** : 인스펙터 연결은 코드 검색에 안 잡힘 → «누가 이 함수를 부르나» 추적이 어려움
- **어디서** : Unity : Button 인스펙터 맨 아래 On Click () 목록 → +

### Update

**Update** · *Update()* — 3주

- **뜻** : 매 프레임 1회 — 플립북 한 장마다 한 번씩 오는 큐
- **예** : 60fps 면 1초에 60번 · 30fps 면 1초에 30번 실행
- **왜** : 실행 횟수가 PC 마다 다름 → 이동량에 Time.deltaTime 을 곱해야 하는 이유 (뒤에서)
- **어디서** : 새 스크립트 템플릿에 빈 void Update() { } 기본 포함

### URP

**URP** · *Universal Render Pipeline* — 1주

- **뜻** : Unity 가 픽셀 색을 계산하는 방식 중 하나 — PC·모바일·Quest 를 모두 지원하는 범용 렌더링 «엔진 설정 묶음»
- **예** : Part I 의 파이프라인 다섯 단계를 실제로 실행하는 주체 = URP · 다른 갈래 : Built-in · HDRP
- **왜** : 파이프라인마다 재질·셰이더 이름이 다름 → AI 가 Built-in 기준 답을 주면 분홍색 재질 같은 오류
- **어디서** : Unity : Project Settings → Graphics → Default Render Pipeline 칸의 URP 에셋 · 이 수업 기준

### UV

**UV** · *UV coordinates* — 6주

- **뜻** : 3D 표면의 각 점이 그림의 어디를 가리키는지 적은 0~1 주소 — 상자 전개도 위 좌표
- **예** : UV (0.25, 0.75) + 1024 텍스처 → 텍셀 (256, 768)
- **왜** : UV 가 꼬이면 무늬가 늘어나거나 뒤집힘 · 이음매(seam) 위치도 UV 가 결정
- **어디서** : Shader Graph UV 노드 (Channel UV0) · 제작은 보통 Blender UV Editing 같은 모델링 툴

### UV 조각

**UV 조각** · *UV island* — 6주

- **뜻** : seam 으로 잘려 나온 전개도 한 덩어리 — 펼친 종이 위의 «섬»
- **예** : 십자형 전개도 = 조각 1개 · 여섯 면을 모두 따로 자르면 조각 6개
- **왜** : 조각 사이 간격이 좁으면 축소판(밉맵)에서 이웃 조각 색이 번져 들어옴
- **어디서** : Blender UV Editor → UV → Pack Islands (Margin = 조각 간격)

### VIO

**VIO** · *Visual-Inertial Odometry* — 11주

- **뜻** : 카메라 영상(시각)과 IMU(관성)를 묶어 «얼마나 어디로 움직였나» 를 계산하는 방법 — 시각-관성 주행거리 측정
- **예** : 카메라 수십 Hz + IMU 약 1000 Hz → 합쳐서 매 프레임 6DoF 자세
- **어디서** : Quest 의 트래킹 내부 (구현은 비공개) → 앱은 OpenXR 런타임이 주는 자세값만 사용

### VOR

**VOR** · *전정안구반사* — 10주

- **뜻** : 머리가 돌면 눈이 반대로 자동 회전해 세상을 고정해 보는 반사 — 몸에 내장된 손떨림 방지 (2주차 전정계)
- **예** : 책을 읽으며 고개를 좌우로 흔들어도 글자가 흔들리지 않는 현상
- **왜** : 헤드락 UI 는 이 반사와 반대로 움직임 → 시선이 UI 에 닿지 못하고 불편
- **어디서** : Unity 설정 없음 · 헤드셋 안에서 몸으로만 확인 (11주 실기)

### VR

**VR** · *Virtual Reality* — 1주

- **뜻** : 진짜 대신 만든 화면·소리 자극으로 «지금 그곳에 있다» 는 경험을 만드는 기술
- **예** : 교실 바닥에 서 있는데 높은 건물 가장자리에서 저절로 뒷걸음질
- **왜** : 목표가 «멋진 화면» 이 아니라 «사람의 반응» → 판단 기준이 화면이 아니라 사람

### vsync

**vsync** · *Vertical sync · 수직 동기화* — 3주 · 다시 : 12주

- **뜻** : 디스플레이가 새 그림을 받아 가는 정해진 순간 — 정시 출발하는 기차의 출발 시각
- **예** : 90 Hz → 11.1 ms · 22.2 ms · 33.3 ms … 마다 출발 · 10.9 ms 에 완성 = 탑승 · 11.4 ms = 다음 기차
- **왜** : «조금 늦음» 이 없음 → 0.3 ms 만 늦어도 한 프레임 통째로 놓침
- **어디서** : Project Settings → Quality → VSync Count 는 PC 화면용 · VR 은 헤드셋 합성기가 직접 맞춤

### w 성분

**w 성분** · *w component* — 2주

- **뜻** : 이동을 받을지 말지 정하는 꼬리표 숫자 — 1 이면 장소(점), 0 이면 방향
- **예** : (1, 2, 3, 1) 은 오른쪽 5 이동 후 (6, 2, 3) · (1, 2, 3, 0) 은 그대로 (1, 2, 3)
- **왜** : 법선·빛 방향 같은 «방향»에 이동을 적용하면 원점에서 멀수록 방향이 기울어 조명이 틀어짐
- **어디서** : MultiplyPoint = w 1 취급 · MultiplyVector = w 0 취급

### World Space 캔버스

**World Space 캔버스** · *Canvas Render Mode* — 12주

- **뜻** : UI 를 화면에 붙이지 않고 3D 공간 속 판자로 세워 두는 방식 — 벽에 붙인 게시판
- **예** : 패널 1.2 m 앞 · 가슴 높이 · 크기 0.6 × 0.4 m → 고개를 돌려도 제자리
- **왜** : Screen Space 그대로 두면 VR 에서 안 보이거나 눈앞에 달라붙음 (10주 함정 #7)
- **어디서** : Canvas Inspector → Render Mode = World Space · Scale 0.001 전후로 크기 맞춤

### Wrap Mode

**Wrap Mode** · *랩 모드* — 6주

- **뜻** : UV 가 0~1 밖으로 나갔을 때 그 자리를 어떻게 채울지 정하는 규칙
- **예** : UV 1.2 → Repeat 0.2 · Clamp 1.0 · Mirror 0.8
- **어디서** : 텍스처 Inspector → Wrap Mode (Repeat · Clamp · Mirror · Mirror Once)

### XR Origin

**XR Origin** · *XR Rig* — 2주 · 다시 : 11주, 13주

- **뜻** : VR 체험자의 «몸통» 역할을 하는 오브젝트 묶음 — 그 안에 머리(카메라)와 두 손(컨트롤러)이 매달림
- **예** : 텔레포트 = XR Origin 전체를 옮김 · 고개 돌리기 = 그 안의 Main Camera 만 회전
- **왜** : 카메라를 직접 옮기면 머리 추적과 싸움 → 운동 시차 왜곡 · 멀미 (11주 함정 #8)

### XR Ray Interactor

**XR Ray Interactor** — 12주

- **뜻** : 컨트롤러에서 레이저를 쏴 먼 물체·UI 를 선택하는 전용 컴포넌트
- **예** : 1.2 m 앞 패널 버튼을 광선으로 가리키고 트리거 → 클릭

- **왜** : 비대칭 절두체 · IPD 를 정확히 아는 유일한 주체 → 카메라 값을 코드로 덮어쓰면 안 되는 이유

### XR 리그

### z-fighting

**z-fighting** · *깊이 다툼* — 4주 · 다시 : 9주
